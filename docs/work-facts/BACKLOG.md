# 개발 순서와 인계

상태: 개발 착수용 계획. 이 문서의 작업은 구현·실행·완료된 것이 아니다. 기준 `main`은 `d6b8ff1dc0dc7a51ebd5896a395ac39236e77d1c`, 기존 준비안은 PR #137의 `10b5311b047c7d8025d96b1c13c269a8900432a0`이다. #137 또는 기존 #135 평가도구를 무단으로 대체하거나 과거 결과를 효과 증거로 사용하지 않는다.

사용자 결정: Claude에서 먼저 검증, 작업 시작 전 관련 기록 전달, 업무 후 새 사실 자동 분류·저장, 매 작업 저장 승인 없음, 정정·삭제. 첫 후보는 macOS Claude Desktop Cowork/통합 대화이며 실행 프로필은 확인 전 미정이다. 출시·개인/팀·저장 위치·제품명은 결정되지 않았다.

대상은 비개발 직무의 모든 일반 사무직군이며 지원 범위는 이들의 사무업무 전반이다.
거래처 회신은 기존 상세
예시이며 제품이나 도메인 모델의 범위를 고정하지 않는다. 초기 구현의 크기는
호스트·사용자 범위·연동 수로 제한하고, 기록 모델과 선별·저장 계약은 문서·회의·
조사·분석·기획·프로젝트·운영·의사결정·소통을 담을 수 있게 설계한다. 구현 전에
모든 업무의 효용을 입증할 필요는 없지만, 한 업무만 통과하고 범용 지원을 주장하지 않는다.
초기·일회성 업무와 빈 라이브러리도 정상 사용 범위다. 유한한 직군·사례의 평가
결과는 해당 범위의 근거로만 쓰고 아직 시험하지 않은 직군·업무를 명시한다.

## 개발 착수 / 검증 / 출시의 경계

- **지금 착수 가능:** 가상 자료 기반 도메인 계약, UX, 호스트 식별 및 비보관 어댑터 실험. 실제 업무 내용을 일절 사용하지 않는 합성 fixture의 격리된 시험 저장은 T00a의 정합성 확인 후 가능하며, 독립 대화 간에 유지하되 시험 종료 시 정리한다. 실제 업무 내용의 지속 보관 기능은 T00b 이전 어느 브랜치에도 추가하지 않는다.
- **개발 완료로 주장할 조건:** P01–P05, P06a, P07–P17과 실패·복구를 선택한 실제 Claude 표면에서 관찰하고, 근거·정정 및 자동 저장을 분리해 입증한다. 단일 거래처 사례 외 G01–G11의 여러 업무 계열을 다루며 해당 계열·조건의 증거 범위를 명시한다. P06b 및 P15의 삭제 측면은 T00b에서 삭제·재생성·보존 정책의 판정값을 정한 뒤 검증해야 한다. 정책이 미결정이면 삭제가 구현·검증됐거나 전체 기능이 완료됐다고 주장하지 않는다. 이때도 일반 사용자 효과를 자동으로 주장하지 않는다.
- **출시 조건:** 정책·보안·권한·유지보수·설치와 복구·사용자 통제, 해당 플랫폼의 실제 동작 및 누락 증거 정리. 테스트 통과나 파일 설치만으로 출시 적합성을 확정하지 않는다.
- **효과 주장:** [평가 계획](EVALUATION.md)의 동등한 바닐라/검색 비교와 실제 비개발 직장인 사례가 있어야 한다. 탐색 결과로 임의의 수치 문턱이나 인과 결론을 만들지 않는다.

## 지속 인계

개발 PR마다 현재 commit SHA, 완료된 범위, 정확한 명령·결과, 실행하지 않은 검사 및 실제 호스트·클린 설치·사용자 효과 증거의 공백, 다음 작업을 기재한다. 업무 기록 보관 규칙이 채택되지 않았다면 그 제한을 숨기지 않는다. 종료된 기존 버전이나 철회된 PR #95의 코드·가이드는 복사하지 않는다.
