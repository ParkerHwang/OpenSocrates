# Claude 우선 검증과 호스트 지원 경계

조사일: 2026-10-30. 아래 공식 문서 확인은 해당 계정·앱의 실제 자동 동작이나 제품 효과의 증거가 아니다. 실제 사용 검증을 Claude로 진행한다는 것은 사용자의 선택이다. ChatGPT, Antigravity, Cursor는 목표로 유지하지만 Claude 결과를 그들의 결과로 사용하지 않는다.

## 첫 번째 대상

**Claude Desktop에서 비개발 사무업무를 수행하는 현재 Cowork/통합 대화 프로필**을 첫 실사용 관찰 대상으로 제안한다. 사용자가 일상적인 요청을 했을 때 관련 기록이 다른 자료 검색보다 먼저 전달되고, 작업 후 기록이 별도 저장 승인 요구 없이 남는지, 새 대화에서 재사용되는지를 각각 확인한다. 거래처 요청 반려 후 후속 회신은 여러 가상 업무 중 하나다. 회의·보고서·기획·조사·분석 등 서로 다른 업무와 새 업무도 [평가 계획](EVALUATION.md)에 포함한다. **한 Claude 호스트를 먼저 확인하는 것은 제품의 사용 직군이나 업무를 하나로 제한하는 결정이 아니다.** Chat, Cowork 및 Code는 별도 조건이며 Code의 성공으로 Chat/Cowork를 대체하지 않는다.

현재 계정·앱 버전·운영체제·실행 위치·조직 정책을 실제로 확인하기 전에는 로컬/클라우드 중 어느 구조도 확정하지 않는다. [Cowork 시작 안내](https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork)는 Chat/Cowork 통합 화면의 단계적 적용 및 기본 클라우드 실행을 설명한다. 다른 공식 설명의 로컬 환경 기술이 남아 있으므로 현재 화면과 버전에 대한 측정이 필요하다.

## 공식 자료와 경계

| 표면·내용 | 공식 문서가 설명하는 것 | 이 계획에서 남는 질문 |
| --- | --- | --- |
| Claude Chat과 Cowork | [플러그인 사용 안내](https://support.claude.com/en/articles/13837440-use-plugins-in-claude)는 스킬·명령이 Chat과 Cowork에 제공되지만 훅은 Chat에서 실행되지 않고 Cowork와 Code에서 실행된다고 설명한다. | Cowork의 현재 통합 계정에서 실제 이벤트별 선행 전달 및 저장이 어떻게 동작하는지 미확인. 설치·로드는 실행 증거가 아니다. |
| Claude Code | [Code 훅 참조](https://code.claude.com/docs/en/hooks)는 요청 처리 전 `UserPromptSubmit`과 응답 종료 시 `Stop` 등을 설명한다. | **Code 계약이다.** Cowork/Chat의 동등한 보장이 아니다. 응답 종료는 업무 완료·이메일 발송·계약 체결과 다르다. |
| 스킬·커넥터 | [플러그인 제작 안내](https://claude.com/docs/plugins/build)는 스킬과 MCP 커넥터를 함께 묶는 방식을 설명한다. [플러그인 사용 안내](https://support.claude.com/en/articles/13837440-use-plugins-in-claude)는 Cowork 원격 커넥터가 클라우드에서 접근 가능한 서버를 필요로 한다고 설명한다. | 스킬 선택, 관련 사실 선행 조회와 작업 후 쓰기가 매번 실행되는지, 권한·영속성·오류 처리는 미확인이다. 로컬 저장소가 클라우드에서 자동 접근 가능하다고 가정하지 않는다. |
| 쓰기 권한 | [Cowork 시작 안내](https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork)는 쓰기·삭제가 자동 검토 대상이거나 조직의 작업별 승인 정책을 따를 수 있음을 설명한다. | 매번 승인 없는 저장은 제품 목표이지 모든 계정의 보장된 동작이 아니다. 제한을 우회하지 않으며 차단·요청·실패를 별도로 기록한다. |
| ChatGPT 대화/Work | [ChatGPT 플러그인 안내](https://learn.chatgpt.com/docs/plugins)의 범위와 Codex 구현은 별개다. | 사용자 요청 전 강제 전달과 작업 후 자동 저장은 별도 조사·관찰이 필요하다. 이번 실사용 검증 대상이 아니다. |
| Antigravity | [훅 공식 안내](https://antigravity.google/docs/hooks)에는 일부 생명주기 및 주입 계약이 설명되어 있다. | 해당 앱·버전의 실제 선별·전달·기록 안정성은 확인하지 않았다. |
| Cursor | [훅 공식 안내](https://cursor.com/docs/hooks)에는 제출·응답·종료 관련 이벤트가 설명되어 있다. | 이벤트가 존재한다는 것과 임의의 사실을 작업 전에 자동 전달한다는 것은 다르다. 실제 동작 미확인. |

현재 main의 Claude account export와 Antigravity 배포물은 콘텐츠 중심이며, Claude Code native 플러그인과 다르다. 구체적 기존 자산은 [기술 설계](TECHNICAL_DESIGN.md)와 [SECURITY.md](../../SECURITY.md)를 참조한다. 기존 Cursor 문서는 과거 버전의 기록이므로 현재 공식 제품 지원의 증거가 아니다.

## 개발자가 먼저 할 확인과 중단 처리

1. **대상 식별:** 기기·OS·Claude 앱 버전, UI에서 표시된 모드, 작업이 표시하는 컴퓨터/클라우드 위치, 플러그인 로드 상태, 관찰된 훅 유형과 실제 신호를 각각 기록한다. 통합 UI의 이름만으로 Chat 또는 Cowork라고 추정하지 않는다. 위치·셀을 판별할 수 없으면 `unknown`으로 유지하고 정해진 셀의 성공으로 주장하지 않는다. 기존 인증·보안 설정을 임의로 바꾸지 않는다.
2. **사전 전달:** 합성 안건 두 개를 준비하고 관련 기록이 응답 생성 및 다른 원문 검색보다 먼저 AI에 전달됐는지, 올바른 건인지와 실패 사례를 관찰한다. 스킬이 표시되거나 선택되는 것만으로 내용 읽기·사용을 증명하지 않는다.
3. **종료와 기록:** 가상 요청 종료, 응답 중단, 새 주제, 사용자 수정, 앱 재개를 분리해 기록 신호와 영속 저장·중복 여부를 확인한다. 승인 UI가 나타나거나 도구 호출이 생략되면 그 결과를 보존한다. 이메일 초안만으로 실제 발송을 확정하지 않는다.
4. **재사용과 경계:** 독립된 새 대화에서 기록의 출처·시점을 사용하고 정정·삭제가 존중되는지 본다. 허용된 출처의 좁은 범위를 읽을 수 있는지와 사용자가 기록을 열람·정정·삭제할 관리 화면을 어디에 제공할 수 있는지도 각기 확인한다. 해당 계정에서 허용되지 않은 접근이나 쓰기, 호스트 신뢰 요청은 우회하지 않는다.
5. **판정:** 본 계정에서 지원하지 않거나 차단되면 `unavailable` 또는 `blocked`와 이유를 기록한다. 명시적 수동 보조 또는 다른 Claude 실행 프로필은 사용 경험을 구분한 대체 실험안이며, 자동 목표를 달성한 것으로 표시하지 않는다. 가상 어댑터 설계와 오프라인 구현은 계속 가능하나 실제 업무 데이터 저장과 릴리스는 [정책 정합화](PRIVACY_PROPOSAL.md)와 별도 검증이 필요하다.

확인 방법과 관찰해야 할 증거는 [평가 계획](EVALUATION.md)에 둔다. 지금까지 위의 실제 호스트 시험은 실행하지 않았다.
