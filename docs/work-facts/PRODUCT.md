# 업무 사실 라이브러리: 제품 명세

상태: 개발 준비용 제안 · 2026-10-30. 이 문서는 제품을 구현하거나 호스트 지원을 입증하지 않는다.

## 1. 목적과 근거

개발·코딩·AI 전문 지식이 없는 직장인이 이미 쓰는 AI에서 반복되는 업무를 이어갈 때, 이전에 확인한 요청·결정·이유·약속·상태를 다시 찾고 설명하는 부담을 줄인다. AI가 일을 시작하기 전에 관련 기록을 먼저 전달하고, 일을 마칠 때 새로 확인한 사실을 분류해 매번 저장 승인을 요구하지 않고 저장한다. 저장된 내용을 사용자가 보고 고치거나 삭제할 수 있다.

일반 업무 글쓰기의 속도·품질 개선은 [2023년의 짧은 과제 실험](https://scale.stanford.edu/publications/experimental-evidence-productivity-effects-generative-artificial-intelligence)에서 관찰됐다. 정보 검증·응답 통합의 부담은 [319명 지식노동자 자기보고 연구](https://www.microsoft.com/en-us/research/wp-content/uploads/2025/01/lee_2025_ai_critical_thinking_survey.pdf)에서 보고됐다. 두 연구는 서로 다른 대상과 조건을 다루며, 이 제품의 수요, 자동 기록 정확도 또는 효과를 입증하지 않는다. 연구의 낡은 모델·과제·자기보고 한계를 현재 호스트 전체에 일반화하지 않는다.

## 2. 첫 범위와 선택의 이유

- **첫 업무:** 이미 처리했던 거래처 요청의 후속 회신. 회신 이전의 반려·사유·조건, 그 이후의 변경, 초안과 실제 발송을 구별할 수 있는 업무를 가상 사례로 먼저 다룬다.
- **첫 실제 검증 호스트:** 사용자 지정 Claude. 첫 후보는 Apple Silicon macOS의 **Claude Desktop Cowork 실행 프로필**이며, 실제 계정의 프로필과 자동 진입·저장 가능 여부는 [호스트 조사](HOSTS.md)의 착수 확인으로 구분한다. 일반 Claude Chat과 Claude Code는 동일한 실행 표면이 아니다. Cowork가 불가능하면 결과를 `unavailable`로 기록하고 대체 경로를 별도 결정한다.
- **초기 범위:** 한 사용자와 한 업무 건의 출처·시점이 있는 기록, 요청 전 선별·전달, 작업 후 자동 분류·저장, 열람·정정·삭제. 개인/팀 사업 방향과 실제 업무 데이터 저장 승인은 결정하지 않는다.
- **후속 목표:** ChatGPT, Antigravity, Cursor. Claude 검증은 이들의 지원 또는 품질 증거가 아니다.

우선순위의 출처는 사용자가 밝힌 비개발 업무, Claude에서의 검증, 자동 사전 전달과 사후 저장 목표다. 범위를 하나로 좁히는 것은 구현을 시작하기 위한 제안이며 호스트 용이성이나 사용자 효과의 측정값이 아니다. 시기·가격·성과를 가중 점수로 계산하지 않았다.

| 대안 | 얻는 것 | 포기·불확실성 |
| --- | --- | --- |
| 평소 AI와 원문 검색 | 별도 기록 관리 없음 | 반복 탐색과 맥락 전달 부담이 얼마나 큰지는 미측정 |
| 사람이 이력을 정리 | 사람이 기록을 직접 통제 | 정리와 갱신에 드는 수고가 생김 |
| 사전 전달과 자동 저장 루프 | 반복 설명 감소 가능성 | 오기록·시점 오류·접근권한·앱 연동 미검증 |

원문 검색만으로 충분하거나 자동 저장의 오염·정정 부담이 이득을 상쇄하면 추천을 재검토한다. 민감정보 보호와 접근권한은 시간 절감으로 교환할 수 있는 점수가 아니다.

## 3. 사용자 여정과 제품 계약

1. 사용자가 Claude에서 평소처럼 “A사 회신을 준비해줘”라고 요청한다.
2. 시스템은 AI가 업무를 진행하기 전에 라이브러리에서 이 안건과 관련된 기록을 선별하고, 마지막으로 확인된 내용·시점·출처·미관찰 구간을 제한된 범위로 제공한다. 아무 기록도 없거나 구분이 모호한 경우 빈 상태 또는 필요한 짧은 확인을 알린다. **빈 결과는 이력이 없다는 증명이 아니다.**
3. AI는 이전 경위를 이용해 작업을 진행한다. 과거 이유를 묻는 일과 현재 계약 여부·외부 약속을 전제로 하는 일을 구분한다. 현재 상태가 결과를 바꿀 수 있으면 정당한 접근 범위에서 좁게 확인하거나 미확인 상태를 유지하며 가능한 초안부터 만든다.
4. 작업 중 확인한 새 사실은 작업 종료 시 자동 분류·저장한다. 사용자는 매 작업 저장 승인 없이 일한다. 종료 이벤트가 없거나 저장 실패 시도 결과를 감추지 않고 [사용자 경험](USER_EXPERIENCE.md)과 [기술 계약](TECHNICAL_DESIGN.md)에 따라 복구한다.
5. 사용자는 기록과 사용된 근거를 열람하고, 잘못된 내용을 정정하거나 삭제할 수 있다. 삭제·정정 후 동일한 원문에서 기록이 다시 생성되거나 사용자 정정이 덮어쓰이지 않도록 설계한다. 원본·백업·억제 표식의 처리 정책은 별도 결정한다.

## 4. 첫 기능의 인수 조건

아래는 구현할 동작의 계약이며 아직 통과한 시험이 아니다. 환경·날짜·버전·재현 입력과 관찰 결과를 남긴다. 인증 또는 화면 동작이 없는 모사·단위 검사는 실제 Claude 사용 증거가 아니다.

| ID | 가상 시나리오 | 기대 결과 |
| --- | --- | --- |
| P01 | A사 안건에 10/29 반려 이력이 있다. 후속 요청을 제출한다. | 일을 진행하기 전에 해당 이력·출처·시점이 AI에 전달된다. 관련 없는 B사 안건은 전달하지 않는다. |
| P02 | AI가 회신 초안을 작성했지만 발송 증거는 없다. | 확정된 발송·약속으로 기록하지 않는다. |
| P03 | 11/3 체결과 재진행 지시가 확인된다. | 기존 반려 이력을 보존하고 새 근거·시점과 변경을 자동 저장하며, 매 작업 저장 승인창을 제품이 요구하지 않는다. |
| P04 | 10/29 이력만 있고 현재 계약 상태를 묻는다. | 과거 기록을 현재 체결 여부로 단정하지 않고, 추가 확인이 불가능하면 미확인이라 알린다. |
| P05 | A사의 두 계약 건이 비슷하다. | 근거가 부족하면 잘못된 안건을 확정해 전달하지 않는다. 필요한 확인만 요청한다. |
| P06a | 사용자가 사실을 고친 뒤 같은 출처가 다시 나온다. | 기존 주장을 재추출해 사용자 정정을 조용히 덮어쓰지 않는다. |
| P06b | 사용자가 사실을 삭제한 뒤 같은 출처가 다시 나온다. | 채택된 삭제·재생성·보존 정책에 따라 처리하고 한계를 명시한다. 구체 판정은 정책 결정 후 고정한다. |
| P07 | 읽기·쓰기·접근권한·종료 신호가 실패한다. | 작업 가능한 범위는 계속하고 데이터 손실과 미저장을 조용히 성공 처리하지 않는다. |
| P08 | 권한 없는 출처 또는 자료 속 명령문을 만난다. | 권한 밖 내용을 전달하지 않으며, 자료를 시스템 지시로 실행하지 않는다. |

## 5. 출시 전 증거 수준

문서 완성, 가상 데이터의 기능 통과, 실제 Claude에서 사전 전달·자동 저장 관찰, 독립 환경 설치·복구, 일반 직장인의 비교 업무 결과는 서로 다른 증거다. 앞 단계의 성공은 뒤 단계의 성공이 아니다. 실제 데이터 사용과 제품 출시 전에는 현재 무보관 정책과 신규 기록 보관 범위가 정합화되어야 한다. [정책 변경 제안](PRIVACY_PROPOSAL.md) · [평가 계획](EVALUATION.md)
