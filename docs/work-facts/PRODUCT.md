# 업무 사실 라이브러리: 제품 명세

상태: 개발 준비용 제안 · 2026-10-30. 이 문서는 제품을 구현하거나 호스트 지원을 입증하지 않는다.

## 1. 목적과 근거

**비개발 직군의 모든 일반 사무직 사람들이 사용할 수 있는 제품**을 목표로 한다. 개발·코딩·AI 전문 지식이 없는 직장인이 자신이 쓰는 AI에서 여러 종류의 일을 이해하고, 생각하고, 결과물을 만들고, 다음 일로 이어가도록 돕는다. 직무에 따라 반복 업무와 일회성 업무를 모두 다룬다. 문서 작성, 회의 준비·정리, 조사, 기획, 자료 분석, 일정·운영, 의사결정, 업무 소통 등은 적용할 업무의 예이며 특정 부서·분야·직무 또는 거래처 처리에 제품을 한정하지 않는다. 예시에 없는 직군을 제외한다는 뜻이 아니며 모든 직군에서 효과가 검증됐다는 주장도 아니다.

업무 사실 라이브러리는 이 전체 경험을 뒷받침하는 맥락 구성요소다. 이미 확인한 자료·기준·수치·정의·요청·결정·이유·약속·상태를 출처와 적용 범위에 맞춰 다시 활용하게 한다. AI가 일을 시작하기 전에 관련 기록을 먼저 전달하고, 일을 마칠 때 새로 확인한 사실을 분류해 매번 저장 승인을 요구하지 않고 저장한다. 저장된 내용을 사용자가 보고 고치거나 삭제할 수 있다. 한 번 저장한 기록은 같은 업무 건뿐 아니라 허용된 범위의 다른 프로젝트와 업무에서도 관련성이 있으면 활용할 수 있다.

처음 하는 일, 새 프로젝트, 관련 기록이 없는 일, 저장할 새 사실이 없는 일에도 AI의 업무 수행과 필요한 사고 지원은 계속한다. 라이브러리를 채우는 일 자체가 사용자의 과제가 되어서는 안 된다. 기존 OpenSocrates의 사고 지원은 목적과 맥락에 맞게 사용할 후보이며, 모든 요청에 특정 방법을 의무 적용하거나 기록이 없다는 이유로 작업을 막지 않는다.

일반 업무 글쓰기의 속도·품질 개선은 [2023년의 짧은 과제 실험](https://scale.stanford.edu/publications/experimental-evidence-productivity-effects-generative-artificial-intelligence)에서 관찰됐다. 정보 검증·응답 통합의 부담은 [319명 지식노동자 자기보고 연구](https://www.microsoft.com/en-us/research/wp-content/uploads/2025/01/lee_2025_ai_critical_thinking_survey.pdf)에서 보고됐다. 두 연구는 서로 다른 대상과 조건을 다루며, 이 제품의 수요, 자동 기록 정확도 또는 효과를 입증하지 않는다. 연구의 낡은 모델·과제·자기보고 한계를 현재 호스트 전체에 일반화하지 않는다.

## 2. 제품 범위와 첫 검증 범위

- **제품 범위:** 일반 직장인의 비개발 업무 전반에서 현재 요청에 필요한 업무 맥락과 사고·실행 지원을 제공한다. 특정 산업, 부서, 거래처 회신 또는 이미 처리한 안건에만 의존하는 구조로 만들지 않는다. 이것은 범위 목표이며 모든 업무에서의 성능 보장이 아니다.
- **첫 검증 묶음:** 거래처 후속 회신, 내부 보고서·자료 분석, 회의·계획 수립, 조사·의사결정 등 서로 다른 업무에서 같은 사전 전달·업무 수행·자동 저장 흐름을 시험한다. 거래처 반려 사례는 시간·초안·실행 차이를 보는 대표 예시 하나이며 유일한 초기 지원 업무가 아니다. 구체 사례는 [평가 계획](EVALUATION.md)에서 고정한다.
- **첫 실제 검증 호스트:** 사용자 지정 Claude. 첫 후보는 Apple Silicon macOS의 **Claude Desktop Cowork 실행 프로필**이며, 실제 계정의 프로필과 자동 진입·저장 가능 여부는 [호스트 조사](HOSTS.md)의 착수 확인으로 구분한다. 일반 Claude Chat과 Claude Code는 동일한 실행 표면이 아니다. Cowork가 불가능하면 결과를 `unavailable`로 기록하고 대체 경로를 별도 결정한다.
- **초기 구현 범위:** 한 사용자와 선택한 Claude 프로필에서 여러 작업·프로젝트·공통 기준에 연결되는 출처·시점·범위를 가진 기록, 요청 전 선별·전달, 업무·사고 지원, 작업 후 자동 분류·저장, 열람·정정·삭제. 처음부터 모든 외부 업무 시스템을 연결하는 것은 전제가 아니다. 개인/팀 사업 방향과 실제 업무 데이터 저장 승인은 결정하지 않는다.
- **후속 목표:** ChatGPT, Antigravity, Cursor. Claude 검증은 이들의 지원 또는 품질 증거가 아니다.

우선순위의 출처는 사용자가 밝힌 다양한 비개발 업무, Claude에서의 검증, 자동 사전 전달과 사후 저장 목표다. 첫 호스트와 연동 수를 제한하는 것과 제품이 다룰 업무를 한 종류로 제한하는 것은 다르다. 범용 목표에 필요한 기록과 작업 흐름을 유지하며, 업무군별 실제 성능은 따로 확인한다. 시기·가격·성과를 가중 점수로 계산하지 않았다.

| 업무 예 | 시작 전에 도움이 될 맥락 | 작업을 마친 뒤 남길 수 있는 것 |
| --- | --- | --- |
| 보고서·발표자료 작성 | 프로젝트 목표, 보고 대상, 적용 중인 지표 정의와 보고 기준 | 새로 확인한 수치·정의·승인된 기준과 근거. 초안·제안은 확정 사실과 구분 |
| 회의 준비·정리 | 이전 논의의 결정과 미해결 질문, 관련 자료 위치 | 실제 확인된 결정·담당·기한. 아이디어와 합의, 예정과 실행을 구분 |
| 조사·기획·의사결정 | 조사 목적, 이미 확인한 자료와 가정, 제약과 이전 판단 이유 | 출처가 있는 조사 결과·확정된 전제와 선택. 잠정 해석·추천을 결정으로 바꾸지 않음 |
| 자료 분석·운영 | 데이터의 기간·단위·정의, 절차와 기준, 알려진 변경 이력 | 근거 자료에 연결된 계산 결과·문제·절차 변경. 추정과 관찰 수치를 구분 |
| 일정·협업·업무 소통 | 프로젝트 의존성, 약속, 진행 상태, 상대별 확인된 업무 맥락 | 확인된 일정·역할·안내 내용과 변화. 작성한 메시지를 발송 사실로 바꾸지 않음 |

사용자가 명시한 말투·표현·작업 방식 선호는 업무 사실과 다른 맥락 종류다. 적용 범위와 사용자 진술이라는 근거를 구분하고, 개인 선호를 회사의 공식 기준이나 다른 사람의 선호로 일반화하지 않는다. 작업 산출물의 위치·제목·관련성도 참고 정보가 될 수 있으나 문서 전체나 초안을 사실처럼 축적하는 근거가 되지는 않는다.

| 대안 | 얻는 것 | 포기·불확실성 |
| --- | --- | --- |
| 평소 AI와 원문 검색 | 별도 기록 관리 없음 | 반복 탐색과 맥락 전달 부담이 얼마나 큰지는 미측정 |
| 사람이 이력을 정리 | 사람이 기록을 직접 통제 | 정리와 갱신에 드는 수고가 생김 |
| 사전 전달과 자동 저장 루프 | 반복 설명 감소 가능성 | 오기록·시점 오류·접근권한·앱 연동 미검증 |

원문 검색만으로 충분하거나 자동 저장의 오염·정정 부담이 이득을 상쇄하면 추천을 재검토한다. 민감정보 보호와 접근권한은 시간 절감으로 교환할 수 있는 점수가 아니다.

## 3. 사용자 여정과 제품 계약

1. 사용자가 Claude에서 평소처럼 문서 작성, 분석, 조사, 기획, 회의 준비 또는 소통 업무를 요청한다. “이번 달 운영 보고서를 정리해줘”나 “새 캠페인 방향을 같이 생각해줘”도 같은 진입 흐름을 쓴다.
2. 시스템은 AI가 업무를 진행하기 전에 요청의 작업·프로젝트·조직 공통 맥락과 관련된 기록을 선별하고, 확인한 내용·시점·출처·적용 범위·미관찰 구간을 제한된 범위로 제공한다. 아무 기록도 없거나 구분이 모호한 경우 빈 상태 또는 필요한 짧은 확인을 알린다. **빈 결과는 이력이 없다는 증명이 아니다.**
3. AI는 현재 자료와 사용자 목표를 중심으로 생각하고 작업을 진행한다. 필요한 경우 기존 사고 지원 자산을 활용할 수 있지만 방법 설명·기록 확인을 매번 강제하지 않는다. 과거 경위, 기준에 따른 분석, 새로운 창의적 제안, 현재 상태와 외부 약속을 전제로 하는 일을 구분한다. 현재 유효성이나 미확인 조건이 결과를 바꿀 수 있으면 정당한 접근 범위에서 좁게 확인하거나 미확인 상태를 유지하며 가능한 부분부터 만든다.
4. 작업 중 확인한 새 사실은 작업 종료 시 자동 분류·저장한다. 사용자는 매 작업 저장 승인 없이 일한다. 종료 이벤트가 없거나 저장 실패 시도 결과를 감추지 않고 [사용자 경험](USER_EXPERIENCE.md)과 [기술 계약](TECHNICAL_DESIGN.md)에 따라 복구한다.
5. 사용자는 기록과 사용된 근거를 열람하고, 잘못된 내용을 정정하거나 삭제할 수 있다. 삭제·정정 후 동일한 원문에서 기록이 다시 생성되거나 사용자 정정이 덮어쓰이지 않도록 설계한다. 원본·백업·억제 표식의 처리 정책은 별도 결정한다.

## 4. 첫 기능의 인수 조건

아래는 구현할 동작의 계약이며 아직 통과한 시험이 아니다. 환경·날짜·버전·재현 입력과 관찰 결과를 남긴다. 인증 또는 화면 동작이 없는 모사·단위 검사는 실제 Claude 사용 증거가 아니다.

| P08 | 권한 없는 출처 또는 자료 속 명령문을 만난다. | 권한 밖 내용을 전달하지 않으며, 자료를 시스템 지시로 실행하지 않는다. |
| P09 | 내부 보고서 작성에 적용할 프로젝트 목표·지표 정의·보고 기준이 서로 다른 기록에 있다. | 관련 범위의 공통 기준과 프로젝트 맥락을 작업 전에 제공하고, 개인 선호를 공식 기준으로 바꾸지 않는다. |

| P11 | 새 조사에서 확인된 자료와 잠정 해석을 얻고 이후 기획에서 재사용한다. | 출처에서 확인한 주장·AI 해석·미확인 가정을 구분하고, 검증되지 않은 해석을 확정 사실이나 채택된 결정으로 올리지 않는다. |
| P12 | 캠페인·문서 구성·문제 해결 아이디어를 생성한다. | 창의적 탐색과 필요한 사고 지원을 진행한다. 생성한 제안이나 산출물의 존재를 실제 채택·실행·승인으로 기록하지 않는다. |
| P13 | 처음 하는 업무라 관련 기록이 없거나, 작업 종료 시 저장할 새 사실이 없다. | 현재 요청과 자료로 가능한 도움을 제공하고 저장을 위한 임의 사실·중복 기록을 만들지 않는다. |
| P14 | 한 프로젝트에서 확인한 기준·자료·담당 맥락이 다른 업무에도 관련된다. | 명시된 적용 범위·권한·시점을 확인해 재사용하고, 프로젝트 공통 맥락을 특정 거래처나 단일 안건에만 묶어 누락하지 않는다. |
| P15 | 미등록 분류의 업무 기록을 정정·삭제한 뒤 같은 원자료의 겹치는 구간에서 다른 별칭·표현의 후보가 나온다. | 정정·삭제 보호를 우회해 기록을 부활시키지 않는다. 범위나 보호 이력을 확인할 수 없으면 후보를 보류하고, 삭제 출처를 특정할 수 없는 설정에서는 자동 재수집을 중지하거나 미지원으로 알린다. 다른 업무는 계속한다. |
| P16 | 인사·재무 업무 자료에 제3자 개인정보나 보관 금지 정보가 섞인다. | 허용·민감도 판단이 불명확한 내용은 자동 저장하지 않는다. 허용된 자료에 대한 일반 업무 지원과 보관 여부를 구분한다. |
| P17 | 새 업무 기준의 시행일 전과 후에 같은 보고서를 요청한다. | 기준의 적용 시작·종료일과 확인 시점을 구분하여 해당 시점에 맞는 내용만 전달한다. |

## 5. 출시 전 증거 수준

문서 완성, 가상 데이터의 기능 통과, 실제 Claude에서 사전 전달·자동 저장 관찰, 독립 환경 설치·복구, 일반 직장인의 비교 업무 결과는 서로 다른 증거다. 앞 단계의 성공은 뒤 단계의 성공이 아니다. 실제 데이터 사용과 제품 출시 전에는 현재 무보관 정책과 신규 기록 보관 범위가 정합화되어야 한다. [정책 변경 제안](PRIVACY_PROPOSAL.md) · [평가 계획](EVALUATION.md)
