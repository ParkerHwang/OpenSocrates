# OpenSocrates v1.5.3: 유지보수와 판단 요청 복구

[English](v1.5.3.md) · [한국어 README](../README.ko.md) · [언어 안내](v1.5.2.ko.md)

v1.5.3은 실질적 사고 지원 범위 명료화, Codex 대용량 제출의 탐색 안내 누락 수정,
구조화된 판단 요청 복구와 열 언어 네이티브 Claude 안내 정렬을 묶습니다.
사고 방법 48개·열 언어·콘텐츠 리비전 5를 유지합니다. 방법 본문과 라우팅
적격성 규칙은 바꾸지 않지만 컨트롤러·안내 변경으로 번들·패키지 식별자는 바뀝니다.

이 문서는 유지보수 범위를 설명합니다. 태그·공개 파일 게시, npm 활성화나 실제
호스트 검증의 증거가 아닙니다. 정확한 소스 검사, 네이티브 배포 게이트와 공개
바이트 검증은 최종 커밋에 묶어 [유지보수 이슈](https://github.com/ParkerHwang/OpenSocrates/issues/132)와
해당 PR에 기록해야 합니다.

## 변경 내용

### 실질적인 사고

실질적인 사고가 처음 필요할 때 지원을 검토하고, 같은 턴 안에서도 목표·선택지·
증거·가정·독자·위험이 중요하게 달라지면 다시 검토합니다. 도구 호출이나 수정마다
방법을 조회하라는 뜻은 아닙니다. 정답이 하나이거나 규칙이 주어졌다는 이유만으로
증명·설명·문제 해결이 기계적인 작업이 되지는 않습니다. 충분한 지원 중 가장
가벼운 것을 선택하며 지원 검토나 독자 안내를 정본 방법 적용으로 간주하지 않습니다.

네 호스트 프로필과 열 언어 지시문에 이 범위를 명료하게 반영합니다. 방법의
사용 조건·금기·필수 중단과 일반 작업의 fail-open 처리는 유지합니다.

### 대용량 Codex 제출

기본 Codex 제출 탐색 안내는 과거 선택기·제어 경로의 32,768바이트 제한과
분리하여 기존 4 MiB 훅 입력 상한까지의 봉투를 받습니다. 프롬프트를 검증 후
버리고 제한된 제출 메타데이터만 투영합니다. 다른 네이티브 이벤트와 과거
선택기는 더 엄격한 파서를 유지합니다. 잘못되거나 상한을 넘는 입력은 계속
제한하며 fail-open으로 처리합니다.

재현된 탐색 안내 누락 경로를 수정한 것이며 [#124](https://github.com/ParkerHwang/OpenSocrates/issues/124)의
모든 보고에 대한 원인·빈도를 입증하지 않습니다. 에이전트의 주의, 방법 전체
읽기, 적용이나 유용한 답변도 증명하지 않습니다.

### 수정 가능한 판단 요청

판단 봉투는 `request.json`과 `features.json`의 `envelope`에 설명되어 있습니다.
문맥은 소문자 16진수 32자이고 판단 ID는 ASCII 영문자·숫자 1~64자입니다.
이 형식 자체는 바꾸지 않습니다.

거부된 요청에는 `invalid_decision_request`, 폐쇄된 `field`·`error`, 가능한
경우 미리 정한 `expected` 설명과 `repair: correct_field_once`를 반환합니다.
제출 값·알 수 없는 키 이름·사적인 텍스트를 되비추지 않습니다. 잘못된 JSON은
수정 가능한 입력 오류이며 거부된 요청이 세션의 기존 가용성 상태를 초기화하지 않습니다.

지목된 필드를 고쳐 한 번 다시 보냅니다. 두 번째 거부, 실행기 실패,
`decision_unavailable` 또는 `canonical_content_unavailable`이면 해당 판단에서
네이티브 경로를 사용할 수 없습니다. 정상적인 `no_intervention`이나 빈 `selected`는
런타임 실패가 아니며 직접 파일 선택으로 우회하면 안 됩니다. 사용 조건·금기·
의존성·중단 조건에 맞지 않는 후보는 적용하지 않고 철회합니다. 방법을 강제하지
않아도 독자 안내만으로 충분할 수 있습니다.

열 언어 네이티브 Claude 판단 안내에 공유 안내와 같은 봉투·복구 구분을
반영합니다. 네이티브 경로를 사용할 수 없을 때 선택적인 파일 대체 경로는
정확한 언어·리비전의 카탈로그와 전체 절차부터 읽고 같은 적격성 검사를
유지합니다. 일반 작업은 계속할 수 있으며 대체 절차를 만들거나 같은 실패
요청을 수정 없이 재시도할 필요는 없습니다.

## 호스트와 설치 범위

기존 프로필을 유지합니다. Codex는 Apple Silicon Mac·Windows x64, 네이티브
Claude Code CLI·Desktop 로컬 Code는 Apple Silicon Mac, 콘텐츠 전용 Claude
계정 스킬은 Mac·Windows 내보내기, Antigravity 작업공간·전역 콘텐츠는 Apple
Silicon Mac·Windows x64 범위입니다. 계정 업로드·활성화·모델의 선택적 로딩은
내보내기와 별개입니다. Windows 네이티브 Claude Code, Windows ARM64, Intel
Mac·Linux 네이티브 검증은 추가하지 않습니다.

출시를 별도로 확인한 다음 Node.js 20+와 호스트의 정상 로그인·신뢰 절차로 실행합니다.

```sh
npx --yes opensocrates@1.5.3 install --host codex
npx --yes opensocrates@1.5.3 update --host codex
npx --yes opensocrates@1.5.3 status --host codex
```

처음 설치할 때는 `install`, 기존 설치에는 `update`를 선택합니다. Mac 네이티브
Claude에는 `--host claude`, Antigravity에는 `--host antigravity`를 명시하고
작업공간 범위에는 같은 절대 경로의 `--workspace`를 사용합니다. 기본값과
`--host all`은 계속 Codex만 선택합니다. 의도적으로 꺼둔 상태를 보존하고
실제 호스트 훅 승인을 거친 후 수명주기 변경 뒤 새 대화를 시작하세요.
프로필별 관리는 [설치 안내](setup-guide.ko.md), 바뀌지 않은 언어 선택 규칙은
[v1.5.2 언어 안내](v1.5.2.ko.md)를 참고하세요.

계정 스킬은 출시 후 이미 존재하는 폴더의 ZIP 절대 경로로 내보냅니다.

```sh
npx --yes opensocrates@1.5.3 export --host claude-chat --output /absolute/path/to/opensocrates-1.5.3-account.zip
```

기존 스킬과 활성화 상태를 백업하고 대상 계정에 ZIP을 업로드해 켭니다. 기존
계정 지침은 보존합니다. 내보내기 성공은 업로드·활성화·자동 사용의 증거가 아닙니다.

## 증거와 한계

구현, 소스 검사, 네이티브 배포 검증, 공개 바이트 검증, 실제 호스트 관찰은
서로 다른 증거입니다. v1.5.2와 그 이전 증거는 원래 소스 식별자·환경에만
해당하며 새 버전 번호가 새 바이트를 검증하지 않습니다. 로컬 합성 회귀 검사는
보편적인 훅 전달·매 턴 사용·적용·답변 품질·토큰 비용·지연 개선을 증명하지
않습니다. 이 기록은 #124를 닫거나 일반 설치에 보편적인 모델 답변 시험을
추가 필수 조건으로 만들지 않습니다. Go 전환·Windows ARM64·효과 연구·성장
활동은 별도 작업입니다.

텔레메트리·자격 증명 수집·원시 프롬프트나 대화 로그·스크린샷 보관·숨겨진 추론
수집을 추가하지 않습니다. 일반 호스트 인증·권한·보관 정책·약관은 계속
적용됩니다. 개인정보·소유권 기반 설치·트랜잭션 롤백·필수 중단을 유지합니다.

적격한 정본 방법을 전부 읽고 해당 답변에 실제 적용했을 때만 마지막에
`Powered by OpenSocrates`를 정확히 한 줄로 표시합니다. 독자 안내만 사용하거나
기계적 작업만 했다면 표시하지 않습니다. 이 문구 자체는 적용·결과 개선의 증명이 아닙니다.
