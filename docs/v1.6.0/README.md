# OpenSocrates v1.6.0 Go 전환 준비

v1.6.0은 현재 릴리스의 48개 방법을 기준으로 실행 로직, 설치, 업데이트와 개발 도구를 Go로 통일하는 작업이다. 별도 세션의 48개 본문 업그레이드는 v1.6.0에서 제외하고 v1.6.1 등 후속 릴리스로 분리한다. 지금 단계의 산출물은 구현 범위와 작업 순서, 인계 항목, 수락 기준이다.

초기 준비 기준은 2026-10-12의 `main` 커밋 `9572db2c71a455d4ada24c78402d0f874002cec9`였다. 현재 콘텐츠 기준은 출시된 v1.5.2 소스 `9838db16910c5f22d9dcc3c7180350cb406fd236`, 리비전 5·48개 방법·열 언어다. 주석 태그 객체 `4c27d59da54eb1591ba24c0ebae62d6ab3168b60`와 같은 트리의 main 병합 `8f08b9a90d711fa3fc60cc7db6f962e3dda43c42`는 서로 다른 소스 식별자다. 초기 v1.5.0·리비전 3과 v1.5.1·리비전 4 기록을 보존하며 새 지원을 되돌리지 않는다. 별도 본문 개선 완료는 선행 조건이 아니다. 실제 해시와 입력은 [현재 기준](CONTENT_BASELINE.json)에 기록한다.

## 사용자 요구와 계획의 기본값

사용자 요구는 기존 Python/JavaScript 코드를 통일할 언어를 검토하고, npm에 얽매이지 않는 설치 방법과 향후 자동업데이트를 마련하며, 포팅 중 필요한 구조 개선도 함께 하는 것이다. 이후 범위 결정에 따라 48개 본문 업그레이드는 후속 릴리스로 옮겼다. v1.6.0은 기존 본문을 유지하는 포팅과 운영 개선으로 진행한다.

계획의 기본 방향은 다음과 같다. 라이브러리나 설치 파일 형식의 세부 선택은 구현 시 현재 API와 실제 패키지 결과를 확인해 고정한다.

- 제품 실행, 설치·제거·진단, 업데이트, 활성 생성·검증·릴리스 도구를 Go로 작성한다. 최종 제품과 활성 개발 경로에 자체 Python·JavaScript·PowerShell·셸 구현 의존성을 남기지 않는다.
- 정식 설치 채널은 GitHub Releases의 플랫폼별 Go 설치 프로그램으로 한다. 사용자에게 Go, Python, Node.js 설치를 요구하지 않는다.
- 자동업데이트는 macOS ARM64와 Windows x64/ARM64의 Codex 설치를 필수 지원 대상으로 한다. 추가 로컬 호스트 확장은 각각의 적용·복구 수락 기준을 통과한 뒤 지원 범위에 넣는다.
- 콘텐츠·스키마·실행파일은 검증한 버전 묶음으로 관리한다. 호스트별 설치 버전과 적용 상태를 따로 기록한다.
- 기본 선택 경로에는 추가 모델 선택 호출, 별도 인증, 원문 보관을 도입하지 않는다. 이전 SDK 경로는 외부 Codex app-server에 대한 별도 Go 어댑터로 포팅한다.
- 자동업데이트는 사용자가 켤 수 있게 하고 `stable` 채널을 기본값으로 한다. 메이저 업데이트와 호환성을 깨는 데이터 전환은 자동 적용하지 않는다.

Markdown·YAML·JSON·운영체제 예약 작업 설정과 GitHub Actions 설정은 유지할 수 있는 데이터다. 기존 호스트 앱, 외부 Codex 실행파일과 운영체제의 서명 도구는 외부 구성요소이며 OpenSocrates의 자체 소스 언어 범위와 구분한다. 현재 릴리스와 과거 평가 기록은 원본을 보존한다.

## 호스트와 플랫폼 범위

아래 표는 v1.6.0의 목표와 검증 경계다. 준비 문서만으로 현재 지원을 확대하지 않는다.

| 대상 | 플랫폼과 설치 범위 | v1.6.0 목표 | 자동업데이트 경계 |
| --- | --- | --- | --- |
| Codex CLI와 Desktop의 로컬 통합 | macOS ARM64, Windows x64/ARM64 | 기존 훅·선택·관리 명령 유지, Go 설치 인수 | 세 플랫폼 필수. 훅 신뢰 승인과 실제 적용 관찰은 별도 |
| Claude Code 로컬 통합 | macOS ARM64, 사용자 범위 | 현재 네이티브 프로필 유지 | 확장 대상. 등록·비활성 상태 보존과 다음 시작 또는 reload 동작을 별도 검증 |
| Antigravity 대화 앱 | macOS ARM64, Windows x64, workspace/global | 현재 rule/skill 설치·업데이트·비활성화·제거 유지 | 확장 대상. 사용자가 명시적으로 등록한 설치 범위만 관리 |
| Claude Web·Desktop Chat·Cowork 계정 스킬 | 콘텐츠 ZIP | 완전한 콘텐츠 생성·검증·내보내기 유지 | 계정 UI 업로드·활성화는 별도. 로컬 업데이트를 계정 적용으로 보고하지 않음 |

현재 Windows 네이티브 Claude Code는 지원 범위에 없다. Linux, macOS Intel, WSL, 원격 호스트 확대는 별도 작업으로 둔다. 계정 스킬의 모델 선택과 로컬 훅의 실행은 서로 다른 보장과 증거를 가진다.

## 함께 개선할 구조

1. 설치·업데이트·제거가 공통 작업 엔진을 사용하고, 호스트 등록과 운영체제 파일 처리를 별도 어댑터로 분리한다.
2. 준비·적용·확인·완료 단계를 기록해 강제 종료 후에도 복구할 수 있게 한다. 변경된 파일이나 확인되지 않은 잠금을 임의로 제거하지 않는다.
3. 기본 콘텐츠 선택, 짧은 훅, 관리 명령, 이전 SDK 연결을 각각 명확한 서비스 타입과 생성 경로로 분리한다.
4. Python 클래스에 종속된 스키마 생성을 언어 중립 계약으로 옮기고, 기존 JSON·해시·저장 상태의 호환성을 유지한다.
5. 플랫폼·설치 범위·지원 명령·자동업데이트 정책을 배포 프로필에서 관리한다. 배포 프로필과 런타임 어댑터의 지원 목록은 구분한다.
6. 오류 메시지 문자열 추측 대신 명확한 오류 코드를 사용한다. 훅의 안전한 통과와 원문 없는 진단은 유지한다.

파일 길이나 디렉터리 모양 자체를 결함으로 보지 않는다. 위 변경은 중복된 설치 흐름, 서비스 조립, 복구와 호환성 경계를 명확히 하기 위한 것이다.

## 완료 기준

- 출시된 v1.5.2의 열 언어 본문과 콘텐츠 의미를 모든 배포 프로필에서 같은 기준으로 생성·검증하고, 후속 본문 업그레이드를 섞지 않는다.
- 기존 기능과 지원 범위가 Go 구현에서 유지되고, 의도한 동작 개선은 별도 사례로 확인한다.
- 활성 제품·생성·검증·릴리스 경로가 자체 Python/Node.js 구현 없이 동작한다.
- 기존 v1.5 설치를 설정·신뢰·비활성 상태·관련 없는 파일의 손실 없이 인수한다.
- 필수 자동업데이트 대상에서 서명 검증, 중단 복구, 실행 중 버전 보존과 업데이터 자체 갱신을 검증한다.
- macOS와 Windows의 네이티브 설치·권한·잠금·제거 검사와 실제 주장하는 호스트별 적용 검증을 완료한다.
