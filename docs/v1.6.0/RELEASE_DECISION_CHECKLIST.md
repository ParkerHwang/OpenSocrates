# v1.6.0 release decision checklist / 출시 판단표

Use this checklist for one final candidate alongside the [implementation handoff](IMPLEMENTATION_HANDOFF.md), [release preparation](RELEASE_PREPARATION.md), [distribution contract](DISTRIBUTION_AND_UPDATE.md) and [environment review](RELEASE_ENVIRONMENT_REVIEW.md). It records separate decisions; writing this document establishes implementation only, not release readiness. Existing [contribution](../../CONTRIBUTING.md), [security](../../SECURITY.md) and [approval policies](HOSTED_MAC_SIGNING.md) remain authoritative.
/ 최종 후보 하나에 대해 기존 인계·배포 계약과 함께 사용한다. 문서 작성 완료는 구현이며 출시 준비 완료가 아니다. 기존 기여·보안·승인 정책을 그대로 따른다.

## Candidate and evidence record / 후보와 증거 기록

The release coordinator records these fields in the issue/PR for **each item and each claimed platform/profile/scope**. Until a candidate is frozen, `candidate_source_sha=null` with reason `final_candidate_not_frozen`; all final-candidate decisions below start `UNKNOWN`.
/ 출시 조정자는 항목별·주장하는 플랫폼/프로필/scope별로 아래 값을 이슈/PR에 기록한다. 후보 동결 전 SHA는 `null`, 사유는 `final_candidate_not_frozen`이며 최종 후보 판정은 모두 `UNKNOWN`에서 시작한다.

| Field / 필드 | Required value / 필수 값 |
| --- | --- |
| Identity / 식별 | Candidate full source SHA, product version, content revision, canonical baseline; platform/architecture, profile/scope and actual OS/tool/host versions / 후보 전체 SHA·제품 버전·콘텐츠 리비전·정본 기준·실제 실행 환경 |
| Evidence / 근거 | Evidence's own full source SHA, artifact/manifest SHA-256, durable receipt/run URL, exact commands, exit codes, run attempt and observed time / 증거 자체의 전체 소스 SHA·파일/목록 해시·보존 위치·정확한 명령과 결과·시도·관측 시각 |
| Decision / 판정 | `PASS`, `FAIL`, `UNKNOWN` or `NOT_APPLICABLE`, owner role, missing input/blocker, next action / 판정·담당 역할·누락 입력/막힘·다음 조치 |

`UNKNOWN` uses `null` for unobserved values and a concrete reason; it never means pass. An observed failed check is `FAIL`, including timeout; preserve the original attempt. `NOT_APPLICABLE` needs an existing scope exclusion, never missing access. Reuse evidence only with its original identity and a stated unchanged-input justification; changed source/bytes need affected checks on their own identity. Retain safe categorical results and hashes, never raw prompts/transcripts, screenshots, credentials, workspace contents or raw host logs. Native entry/read assertions do not prove application or useful results.
/ 미관측 값은 `null`과 구체 사유로 남긴다. 시간 초과를 포함한 실제 실패는 `FAIL`이며 기존 시도를 보존한다. 접근 불가는 범위 제외가 아니다. 과거 증거는 원래 식별자와 변경 없는 입력에 대한 재사용 근거를 유지하고, 변경된 소스·파일은 해당 검사를 다시 받는다. 공개 기록은 안전한 범주·해시로 제한한다. 네이티브 진입·읽기 주장은 적용·유용성 증거가 아니다.

## Independent decisions / 독립 판정

Each row has its own evidence source SHA and decision. A blocked row does not stop unrelated implementation or preparation; it prevents only the dependent claim/action under existing release policy. No row can substitute for another required gate.
/ 각 행은 별도 증거 SHA와 판정을 가진다. 막힌 행과 무관한 구현·준비는 계속할 수 있으며, 기존 정책에 따라 해당 증거에 의존하는 주장·실행을 보류한다. 필수 관문을 다른 행의 통과로 대체하지 않는다.

## Execute around blockers / 막힘을 분리한 실행 순서

- [ ] **Freeze and reconcile — Go integrator.** Select the final source and content baseline before final verification. Reconcile current main and selected reviewed fixes; draft work is not automatically an accepted dependency. Record any exclusions and known defects. / **동결·조정 — Go 통합 담당.** 최종 검증 전 소스·콘텐츠를 고정하고 현재 main·선택한 검토 완료 수정과 조정한다. Draft를 자동 선행 조건으로 삼지 않고 제외·알려진 결함을 기록한다.
- [ ] **Prepare independent work — lane owners.** Source/native checks and migration fixture preparation can proceed while production identities, compatible machines or host access are unavailable. Public production-update execution depends on production trust/artifacts; clean-machine and host activation retain their own environment requirements. Fix a concrete defect in its owning lane, then rerun affected checks. / **독립 준비 — 각 담당.** 운영 신뢰·기기·호스트 접근이 막혀도 무관한 소스/네이티브 검사·이전 fixture 준비는 진행한다. 공개 운영 갱신은 운영 신뢰/파일이 필요하며 새 기기·활성화는 각각 환경이 필요하다. 실제 결함은 담당 영역에서 고치고 영향 검사만 반복한다.
- [ ] **Integrate follow-up evidence — S092 for this work batch.** Consume S061–S069 material when available, retain its source/artifact identities and separate proposed fixtures/research from executed results. Integrate repository changes through S092; absence of sibling material does not justify invented evidence or waiting on unrelated work. / **후속 근거 통합 — 이번 작업의 S092.** 가능한 S061–S069 자료를 원래 소스/파일 식별자와 함께 반영하고 제안 fixture·조사와 실행 결과를 구분한다. 저장소 통합은 S092가 맡으며 미도착 자료를 꾸미거나 무관한 작업을 멈추지 않는다.
- [ ] **Record the release decision — release coordinator.** Put each lane's result, source SHA, missing evidence and next owner/action in the durable PR handoff. Keep Draft, required checks, live-evidence and existing merge/tag/publication/direct-owner-approval boundaries. This checklist adds no approval step and grants no authorization. / **출시 판단 기록 — 출시 조정자.** 행별 결과·소스 SHA·누락 근거·다음 담당/조치를 PR 인계에 남긴다. Draft·필수 검사·실제 증거와 기존 병합/태그/게시/직접 승인 경계를 유지하며 새 승인 절차나 권한을 만들지 않는다.

Method-body upgrades, a separate stabilization program, answer-effect studies and growth targets are follow-up work, not added Go release prerequisites. Concrete privacy, safety, compatibility, delivery or lifecycle defects remain subject to the existing applicable gates; missing native application receipts must not become a new completion gate.
/ 본문 업그레이드·별도 안정화 프로그램·답변 효과 연구·성장 목표를 Go 출시의 추가 선행 조건으로 만들지 않는다. 실제 개인정보·안전·호환·전달·수명주기 결함은 기존 해당 관문으로 처리하며 네이티브 적용 영수증 부재를 새 완료 조건으로 만들지 않는다.
