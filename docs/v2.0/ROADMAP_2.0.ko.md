# OpenSocrates 2.0 개발 로드맵과 인계

상태: **사용자와 정한 방향을 구현 가능한 작업으로 옮긴 계획**. 기능 구현, 실사용 효과 또는 네 가지 데스크톱 환경의 지원을 주장하지 않는다. [제품 요구사항](VISION_2.0.ko.md), [시스템 구조](SYSTEM_2.0.ko.md), [검증 계획](VALIDATION_2.0.ko.md)을 함께 읽는다. 범위와 사용자 선택은 이 문서 세트가 이전 2.0 계획보다 우선하며, 릴리스·개인정보·보안 및 저장소 운영 규칙은 변경하지 않는다.

## 착수 기준과 우선순위

1. 사용자 요청과 대화에서 확인한 범위는 ChatGPT 데스크톱(Chat·Work·Codex)과 Claude 데스크톱을 macOS와 Windows에서 사용하는 것이다. 네 앱·OS 조합과 각 모드를 독립적으로 조사·검증한다. 특정 모드에 컴퓨터 사용, 스킬, 메시지 전송 또는 세션 생성이 제공된다고 미리 가정하지 않는다.
2. 한 컴퓨터의 개인별 프로그램을 기본 범위로 한다. 다중 컴퓨터 동기화는 추후 업데이트다. Grok Bot과 Cursor는 첫 버전 대상에서 제외하고 추후 재검토한다. 기존 1.x 사용자의 지원 프로필을 예고 없이 제거하라는 뜻은 아니다.
3. 기존 앱과 그 대화 세션을 활용한다. 에이전트 실행을 위한 별도 모델 제공자 API와 이를 통한 독자적 AI 앱은 현 범위가 아니다. 공식 연결·호스트 기능을 우선 조사하고 필요할 때 기존 컴퓨터 사용 도구나 오픈소스를 검토한다. 가능한 경로가 없으면 그 조합은 미지원·미검증으로 표시한다.
4. 사용자가 의뢰한 대화는 요구 정리·상담·업무 준비·조율과 보고를 맡고 실제 산출 업무는 새 작업 세션에서 수행한다. 모든 에이전트 간 메시지는 OpenSocrates 통신 계층을 거친다. 각 세션에 업무별 프롬프트와 적합한 맥락·추론 가이드를 전달한다. 이 동작을 제공하지 못하는 호스트에서 달성했다고 표시하지 않는다.
5. 기존 48개 가이드는 설치 초기와 적합한 개인 가이드가 없을 때 사용하는 기반이다. 개인 가이드는 개수 제한 없이 생성·조정하고, 적합한 경우 결합하거나 재조립한다. 공통 생성 지침은 OpenSocrates 버전업으로 바뀌고 사용자별 학습이 공통 지침을 바꾸지 않는다. 필요한 경우 가이드 재조립을 별도 에이전트에 맡길 수 있다.
6. 각 사용자별 백그라운드 학습은 명시적 학습 명령 없이 경험에서 다룰 문제를 찾고, 실제 작업과 진행 중인 관련 작업에 새 방향을 적용하며 발전한다. 중단 전후의 학습 상태를 추적한다. 특정 강화학습 알고리즘, 모델 가중치 변경, 토큰 정렬의 효과는 확정된 사실이 아니다.

## 바로 시작할 개발 흐름과 통합 접점

위 표의 선행 항목은 **해당 기능을 통합 완료로 판단할 때의 의존**이다. 모든 선행 항목의 세부 구현이 끝나야 다른 팀이 탐색이나 합성 시험을 시작할 수 있다는 뜻은 아니다. 아래 작업은 공개 합성 자료와 현재 정책 범위에서 병행 착수할 수 있다. 가짜 호스트는 전환·오류를 반복하는 시험 장치이며 실제 앱 세션이나 실제 학습 결과가 아니다.

| --- | --- | --- |

초기 접점은 구현 언어·DB를 정하기 전에 다음 의미로 맞춘다. 이는 파일명이나 고정 역할 지정이 아닌 **서로 독립적으로 교체 가능한 경계의 초안**이다.

| --- | --- | --- |

| 학습·재개 | 허용된 경험 신호와 현재 설정·공개 진행 상태 → 학습 문제·가이드 후보 또는 대기 | 이번 업무 수정과 영구 선호, 생성과 검증, 일시중지와 취소·삭제, 로컬 상태와 외부 효과. 중단 후 입력을 다시 구할 수 없다면 그 판단만 보류한다. |

가짜 어댑터는 위 경계에서 미지원·지연·오류·중복·재시작을 재현할 수 있어야 한다. 이 가짜 경로가 특정 호스트의 기능·대화 신원·개인화 품질을 입증하지는 않는다. 테스트 기록도 현행 개인정보 정책을 따른다.

통합할 때는 해당 결합에 필요한 계약만 맞춘다. 예를 들어 한 실제 호스트의 첫 경로는 그 표면에서 관찰한 진입점, 해당 경로에 필요한 권한·데이터 정책, 계층의 관련 전송·실패 계약과 적합한 가이드 준비가 필요하다. **완성된 전체 맥락 제품이나 모든 앱·OS의 지원을 첫 호스트 실험의 전제조건으로 두지는 않는다.** 수신자 결속이 아직 미확인인 경로라도, 허용된 범위의 공개 합성 자료로 결속 가능성을 탐색할 수 있다. 이는 민감한 실제 업무 내용을 보내도 안전하다는 허가나 증거가 아니다. 반대로 가짜 호스트가 통과했다고 실제 세션을 만들거나 소통했다고 표시하지 않는다. 첫 실험은 사용자의 의뢰 대화와 별도의 실제 세션, 계층을 통한 요청·결과, 가능한 경우 진행 중 교환을 각각 관찰하고, 어느 단계까지 됐는지와 누락된 단계를 함께 보고한다.

한 앱·OS 경로가 막히면 그 경로의 지원 주장과 의존하는 통합만 보류한다. 다른 표면의 조사와 정책을 지키는 내부 실험은 계속할 수 있다. 이것은 최종 범위를 한 앱으로 바꾸는 결정이 아니다. ChatGPT·Claude와 macOS·Windows의 사용자 약속, 개인별 경험 학습과 진행 중 적용, 설치·롤백·독립적인 품질 평가에 관한 완료 판단은 각각의 실제 근거를 갖춘 후에 한다. 호스트가 제공하지 않는 영수증이나 관찰할 수 없는 효과는 미확인으로 보존하고, 필요한 제품 동작 자체를 미확인으로 바꿔 완성 처리하지 않는다.

회의는 Codex가 주도하고 Claude Opus 5.5와 Cursor의 Grok 4.7 High가 기존 네 개 계획서를 검토한 뒤 서로의 제안과 질문에 답하는 방식으로 진행했다. 현재 macOS의 기존 Claude·Cursor 대화에서 computer use로 요청을 입력하고 응답을 읽었으며, Codex가 내용을 수동으로 중계했다. 이는 해당 기존 대화의 화면 조작 관찰이지 2.0 프로그램의 채널이나 새 세션 자동 생성의 증거가 아니다. 아래는 발언 전문이 아닌 공개 설계 요약이며, **검증된 구현이나 사용자 추가 결정이 아니다**. Gemini의 의견은 사용자의 요청에 따라 포함하지 않는다.

- **제품의 중심:** 거친 요청을 의뢰 세션이 정리하고, 사용자가 선택한 형식을 보존해 OpenSocrates가 실제 앱의 여러 세션을 연결한다. 경험을 통한 개인 가이드의 조용한 발전과 관련 작업에서의 적용이 결합된 한 팀의 경험이 목표다. 강한 제품 경험은 구호가 아니라 실제 반복 사용·품질·부담·통제로 평가한다.
- **Claude의 기여와 수정:** 가이드 생성 지침의 구체 초안, 업무별 확정 선택을 하위 업무에 전달하는 `DecisionLock` 후보, 관련·무관한 후속 업무를 포함하는 평가를 제안했다. 가이드를 독자·목적과 사고 순서에만 한정하고, 반례나 장기 관찰을 모든 후보의 선행 조건으로 삼으며, 사실 메모와의 비교 하나로 제품 전체 가치를 판단했던 주장은 반론을 받고 철회했다. `DecisionLock`은 사용자 변경과 업무별 적용 범위를 존중하는 제안이다.
- **Grok의 기여와 수정:** 미전달 본문 복구 불가, 전송 후 외부 효과 미확인, 학습 근거 부재를 구별하고, 상태 기계의 오프라인 시험과 한 실제 앱의 왕복 시험을 제안했다. 모든 덮어쓰기·외부 전송·삭제·프로젝트 간 이전에 일괄 확인을 붙이거나 화면 조작 충돌 시 학습 전체를 중단하자는 넓은 제안은 철회했다. 마지막 교차 검토에서 별도 분류·판단 세션의 일괄 금지도 철회하고, 초기 순환을 피하면서 필요할 때 위임하는 수정에 동의했다.
- **의장의 정리:** 후보 생성과 실제 사용, 호스트 전달과 결과 품질을 별개로 취급한다. 사용자가 정한 중요한 선택과 권한은 조용한 학습보다 우선한다. 이미 열린 의뢰 세션으로 초기 판단을 시작하는 것은 유력한 실험 후보지만 별도 판단 세션을 원천 금지하지 않는다. 한 번의 실제 앱 연결 성공을 다른 앱·OS의 지원으로 확대하지 않는다.
- **미해결:** 호스트별 실제 연결과 진행 중 전달, 원문 비보관 정책 아래 입력 재확보와 안전한 개인 가이드 보관, 의미 판단의 주체·속도·비용, 중복 효과 방지, 개인화와 부작용의 독립 평가. 특히 사용자 선호로 잘못 귀속한 학습이 조용히 반복될 수 있으므로 사용자가 요청 시 적용·근거를 확인하고 수정할 경로와 탐지 평가가 필요하다. Claude가 제안한 자동 한 줄 표시는 사용자가 원하는 조용한 경험에 맞는지 미결이며 확정하지 않는다. 저장소 정책과 각 호스트의 제한을 바꾸거나 우회하는 결정은 이 회의가 내리지 않았다.

### 이어진 심층 회의

사용자의 요청에 따라 첫 교차 검토에서 회의를 닫지 않고 사용자 경험, 암묵 학습, 기존 연구, 앱별 연결, 맥락 전환, 동적 분담을 다시 검토했다.

- **Claude**는 사용자 정정이 이번 파일의 오류인지 특정 독자의 요구인지 재사용할 접근인지 잘못 귀속될 수 있다는 반례와, 관련 후속 업무·무관 업무·바뀐 선호를 포함한 비교를 제안했다. 사용자가 이미 허용한 파일 수정에 일괄 확인하거나 지표 중심과 결정 중심을 무조건 충돌로 취급한 제안은 반론 후 수정했다.
- **Grok**은 실행 대화의 변경을 레이어가 읽거나 다시 전달할 수 없는 상황, 다른 세션의 쓰기가 끝났는지 알 수 없는 상태에서의 맥락 전환, 자체 호스트 메모리가 범위 밖 선호를 재도입하는 사례를 제시했다. “명시적으로 앞으로라고 말할 때만 학습 후보”, “학습은 항상 파일 전달 후”처럼 암묵 학습과 진행 중 반영을 제한하는 제안은 반론 후 완화했다.
- **의장 검토:** [Reflexion](https://arxiv.org/abs/2303.11366), [PAHF](https://arxiv.org/abs/2602.16173), [AutoAgents](https://arxiv.org/abs/2309.17288)와 기존 앱 메모리를 확인했다. 개별 아이디어의 최초성 대신, 사용자가 실제로 얻는 이익과 호스트 간 제약의 조합을 공정하게 검증해야 한다. 실제 세션을 열고 레이어를 거치는 자동 경로는 아직 이 회의에서 입증되지 않았다.
- **남은 설계 검토:** 사용자 상담·결과물·실행 세션의 현실적 왕복, 운영 중 학습을 위한 호스트 진입점, 저장·검색·삭제 경계와 성능, 동적 분담이 단일 실행보다 유익한 조건, 사용자에게 보이는 신뢰와 통제. 문서에 사례가 추가된 사실만으로 이 의문이 해결된 것은 아니다.

두 모델이 `e21b396`의 네 원문을 다시 읽은 뒤, 의뢰·학습 세션에 가이드와 공통 생성 지침을 전달하는 경로의 누락, 1.x 컨트롤러와 개인 가이드의 신뢰 경계, 실행 세션의 사용자 지시와 모델 보고의 출처 구별, 일시정지 직전 대기한 가이드의 전송 경쟁, 기본 정본이 한도를 넘을 때의 처리, 일부 가이드 적합성에 관한 미결 정책과 시험의 모순, 삭제 후 파생 가이드·동시 파일 쓰기를 지적했다. 이 판에는 그 수정과 대표 검증 사례를 추가했다. 추가된 계약은 여전히 구현과 실제 호스트 검증을 필요로 한다.

이어 `73e5b20`을 두 모델이 다시 검토했다. 개인 가이드의 일부만 적합할 때 그 부분의 사용도 후보에 남기고, 모델의 미확인 보고와 기존 권한 안의 작업 판단을 구분하며, 학습 중지 상태·파생 가이드의 실제 적용 보류·대기 중 파일 충돌을 구체화했다. 공통 생성 지침의 일부만 전달된 경우와 기록 금지된 결과의 호스트 재전송도 별도로 다루었다. 이 검토 역시 계획의 반례 탐색이며 실제 제품 완성을 입증하지 않는다.

이후 `fd8ee36`에 대한 추가 검토에서는 이전 3쪽 결정이 실행 세션의 잠정적 4쪽 변경을 덮어쓰는 문제, 최초 설치와 중지 설정의 완전 유실을 구별할 수 없는 문제, 생성 지침 모듈 이력과 유출 검사 양성 대조의 부재, 확인된 사용자 변경의 후속 위임, 완결 모듈의 필수 보호 조건을 다시 다뤘다. 설정이 완전히 사라진 경우의 자동 시작 정책은 사용자 경험과 이전 중지 존중이 충돌할 수 있어 여전히 대안·실험 과제다.

`4ec1b76`의 수정에 대한 추가 상호 검토에서는 저장 전 점검기의 개정과 결과 추적, 필수 생성 조건이 실제로 빠진 결과와 단지 읽음 증거가 없는 결과의 구분, 모델의 미확인 전언이 중요한 내용을 삭제하는 반례를 더 다뤘다. 의장은 영향받은 후보나 변경만 다루고 무관한 작업은 계속하는 방향으로 반영했다. 체크·전달의 실제 효과는 여전히 제품 구현과 별도 실험이 필요하다.

그 뒤 호스트 연결과 최신 MCP 규격을 놓고 다시 교차 검토했다. Claude는 로컬 연결을 수령 범위에 묶는 안을 냈지만, Grok과 의장이 여러 대화가 연결을 공유할 수 있다는 반례를 제기하자 이를 대화 인증이 아닌 범위 제한 후보로 정정했다. Claude의 추가 안에서 같은 앱의 파일 접근을 다른 대화로의 전달 권한으로 확대하고 외부 효과가 없다고 가정한 부분도 의장이 반박했다. Grok은 특정 MCP 구독만 진행 중 전달이 가능하다고 한 주장을 수정했다. 의장은 기존 앱 세션에 수동으로 메시지를 중계한 이번 회의와 2.0의 자동 채널을 구별하고, 업무 전체를 멈추지 않으면서도 수신자와 권한이 미확인인 민감 전달을 보류하는 기준을 설계에 넣었다. 앱별 새 대화 왕복·수신자 바인딩·진행 중 교환을 먼저 가를 관찰로 정리했으며, 이 역시 아직 시험 결과가 아니다.

Claude는 그 반례를 수용해 파일 참조도 민감할 수 있고 잘못된 세션이 결과 검증 전에 외부 효과를 낼 수 있다는 점을 정정했다. 다만 신원 미확인 시의 축소 위임안은 호스트 권한에 따라 위험이 남는 가설로 남긴다. Grok도 연결 중단 후 이미 수임한 업무의 계속과 처음부터 레이어를 거치지 않은 별도 작업을 구별했다. 후자는 2.0 자동 위임의 성공으로 세지 않는다.

다음 회의에서는 기존 가이드가 영향을 주었을 수 있는 결과를 다시 사용자 선호의 독립 근거로 잘못 세는 자기강화를 검토했다. Claude는 노출된 결과에 대한 반응으로 같은 차원의 새 후보를 만들지 말자고 제안했으나, 의장이 사용자의 직접 수정까지 버린다는 반례를 들자 철회했다. Grok은 원문을 저장하지 못하면 수정 내용을 사용할 수 없다고 보았으나, 일시적 해석과 허용된 원본 재열람이 별개라는 반론을 수용했다. 두 모델은 사용자의 수정은 조건부 신호로 활용하되 가이드의 인과 효과나 독립 지지로 자동 승격하지 않는 방향으로 수정했다. 의장은 전달과 실제 사용의 차이, 메타데이터 자체의 보관 허용 여부, 알려지지 않은 중복 관계를 별도로 남겼다. 추천 시스템의 피드백 편향 연구는 반례를 생각하는 출발점이며 2.0의 실사용 효과를 증명하지 않는다.

추가 반론 후 Claude는 출력이 가이드의 예상과 비슷하다는 이유로 실제 사용을 주장했던 표현과 정해진 분류어만 허용하자는 제안을 철회했다. 분류어도 정보의 조합에 따라 민감할 수 있으며, 사용자 고유의 새 추론 방향을 닫힌 목록으로 제한하지 않는다.

또 다른 회의에서는 그래프 위임 후 비전문가인 통합 세션이 무엇을 확인할 수 있는지 논의했다. 의장이 월별 인원비를 동일인 유지율로 잘못 제시하자 두 모델도 같은 설명을 받아들였다. 의장은 같은 월별 합계에서 서로 다른 교집합이 가능한 합성 반례를 직접 계산해 전달했고, 두 모델이 이를 수용해 검수안을 수정했다. 그 결과 단일 위임 요청에 지표의 목적과 정의를 담고, 계산·정의의 타당성·파일 편집·최종 Word 반영을 따로 살피며, 공유 전제와 이전 결과의 지연을 확인하는 예시를 추가했다. 이 회의는 2.0의 자동 검수 성공이 아니라 공유된 오해가 검수에서 살아남을 수 있다는 제한된 관찰이다.

이후 거친 한국어 요청에서 정본과 개인 가이드를 찾고 적용하는 문제를 논의했다. 두 모델은 일부 정본과 선택 경로를 조사하고 후보 검색과 적용 조건·금기 판단을 구분했다. 의장은 공개 정본 48개에 대한 메모리 FTS 검색과 1.x `decision`의 합성 구조화 입력을 각각 실행했다. 후자는 사전부검을 후보로 반환했지만 적용은 미검증이었다. Claude는 처음에 선택 메타데이터와 절차 본문의 차이를 실제 결함으로 부르고 개인 가이드를 정본 아래로 제한했으나, 의장의 실제 실행 결과와 반론을 검토한 뒤 두 주장을 철회했다. Grok은 읽기 영수증이 없다는 이유만으로 미전달로 단정하지 않도록 정정했다. 이 실험은 해당 모델들의 실제 사용자 요청 분류나 2.0 가이드 검색·효과를 측정하지 않는다.

이어 HTML의 데이터 흐름을 실제 그림으로 검토했다. Grok은 작업 세션과 통신 계층을 단순 양방향으로 그리면 새 의뢰가 가이드·맥락 준비와 앱 어댑터를 건너뛰는 것처럼 보인다고 지적했다. Claude는 기존 한·영 Mermaid에도 선택적 학습·재조립 세션의 결과가 통신 계층을 거쳐 프로그램 내 학습으로 돌아오는 연결과 사용자에게 결과를 전달하는 표기가 빠져 있음을 짚었다. 의장은 원본과 SVG 요약을 함께 고치고, 경험 신호와 생성 결과, 실제 앱 세션과 프로그램 내부 학습·DB를 구분했다. 원문 변경을 놓치지 않도록 지문 검사를 추가했지만, 지문 일치는 그림의 의미 정확성을 자동으로 보장하지 않는다. 이는 계획 문서의 개선이며 실제 연결 성공의 증거가 아니다.

이어 맥락 분기 전환 중 같은 파일을 쓰는 상황을 검토했다. 의장은 임시 합성 파일로 지문 확인 뒤의 교체 경합과 열린 옛 핸들에 대한 쓰기를 macOS에서 순서를 고정해 재현했다. Claude는 같은 지문을 이전 쓰기 여부의 확정 근거로 쓰거나 미확인 조건마다 새 파일·재승인을 요구하던 제안을 반례 후 정정했다. Grok은 비협력 외부 쓰기를 시스템이 반드시 차단해야 한다는 시험 조건이 미검증 조건부 저장을 전제한다는 반론을 수용했다. 과거 시점의 보고서와 현재 결정을 위한 보고서를 구별하고, 확인 가능한 조정·허용된 대안·미확인 상태를 문서와 사례에 반영했다. 이 실험은 실제 Word·여러 앱·Windows나 2.0의 파일 보호를 검증하지 않는다.

구체 지침 초안과 상태 계약은 [시스템 설계 §12–14](SYSTEM_2.0.ko.md), 합성 시연과 비교 실험은 [검증 계획](VALIDATION_2.0.ko.md)을 따른다. Claude와 Grok의 서로 다른 제안은 설계 근거이지 실제 효과의 증거가 아니다.

백그라운드 학습의 중단과 재개를 이어서 논의했다. 의장은 기존 그림이 재개할 때마다 첫 해석으로 돌아가는 것처럼 나타낸 점을 지적했고, Claude와 Grok은 단계별 재개와 해당 판단만 보류하는 방향을 제안했다. Claude는 처음에 진행 중 세션으로 다시 전달하지 말자고 했지만, 의장의 반례를 받아 적합하고 지원되는 진행 중 세션에도 적용할 수 있도록 수정했다. 또한 단계 전환 사이에 설정이 바뀔 수 있으므로 각 전환 전 권한을 확인하자고 제안했다. Grok은 재개 뒤 새 신호만 처리하자는 제한을 철회하고, 재개 시 현재 권한·입력을 확인하며 모델의 이전 출력을 독립 신호로 다시 세지 말아야 한다고 짚었다. 일시중지·취소·사용 중단·삭제는 구별하고, 이전 결과를 자동 채택하거나 매번 새 승인을 강제하지 않는다. 의장이 실행한 단일 프로세스의 합성 SQLite 버전 검사에서는 오래된 조건부 갱신과 새 갱신이 구분됐지만, 실제 중단 복구나 외부 앱 전달을 시험하지는 않았다. 설정 기록이 전부 사라졌을 때 최초 설치와 과거 중지를 구분하는 문제는 열린 상태다.

의장은 모든 로컬 기록을 지워도 이미 외부 앱에 보낸 요청과 응답은 남을 수 있다는 반례를 제기했다. Claude는 로컬 흔적이 없으면 이전 작업이 되살아날 위험도 없다는 주장을 철회했다. 이후 의장이 발송 기록만으로 모든 학습 입력을 제한하고 출처 미상 결과의 내력·기록 권한을 추정한 제안에 반론하자, Claude는 현재 사용자의 지시와 직접 관찰 가능한 수정, 주체 미상 파일 변경, 출처 미상 에이전트 결과를 구분하고 건수·시각의 보관도 허용 범위에 따라야 한다고 정정했다. 최초 실행과 이전 중지의 완전 유실을 구분하지 못할 때의 자동 시작 정책은 선택지로 남긴다. 외부 세션의 출처 판별과 중복 방지는 실제 호스트의 지원을 검증해야 한다.

이어 실제 앱 세션의 보고서 왕복을 검토했다. A의 분석, B의 그래프 제작과 수정 요청, 결과의 A 복귀를 각각 계층을 경유하는 순서와 미확인 경계로 구체화했다. 의장이 암호화된 단기 저장이 현행 원문 보관 금지를 바꾸지 않는다는 점을 지적하자 Claude는 허용된 원천의 재접근과 복구 불가를 구분했다. Claude는 공유 폴더 인계가 계층을 우회할 수 있다는 반례를 받아들이고 파일 참조도 계층을 거치도록 정정했다. Grok은 식별값 반향과 가이드 버전의 출력을 전체 읽기·적용의 증거로 삼던 기준을 반론 후 수정했다. 화면 조작의 짧은 단위와 대기 중 반납은 사용자 방해를 줄일 후보이며 실제 호스트의 동작이나 충돌 방지 보장은 아니다. 이 회의는 공개 합성 시나리오에 대한 설계 검토이며 자동 세션 왕복 실험이 아니다.

다음 회의에서는 개발 착수 순서를 다시 나눴다. Claude와 Grok은 실제 호스트의 공개 합성 탐색과 가짜 호스트 기반 내부 계약을 병행하고, 해당 통합 주장에 필요한 조건만 연결하자고 제안했다. Grok은 처음에 수신자 식별 성공과 내부 계약 완성을 실제 연결 시도의 선행조건으로 뒀으나, 의장이 민감 자료와 공개 합성 시험의 차이를 제기하자 그 제한을 수정했다. Claude는 1.x·2.0 컨트롤러를 항상 하나만 켜고 어댑터를 끄면 롤백된다는 고정안을 철회하고, 실제 기존 설정·설치 자산·부분 이전을 조사해 공존과 복구를 검증하도록 정정했다. 별도 사용자 파일 의뢰의 권한도 프로그램의 원문 비보관과 구별했다. 이 순서는 구현 우선순위 제안이지 실제 호스트 통과나 사용자 범위의 축소가 아니다.

이어 발주와 감사의 합성 수정에서 각각 사고 방향 후보를 만들고, 같은 발주의 현재 요청이 분석 깊이를 제한하는 사례를 검토했다. Claude는 첫 답에서 제공되지 않은 수치와 판매 이력을 만들어 추천했으나, 의장의 반론 뒤 철회했다. 현재 지시는 즉시 따르되 일회성 선택을 장기 선호로 확정하거나 학습 검토를 무조건 금지하지 않고, 관련성이 불명확한 정본을 읽지 않은 채 부적합하다고 단정하지 않도록 정정했다. 추가로 메모리 통제가 어려운 평가에서 조건별 관찰과 가이드 자체의 인과 기여를 구분했다. 이 회의의 답변은 제품 학습이나 품질 향상의 증거가 아니다.

가이드 생성 사례에 대한 Grok의 답변도 도착했다. 처음에는 감사 가이드를 결론 후행의 고정 규칙으로 쓰고, 현재 지시를 비교군마다 다르게 배치했으며, 제공되지 않은 평균을 실제 발주안의 근거처럼 취급했다. 의장의 반론 뒤 현재 목적에 따른 판단, 모든 조건의 동일한 현재 지시, 근거 없는 추천 보류로 수정했다. 이어 Claude와 공통 생성 지침을 실제 세션에 전달할 수 있는 초안으로 조립하고, 외부 자료를 권한으로 승격하지 않으면서 업무 근거로 활용하는 것, 충분한 다른 근거가 남은 판단과 부족한 판단, 가이드 노출 뒤 실제 수정과 인과 증거를 각각 구분했다. Grok은 조립된 초안을 추가 검토하며 값이 언급된 사실과 실제 값·추천 근거의 혼동, 보관 전 검사 실패와 수신 미확인의 혼동을 반례로 들었다. 본문은 검증할 개발 초안이지 배포된 지침이나 효과의 증거가 아니다.

## 인계와 완료 판단

첫 구현은 현재 main의 실제 소스와 테스트를 다시 조사하고 기존 계약을 존중하는 집중 브랜치에서 시작한다. 철회된 v1.5 후보 PR #95의 코드와 가이드는 복사·이식·병합하지 않는다. 1.6 후보는 별도 검토 전 근거로 격상하지 않는다. 실제 호스트 전달·가이드 전체 읽기·적용·유용한 결과를 각각 구분한다.

최종 개발계획서가 있다고 해서 제품을 완성하거나 릴리스한 것이 아니다. 실제 구현과 각 호스트 셀의 검증·독립 평가·명시적 정책 결정이 끝나야 해당 동작을 주장할 수 있다.
