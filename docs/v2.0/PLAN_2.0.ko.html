제품 비전과 요구사항

상태: 2026-11-02 사용자 인터뷰를 반영한 개발 기준 문서. 제품 방향을 정리한 것이며 구현, 설치 지원, 학습 효과 또는 출시 완료의 증거는 아니다.

제품이 제공할 경험

사용자는 평소 쓰는 데스크톱 AI 앱의 대화에서 일을 의뢰한다. OpenSocrates는 불완전한 요청을 이해하고, 필요한 질문과 결과물 상담을 거쳐 업무 프롬프트를 정리한다. 현재 작업에 맞는 추론 가이드와 맥락을 준비하고 새로운 실제 대화 세션들에 작업을 전달한다. 각 작업 세션은 OpenSocrates 레이어를 통해 협의하고 결과를 돌려준다. 사용자는 그 팀을 직접 조직하거나 매번 같은 설명을 반복할 필요 없이 결과와 중요한 결정에 집중한다.

각 사용자의 OpenSocrates는 실제 업무 경험에서 추론 가이드를 만들어 발전시킨다. 추론 가이드는 단순한 사실 메모나 금지 목록에 머무르지 않고, 어떤 맥락과 관점에서 생각할지 돕는다. 동시에 OpenSocrates는 가볍고 빠른 데이터베이스와 통신·상태 관리 기능을 포함하는 실제 프로그램으로 발전한다.

사용자가 원하는 macOS·Windows 지원은 제품 요구다. 문서, 스킬 파일 또는 한 운영체제의 성공만으로 다른 조합의 실제 지원을 주장하지 않는다. 접근 불가능한 조합은 미검증으로 남기며, 필수 범위 축소는 제품 소유자의 별도 결정이 필요하다.

종류 출발점과 변화 주체 사용 방식
기본 48개 추론 가이드 설치 시 제공되는 기본 콘텐츠. 제품 버전 관리 대상이다. 개인 가이드가 아직 없거나 현재 작업에 적합한 개인 가이드가 없을 때 사용한다.
공통 가이드 생성 지침 모든 사용자에게 공통으로 제공한다. OpenSocrates 버전업으로 발전시킨다. 개인별 학습 로직이 경험을 추론 가이드로 바꾸고 평가하는 기준으로 활용한다. 사용자별 학습이 이 공통 지침을 임의로 다시 쓰지는 않는다.
개인별 생성 추론 가이드 각 사용자의 실제 작업·선택·수정·관련 경험을 바탕으로 생성하고 발전시킨다. 적합한 개인 가이드를 우선 사용한다. 여러 가이드를 선택·조합·재조립할 수 있다.

개인별 생성 가이드의 개수에는 48개 같은 고정된 제품 상한을 두지 않는다. 이는 디스크·컨텍스트·계정 사용량이 무한하다는 뜻은 아니다. 검색, 전달량, 중복과 오래된 가이드 처리, 저장 예산은 측정 가능한 설계 과제로 남긴다.

재조립은 문서를 나란히 붙이는 것보다 넓은 작업이다. 현재 업무에 필요한 부분을 선택하고 연결해 적합한 사고의 흐름을 만들 수 있다. 필요하면 OpenSocrates를 통해 별도 에이전트 세션에 재조립 업무를 의뢰한다. 재조립 결과를 이번 작업에서만 쓸지 개인 가이드로 남길지도 관련 경험과 맥락을 보고 판단하는 방향이다. 이 판단의 구체적인 기준과 검증 방법은 구현 전에 명세한다.

요구사항과 확인 가능한 결과

ID 요구사항 수용 사례
P01 불완전한 요청에서 목적·제약·원하는 결과를 파악한다. 결정에 영향을 주는 빈칸만 구체적으로 묻는다. 사용자가 두서없이 보고서를 의뢰했을 때 이미 말한 내용을 다시 묻지 않고, 결과가 갈리는 핵심을 짚어 질문한다.
P02 결과물의 내용·형식·사용 방식을 대략 보여주며 필요한 상담을 한다. 사용자의 이해 수준을 상황별로 살핀다. Word와 HTML의 차이를 모르는 사용자에게 수정·공유·사용 경험의 차이를 설명한다. 이미 형식을 선택한 사용자에게 불필요하게 선택을 되돌리도록 유도하지 않는다. 모든 사소한 일에 상담을 반복하지 않는다.
P03 사용자가 의뢰한 대화 세션에서는 실제 산출물 제작을 수행하지 않는다. 의뢰 세션은 요청 해석, 업무 프롬프트 준비, 가이드·맥락 준비, 상태 전달과 중요한 결정 상담을 담당한다. 조사·분석·그래프·문서 제작과 실제 결과물 통합은 새 작업 세션에서 수행한다. 완성 결과의 전달·표시는 의뢰 세션에서 가능하다.
P04 실제 앱 대화 세션을 열어 일을 수행한다. 사용자는 평소 의뢰 세션만 사용해도 된다. 필요하면 앱의 대화 목록에서 작업 세션을 열어 확인하거나 참여할 수 있다. 세션 생성과 접근은 앱이 허용하는 기능으로 각각 검증한다.
P05 모든 에이전트 간 통신·위임은 OpenSocrates 레이어를 거친다. 조사 세션이 그래프가 필요하다고 판단하면 OpenSocrates에 의뢰를 전달한다. 레이어가 작업 연결과 가이드·맥락 전달을 처리하며 결과와 협의도 같은 경로로 전달한다. 직접 우회 통신을 기본 설계로 삼지 않는다.
P06 업무와 기대 결과가 명확한 단일 의뢰 프롬프트로 동적으로 일을 맡긴다. 사전 역할 목록이나 역할별 AGENTS.md 없이 현재 과업에 맞는 세션을 구성한다. 요청 내용, 결과물과 관련 제약은 그 의뢰에 맞게 명확히 한다.
P07 앱·모델 선택과 위임 필요성을 맥락에 맞게 판단한다. OpenSocrates가 해당 컴퓨터에서 사용 가능한 앱·모델·도구·권한을 고려해 맡길 곳을 선택한다. 추정한 능력과 실제 결과의 품질을 구분해 확인한다.
P08 각 실행 세션에 관련 추론 가이드와 맥락을 전달한다. 처음 작업을 받은 세션뿐 아니라 추가 의뢰·재조립 세션에도 필요한 입력을 전달한다. 전송 성공, 세션에서의 읽기, 실제 적용과 결과 품질은 각각 구분한다.
P09 개인 가이드를 우선 선택하고 적합한 것이 없으면 기본 48개를 활용한다. 초기 사용자와 충분한 개인 경험이 쌓인 사용자의 동일 과업을 각각 시험한다. 관련 없는 개인 가이드를 억지로 쓰지 않으며, 사용자가 지정한 조건이 우선한다.
P10 맥락을 사용자·프로젝트·업무·시점에 맞게 선택하고 우선순위와 버전을 관리한다. 같은 사용자의 다른 프로젝트 경험을 무차별 적용하지 않는다. 사용자가 이전 방향으로 돌아가려 할 때 해당 흐름을 가져오며, 당시 가정과 현재 확인된 사실을 구분한다. Git 트리는 기능을 설명하는 비유이며 Git 구현 선택은 미정이다.
P11 사용자 확인이 필요한 중요한 결정을 상황별로 판단한다. 각자 사소해 보이는 결정이 합쳐져 중요한 변경이 되는 경우도 평가한다. 사용자의 확인, 위임받은 권한과 이미 확정한 선택을 보존한다. 학습된 선호가 새 권한을 만들지 않는다.
P12 실제 작업에서 조용히 배우고 관련 진행 중 작업에도 반영할 수 있다. 사용자가 '배워'라고 말하지 않아도 관련 경험을 학습 후보로 다룬다. 어떤 변경이 왜 관련되는지 내부적으로 추적하고, 개인 선호·프로젝트 제약·일회성 상황을 구분해 시험한다.
P13 백그라운드 학습 자체의 진행을 기록하고 중단 후 재개한다. 관찰한 경험, 아직 다루는 문제, 적용해 본 가이드와 미확인 결과를 구분한다. 재개 시 그사이 바뀐 맥락을 확인하며 중복 반영과 완료 오인을 시험한다. 개인적인 비공개 추론 과정을 저장하지 않는다.
P14 파일·폴더·버전 관리도 맥락에 맞게 수행한다. 기존 파일을 수정할지, 새 버전을 남길지, 관련 폴더를 정리할지를 일의 의미와 기존 방식에 맞게 판단한다. 관련 없는 파일을 임의로 변경할 권한이 생기는 것은 아니다.
P15 관련 작업 재개 시 외부 파일 변경을 발견하고 해석한다. 모든 폴더를 계속 감시하지 않는다. 이전에 남긴 허용된 상태 기록과 현재 파일을 비교한다. 비교할 이전 내용이 없으면 구체적인 차이를 안다고 주장하지 않는다. 수정자나 의도도 별도 근거 없이 단정하지 않는다.
P16 한 팀이 자율적으로 일하되 사용자가 중간 전달자나 팀 관리자가 될 필요를 줄인다. 에이전트가 필요한 업무를 발견하고 OpenSocrates를 통해 협의할 수 있다. 중요한 결정은 의뢰 대화에 전달한다. 백그라운드 동작이 중단되거나 호스트가 제한되면 그 상태를 분명히 한다.

학습에서 확정한 것과 열린 것

확정한 방향은 개인별 학습, 실제 작업을 통한 적용과 조정, 일반적인 조정의 조용한 실행, 진행 중 관련 작업에의 적용 가능성, 학습 진행 상태의 추적이다. 에이전트 협업에서 생긴 수정이나 검토 경험도 각 사용자의 OpenSocrates 안에서 다뤄볼 학습 문제가 될 수 있다. 여기서 문제를 '이슈로 다룬다'는 것은 시스템 내부의 학습 대상으로 다룬다는 뜻이며 GitHub 이슈를 생성한다는 뜻이 아니다.

RL은 현재 지향하는 피드백 순환을 가리킨다. 보상 신호, 학습 단위, 가이드 표현과 채택·보류·폐기 기준은 명세와 실험이 필요하다. 특정 강화학습 알고리즘, 모델 가중치 갱신 또는 내부 token alignment의 개선을 이미 결정하거나 입증한 것으로 쓰지 않는다. 사용자의 수정이 없었다는 사실만으로 만족이나 성공을 확정하지 않는다.

조용한 학습을 매번 승인받는 경험으로 바꾸지 않는다. 한편 잘못된 학습을 알아보고 수정할 방법, 가이드의 관련 범위와 버전을 다루는 방법은 아래 열린 결정에서 구체화한다. 이 문서는 아직 채택하지 않은 제안을 사용자 확정 요구로 승격하지 않는다.

데이터와 권한의 경계

현행 AGENTS.md와 CONTRIBUTING.md는 텔레메트리, 자격증명 수집, 원문 프롬프트·대화 기록, 스크린샷 보관, 작업 공간 콘텐츠 보관과 숨겨진 추론 수집을 금지한다. 이 계획은 그 정책을 변경하지 않는다.

현재 정책 안에서 먼저 설계할 수 있는 것은 범위가 정해진 작업·가이드 식별자, 버전, 상태, 허용된 출처 참조와 파일 상태 지문 같은 최소 기록이다. 개인 가이드는 원문 대화나 문서를 복사하는 저장소로 사용하지 않는다. 프로젝트 내용을 다른 앱에 전달하는 권한, 저장할 개인화 상태와 삭제 범위를 명세해야 한다.

구체적인 파일 차이를 비교하려면 사용 가능한 기존 버전 또는 동등한 변경 자료가 필요하다. OpenSocrates가 학습용으로 작업 공간 원본·스냅샷을 새로 보관해야 하는 제안은 현재 정책과 충돌할 수 있다. 해당 기능을 구현하기 전에 제품 소유자의 명시적 정책 결정과 별도 검토를 거친다. 그 결정 전에는 변경 감지와 상세 비교의 가능 범위를 구분하며, 전체 파일 감시나 원문 보관을 추가하지 않는다.

02 / DEVELOPMENT PLAN

시스템 구조와 데이터 흐름

상태: 2026-11-02 사용자 인터뷰를 반영한 개발 설계. 구현, 호스트 지원, 자동 학습의 효과를 입증한 문서가 아니다. 제품의 확정 방향은 제품 정의, 검증은 검증 계획, 전체 진입점은 시작 안내를 따른다. 이 문서의 계약과 상태 이름은 구현을 위한 제안이며, 실제 스키마를 추가하기 전에 검토한다.

1. 구현 경계

OpenSocrates 2.0은 한 컴퓨터에서 동작하는 프로그램과 개인별 데이터베이스를 갖는다. 기존 앱의 실제 대화 세션을 연결하고, 작업에 맞는 프롬프트·추론 가이드·맥락을 전달하며, 작업 경험을 바탕으로 개인 가이드를 발전시킨다.

초기 대상은 macOS와 Windows의 ChatGPT 데스크톱 앱과 Claude 데스크톱 앱이다. ChatGPT 앱 안의 Chat·Work·Codex를 제품 이름과 실행 표면으로 구분한다. Claude도 실제 계정의 통합 경험, Chat·Cowork·Code 표면과 로컬·클라우드 실행 위치를 기록한다. 같은 앱에 있다는 이유로 모든 표면이 같은 연결 기능을 가진다고 가정하지 않는다. Grok Bot·Cursor 등 추가 호스트와 여러 컴퓨터 사이의 동기화는 초기 범위 밖이다.

모델 제공자의 API를 직접 호출해 독립적인 에이전트 실행 환경을 만들지 않는다. 추론이 필요한 조정, 가이드 생성·재조립, 학습 판단도 지원되는 기존 앱의 대화 세션을 활용하는 방향으로 설계한다. 로컬 프로그램은 연결, 저장, 상태, 권한, 전달을 담당한다. 정확한 실행 언어, 데이터베이스 엔진, 모델 선택 기준은 아직 결정되지 않았다. SQLite 같은 내장형 트랜잭션 데이터베이스는 비교할 후보이며 확정 기술이 아니다.

기존 호스트 연결 기능을 우선 조사하고, 화면 조작이 필요하면 호스트가 제공하는 computer use 또는 검토된 오픈소스 도구를 활용한다. 특정 앱의 숨은 API, 설정 파일, 대화 데이터베이스를 임의로 수정하는 방식을 지원 계약으로 삼지 않는다. 스킬이나 연결 도구의 등록은 실제 메시지 전달·읽기·적용의 증거와 구분한다.

2. 세션과 프로그램의 책임

구성 요소 책임 구현 시 지켜야 할 경계
의뢰 대화 세션 의도·결과물·형식 상담, 업무 프롬프트 준비, 가이드·맥락 준비 요청, 중요한 결정의 사용자 확인, 진행·결과 안내 실제 조사·분석·그래프·문서 작성·결과물 통합은 실행 세션에 맡긴다.
실행 대화 세션 전달된 업무를 수행하고, 필요한 도움·질문·결과를 OpenSocrates에 전달 상대 세션에 직접 우회 전달하지 않는다. 추가 위임도 OpenSocrates에 요청한다.
호스트 어댑터 앱·표면·모델·세션의 가용성 확인, 실제 세션 생성, 메시지 전달·응답 확인, 사용자 중단 반영 실제로 제공되는 기능만 사용한다. 화면 조작과 구조화된 연결은 동일한 증거 수준이 아니다.
통신·작업 조정 의뢰·응답·협의·인계의 라우팅, 세션과 작업의 연결, 중복·대기 상태 관리 모든 관리 대상 에이전트 간 통신이 이 경로를 거치도록 한다.
가이드 선택·재조립 적용 가능한 개인 가이드 선택, 필요시 조합·재조립 의뢰, 기본 가이드 대체 경로 모든 개인 가이드를 매번 주입하지 않는다. 가이드의 개수와 전달할 문맥의 크기를 구분한다.
맥락 관리 사용자·프로젝트·업무·시점·분기·버전의 관련 정보와 우선순위 제공 과거 사실, 현재 사실, 가설, 사용자 선택과 권한을 혼동하지 않는다.
백그라운드 학습 경험에서 학습할 문제를 찾고, 개인 가이드 생성·수정·시험 적용·재검토를 진행 공통 생성 지침을 스스로 바꾸지 않는다. 사용자 확인을 매번 요구하지 않되 중요한 결정은 기존 경계를 따른다.
파일 관리 허용된 작업물의 조회·생성·수정·정리·버전 선택을 실행 세션에 연결 모든 폴더를 상시 감시하지 않는다. 메타데이터만으로 수정 의도나 작성자를 확정하지 않는다.

고정 역할표나 역할별 AGENTS.md를 만들지 않는다. 에이전트에게 전달할 한 번의 업무 프롬프트는 해당 작업의 목적, 기대 결과물, 필요한 범위와 완료 판단을 명확히 한다. 아래의 통신 계약은 프로그램이 데이터를 안전하게 연결하기 위한 것으로, 사전 정의된 인격·직책·작업 절차를 강제하는 역할 Harness가 아니다.

  1. 사용자가 의뢰 세션에서 대략적인 말을 한다. 의뢰 세션은 OpenSocrates와 함께 목적·대상·결과물 형식을 파악하고, 설명이 필요한 선택만 상담한다. 이미 정해진 선택을 다시 유도하지 않는다.
  2. 의뢰 세션은 업무와 기대 결과를 담은 프롬프트를 준비한다. 프로그램은 관련 가이드·맥락·권한을 묶어 실제 실행 세션에 전달한다. 가이드 재조립이 필요하면 그 작업도 별도 세션에 의뢰할 수 있다.
  3. 실행 세션은 실제 작업을 한다. 도움이 필요하면 OpenSocrates에 요청한다. 프로그램이 적합한 앱·모델·세션을 선택하고 가이드·맥락 준비 경로를 다시 거친다. 원래 의뢰 세션이 모든 소통을 수동으로 중계할 필요는 없다.
  4. 결과물 통합과 실질 검토가 필요하면 실행 세션에 맡긴다. 의뢰 세션은 실제 결과 참조와 확인 상태를 받아 사용자에게 전달한다. 완료 보고와 파일이 실제로 존재한다는 확인은 구분한다.
  5. 사용자 선택과 관찰 가능한 작업 경험 중 보관이 허용된 정보만 학습 후보로 연결한다. 통신 과정의 원문을 학습 로그로 남기는 것은 허용되지 않는다.

현재 전달 중인 메시지가 있다는 사실만으로 새 가이드가 모델에 들어갔다고 주장하지 않는다. 호스트 응답 확인, 가이드의 실제 전달, 읽기나 적용에 관한 증거, 결과물 품질은 각각 기록 가능한 수준에서 구분한다.

4. 가이드의 생성·선택·재조립

가이드의 세 종류

종류 변화 주체 수명과 사용
기본 48개 추론 가이드 OpenSocrates의 정식 콘텐츠·버전 관리 설치 직후 사용하며, 해당 작업에 적합한 개인 가이드가 없을 때 사용한다.
공통 가이드 생성 지침 OpenSocrates 버전업 모든 사용자의 공통 기반이다. 개인 학습이 직접 수정하지 않는다.
개인별 생성 가이드 해당 사용자의 학습 로직 실제 경험에 맞게 발전한다. 고정된 가이드 개수 제한은 두지 않으며, 업무마다 관련 부분을 선택한다.

개인 가이드의 생성 버전은 생성 지침 버전, 참조한 가이드 버전, 적용 범위와 허용된 근거 참조를 연결한다. 제품 업데이트가 기존 개인 가이드를 근거 없이 덮어쓰거나 전부 재생성하지 않도록 이행 규칙을 설계한다. 기본 48개와 개인 가이드의 저장 위치·소유권도 구분한다. 개인 가이드는 사용자의 런타임 데이터이며 저장소의 정본 콘텐츠나 생성 지침을 덮어쓰지 않는다.

선택 경로

  1. 현재 사용자 요청의 목적, 프로젝트, 업무, 대상, 시점, 권한에 맞는 개인 가이드를 찾는다.
  2. 적용 가능한 개인 가이드가 있으면 이를 우선 사용한다. 여러 가이드가 필요하면 선택·조합·재조립한다. 단순 이어붙이기만을 요구하지 않는다.
  3. 적합한 개인 가이드가 없으면 기본 48개에서 적용 가능한 가이드를 사용한다. 모든 기본 가이드가 부적합하면 방법을 억지로 적용하지 않고 일반 작업을 계속한다.
  4. 개인 가이드의 일부만 맞는 경우 기본 가이드의 보완 부분까지 조합할지, 적합성이 부족하다고 보고 기본 경로로 갈지는 별도 선택 정책에서 명료화한다. 지금 두 경로 중 하나를 사용자 결정으로 가장하지 않는다.
  5. 재조립 결과를 이번 작업에서만 사용할지 재사용 가능한 개인 가이드로 남길지는 학습 로직이 맥락과 경험을 보고 판단한다. 저장이 곧 효과 검증이나 영구 채택을 뜻하지 않는다.

가이드가 늘어나도 모두 프롬프트에 넣지 않는다. 관련성 검색, 적용 범위, 전달 예산을 구분한다. 가이드 수를 임의의 고정 상한으로 자르는 대신, 저장 용량·검색 지연·중복·폐기 상태 관리의 한계를 실제 측정해 정책으로 공개한다. 검색에 외부 임베딩 API가 필요하다고 전제하지 않는다.

5. 개인 데이터와 통신 계약 제안

실제 정본 스키마는 schemas/source/, 프로그램은 src/opensocrates/에 구현하고 생성물은 기존 생성 절차를 따른다. 다음은 데이터를 식별하고 연결하기 위한 최소 계약의 제안이다. 모든 메시지 본문을 데이터베이스에 영구 저장하라는 뜻이 아니다.

계약 제안 필드 의미
HostEndpoint endpoint ID, app/version, OS, surface, local/cloud location, available operations, model-selection capability, trust state, probe evidence 앱 이름만으로 세션 생성·주입·응답 수신 가능성을 가정하지 않는다.
TaskRecord task ID, project/branch IDs, intake session ref, execution session refs, goal summary, artifact refs, authorized scope ref, status, revision 실제 작업과 대화 세션을 별개로 식별한다. 한 작업이 여러 세션을 사용할 수 있다.
DispatchEnvelope message ID, task ID, sender/destination, parent message ID, retry identity, guide/context version refs, authority ref, expiry 업무 프롬프트·가이드·맥락의 전달과 결과를 연결한다. 민감한 본문은 필요한 호스트 전달 시에만 취급한다.
ContextRecord context ID, scope, branch/version/parent refs, source ref, timestamp, freshness, accepted/proposed/observed status, authority 최신이라는 이유만으로 사용자의 의도나 권한을 바꾸지 않는다. 출처가 바뀌면 영향을 받는 사실만 재검토한다.
GuideVersion guide ID/version, baseline/personal kind, scope, generator version, input guide refs, permitted evidence refs, hypothesis/active/retired status 개인 가이드와 공통 지침의 소유권을 분리하고, 작업에 실제 적용된 버전을 추적한다.
LearningCheckpoint learning ID, question summary, input event IDs, public progress state, pending application refs, versions, revalidation need, revision 숨은 추론이나 원문 대화를 저장하지 않고 학습 자체의 중단·재개 지점을 남긴다.
ArtifactRecord artifact ID, allowed location ref, type, project/branch/task refs, fingerprint, observed timestamp, existing version ref 파일 이동과 새 생성의 판별 가능성을 구분하고, 메타데이터가 수정 의도를 증명한다고 보지 않는다.
AuthorityRecord authority ID, user/host origin, scope, allowed effects, limits, expiry/revocation, pending-confirmation state 에이전트 출력과 과거 기록은 새로운 사용자 권한이 아니다.

서로 다른 앱의 세션 ID는 앱/계정/표면과 함께 해석한다. 로컬 기록에는 가능한 범위에서 불필요한 계정 식별정보를 넣지 않는다. 수신자 검증 없는 전역 브로드캐스트와 모든 프로젝트를 포함하는 기본 문맥은 만들지 않는다.

6. 통신·동시성·복구

프로그램은 전송 요청, 실제 전송 시도, 호스트 접수, 응답 관찰, 작업물 확인을 별개 상태로 관리한다. 호스트가 접수 영수증을 제공하지 않으면 상태는 sent_unconfirmed처럼 미확인으로 남긴다. 화면에 버튼을 눌렀다는 사실을 접수나 완료로 승격하지 않는다.

로컬 DB의 작업·가이드·맥락 수정은 버전 전제조건과 트랜잭션을 사용하도록 설계한다. 두 세션이 같은 가이드를 갱신하면 마지막 저장으로 덮지 않고 두 제안과 근거를 보존해 충돌을 처리한다. 전송 대기 항목과 상태 변경을 연결하는 outbox는 구현 후보이다. 앱으로의 실제 효과까지 데이터베이스 트랜잭션으로 원자화할 수 있다고 가정하지 않는다.

재시도 ID는 OpenSocrates 내부 중복을 줄일 수 있지만 외부 앱에서의 정확히 한 번 실행을 보장하지 않는다. 전송 후 응답 전에 중단되면 먼저 기존 세션·결과를 확인한다. 확인할 수 없는 외부 효과는 맹목적으로 재실행하지 않고 effect_unknown으로 다룬다. 사용자 확인 대기와 호스트 권한 대기는 작업 실패와 구분한다.

여러 세션이 하나의 화면을 조작하는 경우 앱·화면 자원에 대한 조정을 설계하고, 취소나 사용자 입력이 도착하면 재관찰한다. 로컬 앱 종료·기기 잠자기·오프라인·업데이트를 학습이나 전달의 영구 실패로 오인하지 않는다. 실행 불가능 상태에서는 대기와 남은 일을 기록한다. 여러 기기 간 공유나 전역 클라우드 서비스의 존재를 이 복구 설계에 전제하지 않는다.

7. 백그라운드 학습과 진행 중 적용

구조도 원문 보기
flowchart TD
    signal["허용된 선택·수정·협업·변경 관찰"]
    assess["출처와 관련 맥락에서 해석"]
    issue["개인의 학습 문제"]

    observe --> assess
    assess -.-> checkpoint
    propose -.-> checkpoint
    apply -.-> checkpoint
    checkpoint --> resume --> assess

학습의 상태 예시는 observed → interpreting → candidate → pending_application → observing_outcome → revised/retained/retired이다. 중단과 취소는 별도 상태이며, 재개 시 마지막으로 확인한 단계와 미완료 효과를 복구한다. 이 목록은 실제 RL 알고리즘이나 검증된 채택 규칙이 아니다. 무수정, 침묵, 에이전트 간 합의만으로 성공을 확정하지 않는다.

진행 중인 관련 작업에 반영하는 기능은 목표에 포함한다. 다만 로컬 DB의 새 버전을 쓰는 것과 이미 실행 중인 모델의 문맥을 바꾸는 것은 다르다. 어댑터가 지원하는 다음 메시지·도구 호출·세션 이어가기 등 실제 진입점을 찾아 전달하고, 작업에 수신된 버전을 추적한다. 전달할 진입점이 없으면 pending_application으로 남기며 실시간 적용을 주장하지 않는다. 버전 고정만으로 진행 중 반영 요구를 제거하지 않는다.

반영 전에 해당 업무의 대상·목적·현재 사용자 선택과의 적합성을 판단한다. 일반 선호와 프로젝트 한정 수정, 외부 환경 변화, 다른 사람의 수정, 표현상의 변화, 실제 오류 교정을 구별해야 한다. 불명확한 신호는 맥락에 붙은 미확인 가설로 다룰 수 있으며, 강한 개인 선호로 승격하지 않는다. 구체적 보상, 채택·폐기, 회귀 탐지, 연산 예산은 검증 계획의 실험에서 결정할 항목이다.

8. 맥락 분기와 파일 관리

맥락 트리는 사용자가 쉽게 이전 방향으로 돌아가거나 관점을 바꾸게 하는 개념이다. 구현 후보는 출처와 부모 관계가 있는 버전 그래프이다. 실제 Git 사용이나 문맥 전환 시 디스크 파일을 자동으로 checkout하는 기능은 확정하지 않았다.

현재 사용자 요청과 유효한 권한을 보존한 상태에서, 업무·프로젝트·대상·시점·관련성에 따라 사용할 맥락을 선택한다. 과거 관점으로 돌아갔다고 현재 권한을 복원하거나 만료된 사실을 현재 사실로 취급하지 않는다. 서로 충돌하는 가격·마감·목표는 단순한 텍스트 병합 성공으로 해결하지 않는다. 우선순위 판단의 구체적 정책과 학습 가능 범위는 정본 계약에서 다룬다.

파일 관리자는 실행 세션의 파일 작업을 프로젝트·맥락·버전 참조와 연결한다. 기존 파일 수정, 새 버전 생성, 기존 폴더 정리를 일의 맥락에 맞게 판단한다. 모든 변경을 새 파일로 만드는 고정 규칙이나 모든 덮어쓰기에 확인을 요구하는 규칙을 사용자 결정으로 추가하지 않는다. 중요한 결정은 사용자 확인 경계를 따른다.

다음 관련 작업에서 기록된 상태와 실제 파일을 대조한다. 수정 시각은 변경 신호일 뿐 내용 차이를 증명하지 않으며, 동일한 해시 방식으로 계산한 서로 다른 지문은 바이트가 다르다는 근거가 된다. 구체적인 차이를 분석하려면 읽을 수 있는 이전 버전이나 동등한 이력이 필요하다. 없으면 변경 사실만 남기고 차이·수정자·이유를 만들어내지 않는다. 파일 이동, 이름 변경, 자동 서식과 실제 내용 수정도 구분해 평가한다.

9. 보관·권한·신뢰 경계

현재 AGENTS.md, CONTRIBUTING.md, SECURITY.md를 그대로 준수한다. 원문 프롬프트·대화, 스크린샷, 작업 공간 내용, 자격증명, 숨은 추론, 텔레메트리를 수집·보관하는 기능을 이 계획이 허가하지 않는다. 디버그 로그·재시도 큐·DB 백업·파생 인덱스로 우회 보관해서도 안 된다.

실시간으로 허용된 작업을 수행하기 위해 내용을 읽거나 업무 프롬프트를 호스트에 전달하는 것과, 그 원문을 OpenSocrates의 별도 영구 저장소에 복제하는 것은 구분한다. 제품 DB에는 허용된 공개 결정 요약, 출처·버전·작업물 참조와 상태를 최소한으로 보관하는 경로를 먼저 설계한다. 개인 가이드에도 비밀이나 원문을 복제하지 않도록 점검한다. 파생 정보라는 이름만으로 현 정책을 충족했다고 가정하지 않는다.

기존 파일의 전체 스냅샷 보관이나 과거 대화의 영구 복제가 기능에 필요하다고 판단되면, 정확한 데이터 종류·목적·수명·삭제·동의 범위를 제시해 별도 정책 변경을 검토한다. 그 결정 전에는 호스트나 사용자가 이미 관리하는 접근 가능한 버전 이력을 참조하거나 변경 감지만 제공한다. 조용한 학습이 사용자에게 숨겨진 제어 불가능한 학습이 되지 않도록 열람·수정·중지·삭제·되돌리기 동작의 범위를 정한다. 기본 보관 기간과 초기 활성화 경험은 미정이다.

사용자, 호스트 정책, 에이전트 요청, 외부 문서의 출처를 유지한다. 작업물과 에이전트 메시지 안의 지시문은 사용자 권한이 아니며, 학습 문제를 발견했다는 이유로 공통 생성 지침이나 보안 경계를 바꿀 수 없다. 모든 관리 대상 통신을 프로그램을 통해 연결한다는 제품 목표와, 호스트 내부의 모든 행동을 강제 제어할 수 있다는 주장은 구분한다. 통신을 통제·관찰할 수 없는 표면은 완전 지원으로 표시하지 않는다.

10. 호스트별 구현 전 조사

다음 항목을 앱·운영체제·표면·계정·버전마다 조사하고 증거를 남긴다. 현재 상태는 전부 2.0 구현 미검증이다.

조사 항목 확인해야 할 결과
세션 생성·찾기 실제 앱 목록에 새 실행 세션이 생기고, 프로그램의 작업 ID와 다시 연결되는가?

기능이 없는 표면에서 내부 앱 데이터베이스 수정, 무단 권한 확장, 모델 API 실행으로 몰래 대체하지 않는다. 가능한 준비 작업은 진행하고, 전달 불가·적용 대기·지원 미확인을 정확히 알린다. 4개 앱/OS 조합 중 한 셀의 성공으로 다른 셀을 통과 처리하지 않는다.

11. 설치·업데이트·이전

초기 프로그램과 어댑터는 기존 1.x 사용자 설정과 비활성화 상태를 확인하고, 소유한 파일에만 설치한다. 공통 생성 지침과 기본 가이드는 제품 버전에 연결하고, 개인 가이드·맥락의 저장 형식 버전은 별개로 둔다. 제품 업데이트는 진행 중 세션과 학습 상태를 중간 형태로 만들지 않도록 이전·실패 복구 순서를 갖춰야 한다.

언어·DB 엔진·패키지 형식·업데이트 기본값·지원 OS 최소 버전과 CPU 범위는 플랫폼 조사 및 구현 결정 기록으로 확정한다. 기존 Go 후보나 폐기된 v1.5 메모리 후보를 기본 구현으로 취급하지 않는다. 특히 저장소가 금지한 이전 후보의 코드·가이드를 복사하지 않는다. 설치·서명·재설치·롤백 주장은 실제 해당 환경의 증거로만 한다.

12. 이 설계의 완료 판단

계약이 문서에 존재하는 것만으로 동작을 인정하지 않는다. 검증 계획의 실제 호스트·OS별 전달, 분리 세션 실행, 가이드 선택·재조립, 진행 중 반영, 학습 재개, 파일 비교, 권한·삭제·실패 사례를 통과해야 해당 기능을 주장할 수 있다. 작업 품질 향상은 전달 성공과 별도로 평가한다. 정책·호스트 기능·학습 신호의 미결정은 각각 해당 기능에 연결하고, 무관한 조사나 문서 작성을 막는 전역 조건으로 넓히지 않는다.

개발 로드맵과 인계

상태: 사용자와 정한 방향을 구현 가능한 작업으로 옮긴 계획. 기능 구현, 실사용 효과 또는 네 가지 데스크톱 환경의 지원을 주장하지 않는다. 제품 요구사항, 시스템 구조, 검증 계획을 함께 읽는다. 범위와 사용자 선택은 이 문서 세트가 이전 2.0 계획보다 우선하며, 릴리스·개인정보·보안 및 저장소 운영 규칙은 변경하지 않는다.

착수 기준과 우선순위

  1. 사용자 요청과 대화에서 확인한 범위는 ChatGPT 데스크톱(Chat·Work·Codex)과 Claude 데스크톱을 macOS와 Windows에서 사용하는 것이다. 네 앱·OS 조합과 각 모드를 독립적으로 조사·검증한다. 특정 모드에 컴퓨터 사용, 스킬, 메시지 전송 또는 세션 생성이 제공된다고 미리 가정하지 않는다.
  2. 한 컴퓨터의 개인별 프로그램을 기본 범위로 한다. 다중 컴퓨터 동기화는 추후 업데이트다. Grok Bot과 Cursor는 첫 버전 대상에서 제외하고 추후 재검토한다. 기존 1.x 사용자의 지원 프로필을 예고 없이 제거하라는 뜻은 아니다.
  3. 기존 앱과 그 대화 세션을 활용한다. 에이전트 실행을 위한 별도 모델 제공자 API와 이를 통한 독자적 AI 앱은 현 범위가 아니다. 공식 연결·호스트 기능을 우선 조사하고 필요할 때 기존 컴퓨터 사용 도구나 오픈소스를 검토한다. 가능한 경로가 없으면 그 조합은 미지원·미검증으로 표시한다.
  4. 사용자가 의뢰한 대화는 요구 정리·상담·업무 준비·조율과 보고를 맡고 실제 산출 업무는 새 작업 세션에서 수행한다. 모든 에이전트 간 메시지는 OpenSocrates 통신 계층을 거친다. 각 세션에 업무별 프롬프트와 적합한 맥락·추론 가이드를 전달한다. 이 동작을 제공하지 못하는 호스트에서 달성했다고 표시하지 않는다.
  5. 기존 48개 가이드는 설치 초기와 적합한 개인 가이드가 없을 때 사용하는 기반이다. 개인 가이드는 개수 제한 없이 생성·조정하고, 적합한 경우 결합하거나 재조립한다. 공통 생성 지침은 OpenSocrates 버전업으로 바뀌고 사용자별 학습이 공통 지침을 바꾸지 않는다. 필요한 경우 가이드 재조립을 별도 에이전트에 맡길 수 있다.
  6. 각 사용자별 백그라운드 학습은 명시적 학습 명령 없이 경험에서 다룰 문제를 찾고, 실제 작업과 진행 중인 관련 작업에 새 방향을 적용하며 발전한다. 중단 전후의 학습 상태를 추적한다. 특정 강화학습 알고리즘, 모델 가중치 변경, 토큰 정렬의 효과는 확정된 사실이 아니다.

첫 번째 끝까지 이어지는 사례

  1. 사용자가 ChatGPT 또는 Claude 데스크톱의 의뢰 대화에서 부정확하거나 불완전한 말로 보고서를 요청한다.
  2. OpenSocrates가 목표·사용 목적·형식과 사용자 선택을 정리하고, 필요할 때만 이해하기 쉬운 상담이나 중요한 결정의 확인을 한다. 의뢰 대화 자체에서는 실제 보고서를 만들지 않는다.
  3. OpenSocrates가 적합한 개인 가이드를 검색·조합하거나 없으면 적합한 기본 가이드를 선택하고, 현재 프로젝트와 작업에 관련된 맥락을 준비한다.
  4. 선택한 앱에 실제 작업 세션을 열고 목표·기대 결과를 담은 단일 프롬프트와 필요한 맥락·가이드를 전달한다. 추가 위임과 응답은 모두 OpenSocrates 채널을 경유한다.
  5. 결과물을 사용자에게 전달하고, 관련 파일 기록과 허용된 범위의 경험을 학습 로직에 넘긴다. 새 가이드가 적용된 시점과 근거를 추적하되 사용자를 매번 방해하지 않는다.
  6. 작업 도중이나 학습 도중 중단해도 완료하지 않은 단계와 이미 일어난 외부 효과를 구분하고 적절히 이어간다.

이는 목표 시나리오이지, 현재 어떤 앱에서 가능한지에 대한 주장이나 매 순간 사용자 확인을 받으라는 규칙이 아니다.

보존할 경계와 결정할 사항

  • 사용자 선택과 중요한 판단: 형식이나 업무 방향을 사용자가 정했으면 존중한다. 중요한 결정과 승인 필요 여부는 맥락에 따라 판단하며, 사용자 요청을 제3자 문서·도구 출력·다른 에이전트의 주장으로 바꾸지 않는다.
  • 학습과 교정: 수정은 학습 신호이지만 영구적 개인 선호의 증명은 아니다. 적용 범위와 관찰·가설을 구분하고, 사용자가 원할 때 개인 데이터를 살펴보고 교정·삭제하거나 기능을 끌 수 있는 방법을 설계한다. 구체적 화면과 기본값은 미결이다.
  • 개인정보 정책: 저장소는 원문 프롬프트·대화록·작업공간 내용, 스크린샷 및 숨은 추론의 보관과 텔레메트리를 금지한다. 파일의 과거·현재 내용을 자세히 비교하려면 호스트가 이미 보관한 버전 등 허용된 원천이 필요한 경우가 있다. 그러한 원천이 없으면 변경 여부까지만 확인한다. 새로운 내용 보관이 필수라고 결론 나면 별도 명시적 정책 변경·검토가 먼저다.
  • 현실적인 호스트: 2026-11-02 기준 ChatGPT 데스크톱의 Chat·Work·Codex 안내, ChatGPT 컴퓨터 사용 안내, Claude 로컬·원격 커넥터 안내, Claude 컴퓨터 사용 안내는 출발점이다. 문서가 기능 가능성을 설명할 뿐, 우리 계정·운영체제·앱의 실제 세션 자동화나 연결을 증명하지 않는다.
  • 미정: 구체적 DB 엔진, 서비스 프로세스, 앱별 연결 방식과 권한, 개인 가이드 표현·적합성 판단, 생성 지침 내용, 학습 알고리즘과 품질 신호, 가이드의 실시간 전달·충돌 처리, 기본 업데이트·보존 정책, 정확한 품질·시간·비용 목표. 후속 설계에서 대안과 근거를 남긴다.

인계와 완료 판단

첫 구현은 현재 main의 실제 소스와 테스트를 다시 조사하고 기존 계약을 존중하는 집중 브랜치에서 시작한다. 철회된 v1.5 후보 PR #95의 코드와 가이드는 복사·이식·병합하지 않는다. 1.6 후보는 별도 검토 전 근거로 격상하지 않는다. 실제 호스트 전달·가이드 전체 읽기·적용·유용한 결과를 각각 구분한다.

최종 개발계획서가 있다고 해서 제품을 완성하거나 릴리스한 것이 아니다. 실제 구현과 각 호스트 셀의 검증·독립 평가·명시적 정책 결정이 끝나야 해당 동작을 주장할 수 있다.

검증과 평가

상태: 2026-11-02 개발 계획. 이 문서는 실행 결과, 지원 인증, 성능 개선의 증거가 아니다. 제품 요구사항과 시스템 설계를 실제로 확인할 수 있는 사례로 바꾼다.

1. 검증할 제품과 판단 기준

첫 범위는 한 사용자의 한 컴퓨터에서 실행하는 OpenSocrates 프로그램과 가벼운 데이터베이스, ChatGPT 데스크톱 앱 및 Claude 데스크톱 앱의 연결이다. macOS와 Windows를 각각 확인한다. ChatGPT의 Chat·Work·Codex, Claude의 일반/통합 대화·Cowork·데스크톱 Code는 실제로 노출되는 기능과 경계에 따라 별도로 기록한다. 앱 안의 Codex를 다른 데스크톱 제품으로 취급하지 않는다. 독립 CLI·웹·모바일, Cursor, Grok Bot, 여러 컴퓨터 간 동기화는 첫 출시의 지원 근거가 아니다.

사용자가 요청한 대화는 상담과 작업 준비·조율을 수행한다. 실제 조사·분석·제작·결과물 통합은 새 앱 대화 세션에서 이루어진다. 모든 에이전트 간 의뢰·질문·응답·인계는 OpenSocrates 레이어를 거쳐야 한다. 그 레이어가 각 업무에 맞는 프롬프트, 맥락, 추론 가이드를 전달한다. 모델 제공자 API를 직접 호출하는 구현을 이 제품의 실행 경로로 대신 시험하지 않는다.

제품의 효과를 평가할 때는 관찰 가능한 사용자 결과를 먼저 정한다. 의도 이해, 결과물의 품질·사용성, 재작업, 불필요한 질문과 사용자 개입, 맥락 전환, 권한 준수, 소요 시간·비용을 평가한다. 특정 파일 구조나 알고리즘이 있다는 사실은 좋은 사용자 경험의 충분조건이 아니다. ‘token alignment’, MoE, RL, Git 트리는 구상의 설명 또는 설계 가설이며, 내부 토큰이나 숨은 추론의 변화를 관측했다고 주장하지 않는다.

기능별로 등록·활성화, 세션 생성, 전달된 프롬프트/가이드/맥락의 식별, 에이전트의 수신 또는 읽기, 실제 업무 결과를 구별한다. 에이전트의 자기 보고만으로 읽기나 적용을 독립 검증했다고 쓰지 않는다. 개인정보를 남기지 않는 수신 식별자를 호스트가 제공하지 않으면 해당 단계는 미확인으로 두고 최종 결과의 관찰은 별도로 보고한다. 제공되지 않는 영수증을 찾는 일을 제품 완료의 추가 조건으로 만들지 않는다.

3. 시험 준비와 자료 경계

시험 전에 사례 버전, 합성 입력, 기대 결과, 모델·노력 수준·도구 접근, 앱·운영체제 버전, 사용자 권한, 반복 수·순서, 시간 제한, 실패와 중도 중단의 처리, 평가자를 고정한다. 실제 입력이나 사용자 파일을 보관하지 않아도 재현 가능한 시험은 공개 가능한 합성 자료와 버전으로 만든다.

실사용 평가는 사용자가 범위를 알고 동의한 과업에서 진행한다. 사용자가 원래 할 일을 수행하는 동안 최소한의 결과 판정과 부담을 측정하며, 매 수정마다 이유를 설명하거나 장기간 수동 기록을 작성하도록 제품 사용의 전제로 요구하지 않는다. 별도 연구용 인터뷰나 평정은 선택적인 평가 절차로 구분한다. 평정을 얻지 못한 결과는 미평가로 남긴다.

AGENTS.md와 CONTRIBUTING.md의 현재 정책을 따른다. 원문 프롬프트·대화록, 작업 공간 내용의 복사본, 자격 증명, 스크린샷, 숨은 추론을 수집·보관하지 않고 텔레메트리를 추가하지 않는다. 사용자 소유의 최종 결과물은 원래 전달 위치에 두며 평가 저장소에 복제하지 않는다. 공개 가능한 합성 자료, 내용 없는 상태·버전·결과 수치와 허용된 참조만 시험 기록에 남긴다. 가이드나 요약에도 원문·비밀이 재현되지 않는지 확인한다.

파일 이전 내용의 상시 보관이나 비공개 실제 프롬프트 재현이 필요한 평가안은 이 문서만으로 허용되지 않는다. 먼저 정책 변경을 별도로 검토하고 명시적으로 결정하거나, 기존에 허용된 원본 버전 참조와 합성 자료를 사용하도록 시험을 바꾼다. 데이터가 없다는 이유로 실제 변화의 원인이나 의도를 꾸며내지 않는다.

4. 비교 평가 설계

비교 조건 확인할 질문
A: 같은 호스트, OpenSocrates 없음 일반적인 앱 사용의 결과와 부담은 어떠한가?
B: 정확히 고정한 v1.5.3 기존 48개 가이드 배포·선택 경로와 비교해 무엇이 달라지는가?
C: 2.0, 기본 가이드와 프로그램 연결 세션 분리·통신·맥락 전달 자체의 영향은 무엇인가?
D: 2.0, 개인 가이드 선택·재조립 관련 개인 가이드가 추가로 기여하는가?
E: 2.0, 경험으로 가이드를 생성·조정 미리 작성한 개인 가이드와 달리 실제 학습 과정이 다음 업무를 개선하는가?

모든 비교를 무조건 한 번에 실행하지 않는다. 주장에 필요한 대조 조건을 선택한다. 예를 들어 위임의 효과는 동일한 자료·도구·예산에서 하나의 실행 세션과 OpenSocrates를 통한 동적 위임을 비교한다. 가이드의 효과는 프로그램과 실행 조건을 고정하고 관련 가이드만 바꾼다. 사실 메모만 전달하는 조건과 비교하면 개인 사실 회상과 사고 가이드의 기여를 더 잘 구분할 수 있다. 실험마다 변경한 요인과 함께 변경된 요인을 명시한다.

v1.5.3은 릴리스 기준선 목록에 연결된 정확한 배포본과 해당 호스트의 실제 동작을 확인한다. 특정 호스트의 B와 비교하려면 그 호스트의 B 조건이 필요하다. 다른 운영체제나 앱의 기준선 측정이 끝나지 않았다는 이유로 이미 근거가 있는 개별 호스트의 정적 비교·기능 관찰·별도 비교를 막지 않는다. 해당 표면에서 v1.5.3이 지원되지 않으면 B를 ‘적용 불가’로 적고 A 등 적절한 대조군을 쓴다.

학습을 평가할 때는 가이드 생성에 쓴 경험과 평가 업무를 구분한다. 동일 프로젝트의 후속 업무, 다른 프로젝트의 유사 업무, 관련 없는 업무, 시간이 지나 선호나 사실이 바뀐 업무를 포함한다. 후보 조건 사이의 사용자 학습·피로·순서 효과를 기록하며, 각 조건의 개인 데이터베이스와 가이드 상태를 격리한다. 현재 상태를 다른 조건에 흘려보내고 독립 비교라고 하지 않는다.

모델·도구·접근 권한·가용 기능을 최대한 맞춘다. 앱 간 비교에서 이를 맞출 수 없으면 차이를 보고하고 제품이나 모델 하나의 인과 효과로 해석하지 않는다. 모든 시도, 재시도, 시간 초과, 실패, 동률과 중단을 포함한다. 표본 수와 반복 단위를 공개하며, 하나의 출력에 대한 여러 평가를 독립적인 여러 업무로 세지 않는다.

GUIDE-06 다수의 개인 가이드가 누적됨 48개 등의 고정 개수로 잘라내지 않고 적합한 가이드를 찾는다. 크기 증가에 따른 검색·재조립 지연, 중복·상충 가이드 처리와 보관 제약을 측정한다. 무제한 저장 공간을 약속하지 않는다.

LEARN-01 사용자가 ‘배워’라고 말하지 않고 수정함 허용된 경험에서 학습할 문제를 찾고 관련 개인 가이드에 반영할 수 있다. 학습할 문제는 사용자별 내부 항목이며 GitHub 이슈를 생성하지 않는다.

6. 품질·학습·부담 측정

평가자는 가능하면 비교 조건을 모른 채 결과물을 먼저 판단한다. 숫자·사실·논리, 의도와 독자 적합성, 요청한 형식의 사용성, 필요한 수정과 추가 지시를 평가한다. 파일 열기·수정 가능 여부, 그래프의 단위·축·원자료와의 일치도 포함한다. 설명이 매끄럽다는 이유로 잘못된 결과를 통과시키지 않는다. 사용자 평가와 분야별 독립 평가를 구분하고 이견·동률을 보존한다.

학습은 과거 업무의 수정량뿐 아니라 이후 평가 업무에서의 정확성·적합성, 불필요한 일반화, 이전에 잘하던 업무의 회귀, 관련 없는 프로젝트로의 잘못된 전이로 평가한다. 무응답·미사용·수정 없음은 만족과 동치가 아니다. 학습 신호의 확실성, 확인하지 못한 원인, 개입된 모델·도구·가이드 변경을 기록하고, 관측만으로 특정 가이드의 인과 기여를 확정하지 않는다.

사용자 부담은 설명·정정의 반복, 필요한 상담과 불필요한 질문, 중요한 결정의 누락, 사용자가 직접 에이전트 사이를 중계한 횟수·시간으로 본다. 평소 조정은 조용히 하되 요청 시 현재 적용 상태와 허용된 변경 근거를 확인하고 고칠 수 있는지 시험한다.

시간과 비용은 첫 응답, 사용자 결정에 필요한 준비, 사용 가능한 최종 결과까지의 경과 시간, 가이드 검색·조립, 통신·화면 조작·모델 대기, 백그라운드 학습, 재시도·복구를 나눈다. 사용자 전면 작업과 백그라운드 작업의 자원 경쟁을 포함한다. 호스트가 제공한 실제 사용량과 추정치를 구분하고 미제공 수치는 미확인으로 둔다. 병렬 구간의 시간을 중복 합산하거나 캐시 토큰을 총 입력에 다시 더하지 않는다.

성능·품질 목표치는 제품 책임자와 평가 담당자가 기준선, 사용 목적, 허용 가능한 실패·사용자 부담을 보고 후보 결과를 보기 전에 정한다. 근거 없는 비율·횟수·시간을 보편적 합격선으로 쓰지 않는다. 권한 침해·비밀 유출·사용자 의사 변경 같은 실패는 해당 기능의 배포 판단을 다시 열며 평균 점수로 상쇄하지 않는다. 한 비교가 실패해도 원인을 가리지 않고 전체 제품의 불가능성을 단정하거나 다른 독립 작업을 중단시키지 않는다.
