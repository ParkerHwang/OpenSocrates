# S087 · 성장·첫 사용·재사용 최소 지표 정의서

문서 상태: **통합 전 초안**. 2026-10-15 공개 자료를 읽어 정의와 수동 기록 양식을 작성했다. 제품 코드, 설치, 계정, 기존 자동화는 변경하지 않았다. 통합 후보에 대한 최종 검사·현장 사용 조사는 수행하지 않았다.

이 문서는 운영자가 같은 단위로 관찰을 기록하도록 돕는다. [#113](https://github.com/ParkerHwang/OpenSocrates/issues/113)의 주된 홍보 지표인 유기적 Stars를 유지하되, 노출·다운로드·설치·첫 사용·재사용·독립 추천을 각각 별도로 기록한다. Stars나 다운로드 증가로 채택, 효과 또는 홍보의 인과적 성과를 판단하지 않는다.

## 1. 범위와 공통 시각

| 항목 | 확정 내용 |
| --- | --- |

| 제품 사실 기준 | [v1.5.2 영문](https://github.com/ParkerHwang/OpenSocrates/blob/227a528996d93c423851db1d663f9572be534e59/docs/v1.5.2.md) · [국문](https://github.com/ParkerHwang/OpenSocrates/blob/227a528996d93c423851db1d663f9572be534e59/docs/v1.5.2.ko.md) |

| 시각 원본 | 프로그램의 `control/run.json`; 채팅 생성 시각으로 시작·종료를 옮기지 않는다 |

| 이후 관찰 창 | **정의 제안**: 첫 사용 시각 t0 이후 168시간. 실제 조회·연락·일정 생성은 별도 승인된 작업에서만 한다 |

기록 시각은 UTC ISO 8601로 저장하고 필요하면 서울 시각을 함께 적는다. 구간은 기본적으로 시작 포함·종료 제외 `[start, end)`다. 단, npm API의 날짜 `start`·`end`는 양 끝 날짜를 포함하므로 원래 날짜를 보존하고, 비교가 필요하면 UTC 다음 날 00:00을 배타적 종료로 변환한다.

다음 세 가지를 항상 분리한다.

- **측정 대상 기간** `window_start/end`: 이벤트가 속하는 기간 또는 누적 시작부터 관찰 시점까지의 범위.
- **조회 시각** `observed_at`: 실제로 응답을 읽은 시점. 응답의 HTTP Date가 있으면 함께 적는다.
- **자료 최신성** `freshness/status`: 지연·미성숙·접근 제한·미응답 여부. 조회가 오늘이라고 자료 기간도 오늘이 되지는 않는다.

## 3. 중복 제거·미응답·계산 규칙

### 3.1 최소 수동 연결

1. 보관 범위는 비민감 요약, 관찰 시각, 공개 출처 URL, 상태 범주, 필요할 때만 임의 보고자 토큰이다. 이름·이메일·핸들 목록·쿠키·기기 식별자·계정 해시·원문 프롬프트·대화·스크린샷은 저장하지 않는다. 토큰과 실명/계정을 연결하는 대응표를 만들지 않는다.
2. 같은 공개 보고의 수정·번역·인용·재게시를 같은 `source_event`로 연결하고, 원문 출처 기준으로 한 건만 센다. 여러 앱에서 같은 과제를 한 보고는 과제 이벤트 한 건, 호스트 관찰은 별도 하위 상태다.
3. 동일 공개 작성자가 기존 보고에 직접 후속 보고를 남겼거나, 자발적으로 같은 보고임을 확인한 경우에만 같은 임의 토큰으로 연결한다. 다른 플랫폼 계정의 닉네임·문체·사진으로 동일인을 추정하지 않는다. 연락하거나 신원 자료를 추가 수집하지 않는다.
4. 동일인 연결이 불명인 보고는 `identity_unresolved`로 두고 **사람 단위 U01/U02 비율의 분자·분모에서 제외**한다. 원장에는 연결 불명 보고 건수를 따로 남긴다. 이를 0명 또는 서로 다른 신규 사용자로 자동 처리하지 않는다. 공개 자료만으로 전 세계 고유 사용자를 산출하지 않는다.
5. 동일인 첫 사용은 명시적으로 확인된 가장 이른 t0 하나다. 날짜만 알면 해당 UTC 일자의 범위로 보관하며 정확한 시각은 null이다. 첫 사용 시각 구간이 작업 창 경계를 가로지르면 W2h 발생 분류는 unknown이다.
6. 사용자 한 명이 여러 과제를 재사용해도 U02의 사람 수는 한 명이다. 과제 건수는 별도 열에 쓸 수 있지만 사람 수와 더하지 않는다. 첫 과제의 두 번째 턴은 별도 과제가 아니다. 이후 버전/호스트를 바꾼 사용은 기존 사용자 재사용으로 표시하며 새 첫 사용자로 다시 세지 않는다.
7. 모순된 보고는 `conflicting`으로 보존한다. 최신 수정이 이전 보고를 명시적으로 바로잡은 경우 정정 관계를 남기고, 그렇지 않으면 관련 사용 여부는 unknown이다. 불리한 실패·timeout·미완료를 지우지 않는다.

이 원장은 자발적 피드백을 읽는 운영자의 수동 기록 양식이다. 참가자 모집, DM, 설문 발송, 연락처 저장, 지속 수집을 승인하거나 구현하지 않는다.

### 3.2 7일 창과 결측

보고 마감 `T`를 먼저 고정한다. t0가 정확하면 `T ≥ t0+168h`인 경우만 성숙 코호트 N에 넣는다. t0가 날짜 구간이면 가장 늦은 가능한 t0에서 168시간이 지난 뒤 성숙시킨다. 이후 보고에 발생 시각이 있으면 사건 창으로 분류하되, 접수 시각도 남긴다. 마감 뒤 도착한 수정은 새 `as_of` 판본에 반영하고 과거 결과를 조용히 덮어쓰지 않는다.

- **yes**: 7일 창 안의 실제 별도 사용이 명시되어 있다.
- **no**: 창이 지난 뒤, 해당 7일 동안 별도 사용하지 않았다고 명시했다. 거절·불만만으로 no를 추정하지 않는다.
- **unknown**: 무응답, 철회, 불명확한 사용 시각/내용, 연결되지 않은 보고, 모순 등. 사유를 나눠 기록한다.
- **immature**: 아직 168시간이 지나지 않았다. N에 넣지 않으며 yes가 먼저 왔어도 같은 보고 마감의 성숙 지표에는 이르게 포함하지 않는다. 재사용 개별 보고로는 보존한다.

성숙하고 동일인 연결이 된 코호트에서는 `N = R + F + U`, `C = R + F`로 기록한다. F는 명시적 no, U는 unknown이다. `N=0`이면 U03과 응답 확인 비율은 null, `C=0`이면 U04는 null이다. 정수 0은 정의된 창과 원장을 실제로 확인해 해당 사건이 없을 때만 쓴다. 자료를 읽지 않았거나 권한이 없으면 null이다.

현재 이 작업에서 실제 U01 코호트와 과거 t0를 확인하지 않았다. **N·R·F·U·재사용율은 모두 unknown**이다. 새로 시작한 2시간 창만으로 그 창의 신규 사용자 7일 유지율을 완성할 수 없다.

## 5. 수동 기록 양식과 synthetic 예시

다음 양식은 작성 제안이다. 제품에 기록기를 추가하지 않는다. 실제 사용 시 기존 승인된 안전한 운영 기록 안에서만 작성하고 원문 대화·개인정보는 넣지 않는다. 공개 보고 URL도 불필요한 계정·추적 매개변수는 보존하지 않는다.

### 5.1 공개 집계 한 행

| 필드 | 빈 양식에 넣을 내용 |
| --- | --- |
| `record_id / is_synthetic` | 고유 수동 행 ID / 실제면 false |
| `metric_id / unit / value` | 예: D01 / download_events / 정수 또는 null |
| `numerator / denominator` | 비율만 각각 정수. 개수는 numerator=value, denominator=null 및 `not_applicable` |
| `scope` | repo / package / release_tag / asset_ids / host 중 해당 필드 |
| `window_start / window_end / boundary` | 원본 창과 포함 규칙; 현재 잔액은 `window_kind=point_in_time` |
| `observed_at / source_http_date` | 실제 조회 시각과 응답 Date; 없는 값은 null |
| `source_url / evidence_status` | 직접 확인한 출처 / observed·reported·calculated·unknown |
| `missing_reason / limitations` | null 이유, 지연, 모집단 제한. 값이 0이면 실제 확인 범위 |

**SYNTHETIC — 다음 숫자·시각은 모두 기록 연습용이며 실제 결과에 합산하지 않는다.**

| record_id | is_synthetic | metric_id | 값·단위 | 분모 | 기간/조회 시각 | 출처 | 제한 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| SYN-AGG-01 | true | S01 | 40 star balance | 해당 없음 | `point_in_time=2026-11-01T00:00:00Z` | `synthetic://example/repo` | 실제 관찰 아님 |
| SYN-AGG-02 | true | S01 | 42 star balance | 해당 없음 | `point_in_time=2026-11-01T02:00:00Z` | `synthetic://example/repo` | 같은 가상 저장소 |
| SYN-AGG-03 | true | S02 | +2 net stars | 해당 없음 | 위 두 시각 사이 | SYN-AGG-01/02 | 신규 2명·홍보 기여 2건을 뜻하지 않음 |

### 5.2 사용 보고 한 행

필수 열: `report_id, is_synthetic, reporter_token, identity_link_status, relationship_status, source_event, received_at, t0_or_range, prior_use_status, product_version, host_profile, task_category, attempt_status, install_state, enabled_state, full_read_evidence, application_evidence, usefulness_report, reuse_event_time_or_range, reuse_is_separate_task, reuse_7d_status, missing_reason, source_url`.

`full_read_evidence`와 `application_evidence`는 지원되는 실제 근거가 없으면 `unverified`다. 설치 성공, 답변 말미의 사용 표기 또는 모델 자신의 주장으로 네이티브 적용 영수증을 만들지 않는다. 민감한 작업 제목 대신 `email / proposal / changed_requirement / other` 같은 과제 범주만 쓴다.

**SYNTHETIC — 아래 보고자는 실재하지 않으며 실제 사용·유지율 증거가 아니다.** 보고 마감은 가상으로 `2026-11-09T00:00:00Z`, 세 명의 최초 사용은 모두 `2026-11-01T00:00:00Z`로 둔다.

| report_id · 토큰 | 첫 사용 | 이후 보고 | 7일 상태 | 중복 처리 |
| --- | --- | --- | --- | --- |
| SYN-U01 · SYN-P01 | 이전 사용 없음 명시, email 시도 completed | 11-03에 별도 proposal 사용 명시 | yes | U01 1명, U02 1명 |
| SYN-U02 · SYN-P01 | 새 첫 사용 아님 | SYN-U01 후속 보고를 다른 곳에 재게시 | 기존 yes | 같은 출처 사건으로 연결, 인원 추가 없음 |
| SYN-U03 · SYN-P02 | 이전 사용 없음 명시, proposal 시도 failed | 창 종료 뒤 7일 내 별도 사용 없었다고 명시 | no | 실패한 첫 시도도 코호트에 포함 |
| SYN-U04 · SYN-P03 | 이전 사용 없음 명시, changed_requirement 시도 partial | 후속 응답 없음 | unknown / no_response | 이탈·no로 바꾸지 않음 |

**SYNTHETIC 계산**: 성숙 N=3, R=1, F=1, U=1, C=2. 확인 하한 U03=`1/3=33.3%`, 응답자 비율 U04=`1/2=50%`, 응답 확인 비율=`2/3=66.7%`, 미응답 1명. 이 세 비율은 서로 다른 뜻이며 “제품 유지율 50%”로 쓰지 않는다. 합성 행은 실제 원장과 섞지 않고 `is_synthetic=true`를 유지한다.

## 6. 주장과 증거의 연결

## 7. 운영자가 사용할 최소 읽기 순서

1. **이번 2시간 인계**: 문서 작성 여부와 실제 수집한 시각별 카운터만 적는다. 시작값 없는 순변화, 7일 미성숙 코호트, 설치/사용 미확인은 null과 사유로 남긴다. 과거 이슈의 23 Stars나 다른 릴리스 집계를 이번 시작값으로 재사용하지 않는다.
2. **실제 자발적 보고가 있는 경우**: 설치·첫 시도·결과·재사용·추천을 각 열에 분리한다. 반복되는 구체적 설치 혼란이나 실패 보고가 있으면 그 사실을 해당 이슈의 후속 작업 후보로 제안한다. 빈도·원인·효과를 확대하지 않는다.
3. **이후 관찰이 별도로 승인된 경우**: 동일 정의의 수동 스냅샷과 성숙 코호트를 읽는다. Stars 순변화는 홍보 목표 신호로, 실제 첫 시도·재사용 보고는 사용자 가치 검토의 근거로 함께 보되 서로 대체하지 않는다. 수치 목표·유지율 목표는 근거 있는 기준선 없이 새로 확정하지 않는다.

이 문서는 텔레메트리, 지속 수집, 자동 대시보드, 스케줄, 계정 알림·피드 조회, 게시·댓글·DM을 만들거나 실행하지 않는다. 지표 정의가 외부 실행 권한을 추가하지 않는다. 최종 통합 검사는 S001이 게시한 정확한 동결 후보 SHA를 기준으로 담당자가 수행해야 한다.
