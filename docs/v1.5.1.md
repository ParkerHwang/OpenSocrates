# OpenSocrates v1.5.1: Chinese and Japanese instructions

[한국어](v1.5.1.ko.md) · [English README](../README.md) · [简体中文](../README.zh.md) · [日本語](../README.ja.md)

v1.5.1 adds Simplified Chinese (`zh`) and Japanese (`ja`) to the existing English
(`en`) and Korean (`ko`) reasoning content. It is a v1.5 maintenance release,
separate from the v1.6.0 Go migration and Windows ARM64 work.

## Content and host scope

All 48 authored methods provide complete procedures and canonical examples in
all four languages: 192 procedure files. The teacher-question overlay contains
three questions per method per language, 576 total. The bundle and overlay use
content revision 4; the original English/Korean authored method body text and
individual method revisions are preserved.

Four existing profiles receive the localized controllers, guides and references:

| Profile | Supported environment | Delivery |
| --- | --- | --- |
| Codex | Apple-silicon Mac and Windows x64 | Existing native package and hooks |
| Claude Code CLI / Desktop local Code | Apple-silicon Mac | Stateless native entry and installed references |
| Claude web / Desktop Chat / Cowork | Account skill exported on Mac or Windows | Executable-free skill ZIP; account upload and activation are separate |
| Antigravity conversation application | Apple-silicon Mac and Windows x64 | Workspace or global rule and skill |

This update adds no native Windows Claude Code, Windows ARM64, Intel Mac or
Linux native qualification. The historical [Mac guide](macos-v1.5.md),
[Windows guide](windows-v1.5.md) and [v1.5.0 handoff](v1.5.0/PREPARATION_HANDOFF.md)
retain their dated evidence. Use the 1.5.1 commands in the current READMEs and
[setup guide](setup-guide.md); historical observations do not become new live
observations through translation or publication.

## Selecting reasoning instruction language

When the retained selector resolves current input, the order is:

1. A trusted explicit locale supplied for the current request.
2. The stored `locale_preference`, when set to `en`, `ko`, `zh` or `ja`.
3. Script detection on the transient current input, with English fallback.

Any recognized hiragana or katakana selects Japanese before character counts.
Otherwise, dominant Hangul selects Korean and dominant Han characters select
Chinese. ASCII dominance, ties, empty input and unrecognized scripts use English.
This is a script heuristic, not a guarantee of identifying the user's language.
Han-only text can be Chinese or Japanese; explicitly select `ja` for Japanese
text without kana. Traditional Chinese is not a separate authored locale: `zh`
contains Simplified Chinese instructions.

The stored preference is a native runtime setting, not an npm installer option.
From the installed Codex package root on Mac:

```sh
bin/launch.sh locale codex get
bin/launch.sh locale codex set zh
bin/launch.sh locale codex set ja
bin/launch.sh locale codex set follow
bin/launch.sh locale codex reset
```

On Windows x64, use the package's Node launcher:

```powershell
node bin/launch.mjs locale codex get
node bin/launch.mjs locale codex set ja
node bin/launch.mjs locale codex reset
```

`follow` and `reset` clear the stored preference so current-input detection can
apply. They do not erase unrelated settings. For source development in the
repository's locked environment, the corresponding entry is:

```sh
uv run --locked python -m opensocrates locale get
uv run --locked python -m opensocrates locale set zh
uv run --locked python -m opensocrates locale reset
```

The retained SDK selector path is unavailable on Windows. A stored setting does
not change the stateless decision path or configure an account/content package.

### Stateless decision requests

Decision requests require an explicit JSON `locale` of `en`, `ko`, `zh` or `ja`.
They do not read stored settings or infer language from a transcript. From the
Codex package root, send the existing closed request envelope to
`bin/launch.sh decision codex` on Mac or `node bin/launch.mjs decision codex`
on Windows. Set the envelope's `locale` to the desired language; do not add an
unsupported `--locale` flag. The package reference
`skills/opensocrates/references/decision/request.json` is the complete example.
Its routing features must describe the current task, including known
prerequisite failures; changing language does not bypass method applicability.

Claude's native package uses `bin/launch.sh decision claude`. Account skills and
Antigravity content use the corresponding locale guide/catalog and complete
references, without this local preference store. Ask the agent to use Simplified
Chinese or Japanese OpenSocrates instructions when an ambiguous input needs an
explicit choice. Model-selected account skill loading can still be missed.

Reasoning instruction language is separate from answer language, host UI
language and npm installer output. This update does not claim that every CLI
message is translated. Method IDs, JSON keys and the attribution footer remain
stable across languages.

## Install, update and activate

Use Node.js 20+ and the host's normal login and permissions:

```sh
npx --yes opensocrates@1.5.1 install --host codex
npx --yes opensocrates@1.5.1 update --host codex
npx --yes opensocrates@1.5.1 status --host codex
```

Choose `install` for a new installation and `update` for an existing one. Native
runtimes are bundled. Explicitly select `--host claude` on Mac or
`--host antigravity` on a supported platform; use the existing absolute
`--workspace` path consistently for workspace installation and lifecycle checks.
The default and `--host all` still select Codex only.

For an account skill, export a ZIP into an existing folder:

```sh
npx --yes opensocrates@1.5.1 export --host claude-chat --output /absolute/path/to/opensocrates-1.5.1-account.zip
```

Back up the existing skill and its enabled state before replacement. Upload and
enable the new ZIP in the correct Claude account and preserve existing account
instructions when appending the standing instruction in the setup guide.
Successful export is not account installation or activation. Review actual
host trust/permissions, preserve intentionally disabled installations, and
start a fresh conversation after lifecycle changes.

## Attribution, privacy and evidence

The exact final line `Powered by OpenSocrates` applies only after an eligible
canonical method was completely read and actually applied to that answer.
Use the same English line in all four languages. Reader guidance alone and
mechanical work do not qualify. The line does not prove native application or
better results.

The language additions introduce no telemetry, credential collection, raw
prompt/transcript storage, screenshot retention or hidden-reasoning capture.
Script detection uses transient current text. Stateless decision retrieval
reads no private transcript and initializes no database. Normal host requests
remain governed by the host's authentication, permissions, retention and terms.

Implementation, local validation, release validation and live host observations
are separate evidence levels. Translation parity and archive checks cannot
prove every account's activation, every-turn method use, or universal answer
quality, token-cost or latency improvement. Do not add a universal model-answer
receipt requirement to ordinary installation completion.
