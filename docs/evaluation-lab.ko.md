# 사무업무 평가 실험실

[English](evaluation-lab.md) · [다른 과제 묶음 만들기](evaluation-lab-casepacks.ko.md)

전달하려는 메시지, 톤, 상황에 맞는 내용, 참조와 구성이 함께 좋아지는지 실제
사무업무 답변으로 비교하는 로컬 도구입니다. 실제 앱 실행과 첫 판단은 사용자가
맡습니다. 도구는 가상 과제 준비, 시도별 분리, 승인한 최종 답변 수집을 맡습니다.
모델을 대신 실행하거나 어떤 답변이 좋은지 판정하지 않습니다.

## 처음에는 앱 하나에서 여섯 번

1. [Python 3.12 이상](https://www.python.org/downloads/)과 테스트할 앱을 설치하고,
   앱의 정상 로그인 절차를 따릅니다. API 키는 필요하지 않습니다.
2. 휴대용 ZIP을 본인이 쓸 수 있는 폴더에 풉니다. Mac에서는
   **Start Lab.command**, Windows에서는 **Start Lab.cmd**를 엽니다. 운영체제의
   정상 신뢰 확인 절차를 따릅니다. Python이 없다면 실행기가 안내하는 공식
   설치 프로그램을 설치한 뒤 다시 엽니다. 보안 정책을 우회하지 않습니다.
3. 로컬 브라우저 화면에서 **현재 OS와 앱 하나**를 선택합니다. 처음에는 절차
   확인용 과제 두 개와 실행 한도 6회를 사용합니다. 과제 두 개를 세 조건으로
   실행하는 구성입니다. 실험을 생성하는 것만으로 모델 사용량이 발생하지 않습니다.
   OS·앱 조합 여섯 개를 모두 고르면 절차 확인만 36회가 계획되며, 서로 독립된
   조합으로 다룹니다.
4. 생성된 답변을 보기 전에 가상 과제와 공통 짧은 지시를 읽고, 실제 사무업무를
   비교하기에 적절한 내용인지 확인합니다.
5. 한 시도를 준비하고 앱별 안내와 실행 전 확인을 마칩니다. 앱에서 Run을 누르기
   **전에** 실험실에서 해당 시도의 기록을 시작합니다.
6. 최종 답변을 미리 보고 가상 과제의 요청된 최종 결과물만 승인합니다. 나머지
   시도를 마친 뒤 평가 화면에서 먼저 사용할 답변을 고르고, 이후 조건을 공개합니다.

브라우저는 내 컴퓨터의 주소에만 연결합니다. 상태를 갱신하려면 화면을 열어
두세요. 이 화면을 닫아도 다른 앱에서 실행 중인 모델 작업은 멈추지 않습니다.

## 비교하는 세 조건

| 조건 | 구성 |
| --- | --- |
| A | 활성 환경에 OpenSocrates가 없는 상태의 일반 과제입니다. |
| B | 같은 과제에 모든 과제에서 공통으로 쓰는 짧은 지시 하나를 더합니다. |
| C | 해당 앱용으로 준비한 OpenSocrates 1.5.3 콘텐츠와 함께 일반 과제를 실행합니다. |

모든 시도는 새 대화와 별도 실행 폴더를 사용합니다. 제공된 프롬프트를 그대로
쓰세요. 앱이 추가 질문을 하면 제공된 응답 카드를 사용하고 질문 횟수를 기록합니다.
과제마다 B의 지시를 개선하거나 C의 답변을 본 뒤 코칭하지 않습니다. 실패하거나
막힌 시도도 그대로 기록합니다. 재시도는 별도 진단 기록이며 첫 시도를 대체하지
않습니다. 시작한 시도는 실패해도 실행 한도에 포함됩니다. 자동 재시도나 앱의
작업 자동 실행은 없습니다.

| macOS·Windows 앱 | 요청한 설정 | 실행 전에 확인할 실제 표시 |
| --- | --- | --- |
| Codex 앱 Work | `gpt-6-luna max` | Work에서 GPT-6 Luna, Max effort. |
| Claude Cowork | `haiku-5.5-medium` | Cowork에서 Haiku 5.5, Medium effort. |
| Antigravity 독립 앱 | `gemini-3.8-flash-mid` | Gemini 3.8 Flash Medium. 이 표시와 요청한 이름의 대응을 직접 확인합니다. |

실제 모델, 사고 수준, 앱 버전과 실행 위치를 관찰한 대로 기록합니다. 요청한
조합을 선택할 수 없다면 이용 불가 또는 미확인으로 남깁니다. 다른 모델, 일반
채팅, Claude Code, Codex CLI로 대체하지 않습니다. Mac·Windows 앱에서 시작했다는
사실만으로 작업이 그 OS에서 실행된다고 볼 수 없습니다. 클라우드, 동기화,
미확인 실행 상태를 구분해 기록합니다.

## 앱 설정과 환경 확인

앱에는 실험실이 표시하는 **그 시도의 실행 폴더만** 허용합니다. 실험실 전체,
소스 저장소, 다른 시도의 폴더를 주지 않습니다. 실행 폴더에는 해당 가상 과제의
자료와 프롬프트, 빈 `out/` 폴더가 있고, C에는 앱용 콘텐츠도 들어갑니다.
폴더 분리는 운영체제의 격리 기능이 아니므로 앱의 정상 접근 권한도 사용합니다.

해당 시도의 파일은 준비 화면에서 제공하는 앱별 안내를 따릅니다.

- **Work의 C:** 변경하지 않은 1.5.3 계정 스킬 전체로 만든 실험용 콘텐츠 플러그인
  어댑터를 제공합니다. Work UI에서 지원하는 경우 가져옵니다. 명령 훅은 없습니다.
  새 전달 방식을 시험하는 것이며, 파일이 있다는 것만으로 Work가 스킬을 발견하거나
  적용했다는 뜻은 아닙니다. 가져오기를 지원하지 않으면 이 조합을 막힘으로 기록하고
  CLI로 바꾸지 않습니다.
- **Cowork의 C:** 제공된 계정 스킬을 Claude의 정상 스킬 화면에서 업로드하고 테스트에
  활성화합니다. 필요한 신뢰 확인 절차를 마칩니다. 스킬이 있다고 말하는 지시만으로
  실제 활성화를 대신할 수 없습니다. 계정 스킬은 다른 기기·화면에 동기화될 수
  있으므로 A·B를 실행하기 전에도 상태를 다시 확인합니다. 기존 설정을 보존하고,
  테스트를 위해 직접 바꾼 항목만 되돌립니다.
- **Antigravity의 C:** 제공된 작업공간 규칙과 스킬이 들어 있는 새 실행 작업공간을
  엽니다. 전역 설치를 하거나 다른 조건의 작업공간을 재사용하지 않습니다. 워크플로와
  일반 Gemini 웹사이트는 이 테스트의 실행 경로가 아닙니다.

매 시도마다 계정·전역 지시, 설치된 플러그인과 스킬, 프로젝트·폴더 지시, 메모리,
커넥터와 상위 작업공간 규칙을 확인합니다. OS를 새로 설치했거나 새 폴더를 만들어도
계정 설정이 이어질 수 있습니다. 실험실은 사용자의 환경 확인을 기록하며, 자동으로
새 기기 환경을 인증하지 않습니다. A·B에 기존 OpenSocrates 지시가 남아 있으면
오염입니다. 확인된 오염은 시작을 막습니다. 격리가 미확인이라면 탐색용 실행을
명시적으로 선택해야 하며 결과에서도 그 상태를 유지합니다.

더 강한 격리가 필요하면 독립적으로 준비한 OS 환경이나 깨끗한 스냅샷을 사용합니다.
시작을 위해 로그인 토큰을 복사하거나 전역 설정을 지우거나 관계없는 플러그인을
제거하지 않습니다. 정상 앱 설정을 사용하고 확인 가능한 범위를 기록합니다.
앱의 실제 스킬 발견을 관찰할 수 없다면 전달·적용은 미확인으로 둡니다. 답변의
자기 설명이나 꼬리말은 로딩, 전체 읽기, 적용의 증거가 아닙니다.

## 최종 답변 수집과 모니터링

프롬프트는 실행 폴더 안의 `out/final.md`에 결과물을 작성하도록 요청합니다.
모니터링은 이 파일의 존재, 크기, 읽을 준비 여부만 확인합니다. 파일 도착만으로
모델의 작업 종료나 OpenSocrates의 효과를 알 수는 없습니다. 내용을 미리 보고
가상 과제의 최종 결과물인지 확인한 뒤 **그 버전**을 승인합니다. 미리 본 뒤
파일이 바뀌거나 실험실을 재시작했다면 다시 미리 보고 승인해야 합니다.

앱이 파일을 쓸 수 없으면 실험실의 수동 입력으로 최종 결과물을 붙여 넣고 수동
수집으로 표시합니다. 문장, 구성, 참조와 꼬리말을 그대로 보존합니다. 전체 대화,
생각 과정, 도구 로그, 계정 정보나 실제 비공개 업무를 붙이지 않습니다. 미리 보기를
거절하면 승인된 답변 모음으로 가져오지 않으며, 거절한 내용이나 그 지문을 저장하지
않습니다. 앱이 만든 원본 파일은 실행 폴더에 남아 있으므로 폴더 관리는 별도로 합니다.

수집 범위는 승인한 가상 과제의 최종 답변, 승인한 사람의 의견·수정본, 명시적인
실험 메타데이터입니다. 배경 화면 녹화, 대화 수집, 전역 호스트 로그, 인증 정보,
숨겨진 사고 과정 수집은 사용하지 않습니다. 이 버전에는 네이티브 훅 모니터링이
없습니다. 서비스 쪽 데이터 보관은 각 제공자가 관리하며 이 도구가 통제하지 못합니다.
로컬 도구는 업로드하지 않고, 내보내기도 로컬 파일로만 만듭니다.

## 먼저 사람이 고릅니다

세 답변 전체를 비교해 실제로 사용할 답변, **동률**, **모두 사용하기 어려움**을
고릅니다. 짧은 첫 느낌은 선택 사항이고, “왜인지는 설명하기 어렵다”도 유효합니다.
확신, 어느 조건인지 알아봤는지, 평소 체감하던 차이가 재현됐는지도 기록합니다.
첫 판단을 저장해 잠근 다음 조건과 사실 확인 항목을 공개합니다. 이후 직접
고쳐 보는 과정으로 원하던 차이를 드러낼 수도 있습니다.

실행과 평가를 같은 사람이 할 수 있으므로 부분적인 가림입니다. 익명 표시는
단서를 줄이지만 기억, 식별 가능한 꼬리말, 익숙한 조건을 지우지는 못합니다.
가능하면 한 묶음을 완료한 뒤 시간을 두고 평가합니다. AI의 문장 비교나 원인
추정은 사람의 첫 반응 이후에 하며, 사람의 선택을 덮어쓰지 않습니다.

제공된 절차 확인 과제 두 개는 진행 방식이 맞는지 확인합니다. 발견용 과제 네 개는
다양한 업무와, 과한 개입이 불리할 수 있는 단순 업무를 살핍니다. 사람의 승인을
받은 기준과 실험 설정을 고정한 뒤 별도의 확인용 예시 두 개를 씁니다. 과제가
평소 경험을 담지 못하면 다음 과제 묶음을 바꾸거나 다회차 대화 연구를 별도로
설계합니다. 부적절한 과제를 많이 실행한다고 그 문제가 해결되지는 않습니다.

## 이어 하기, 반복하기, 합치기

- **이어 하기:** 같은 압축 해제 폴더의 실행기를 다시 엽니다. `lab-data/`에 실험이
  유지됩니다. 같은 데이터 폴더로 실험실 두 개를 동시에 실행하지 않습니다.
- **새 실험:** 원래 ZIP을 다른 쓰기 가능한 폴더에 새로 풀거나, `--data`로 새 전용
  데이터 폴더를 지정합니다. 빈 실험을 원하면 기존 `lab-data/`를 복사하지 않습니다.
  앱이나 실험 기록을 자동 삭제하는 초기화는 없습니다.
- **다른 OS·앱:** 독립된 새 도구 사본을 준비하고 그 환경에서 확인한 설정을 기록합니다.
  로그인 캐시를 옮기지 않습니다. 고정된 과제·콘텐츠 식별자가 같아야 나중에 비교할
  수 있습니다.
- **내보내기:** 실험실의 내보내기를 사용합니다. 허용된 메타데이터, 승인한 답변,
  잠근 판단과 설명 보고서가 포함됩니다. 직접 공유하기 전까지 비공개로 보관합니다.
  아직 공개하지 않은 조건의 대응표는 포함하지 않습니다.
- **합치기:** 예를 들어 번들에서
  `python merge-exports.py mac-export.json windows-export.json --output combined.json`을
  실행합니다. 읽기 전용 병합기는 과제·콘텐츠 식별자가 맞는지 확인하고, 충돌하는
  중복을 거부하며 새 결과를 만듭니다. 가져온 실험을 이어 실행하는 기능은 아닙니다.

결과는 OS, 앱, 모델, 사고 수준별로 나눕니다. 미실행·막힘·실패를 남기고 재시도로
첫 시도의 분모를 개선하지 않습니다. 통합 승률을 만들거나 누락된 사용량으로
절감 효과를 추정하지 않습니다. 한 사람의 선호는 유용한 개인 증거이며 일반
사용자의 효과를 입증하지는 않습니다. 새로운 다양한 과제에서 B와 C가 비슷하면
OpenSocrates의 추가 효용은 미확인입니다. 편리함과 다회차 대화의 효과는 별도
증거가 필요합니다.

## 유지보수자를 위한 실행

소스 저장소에서는 `python tools/evaluation_lab.py`로 시작합니다. `--data`,
`--pack`, `--payloads`, `--no-browser`, `--port`로 로컬 경로와 실행 설정을 지정할
수 있습니다. 휴대용 도구는
`python tools/build_evaluation_lab.py --payloads-dir PATH --output office-lab.zip`으로
만듭니다. 빌더가 요구하는 정확한 공개 배포 파일을 사용하며 고정된 해시를 확인합니다.
빌드나 실험실 시작에는 모델 호출이 없습니다.

소스 저장소의 [설계](evaluation-lab-design.md)와
[구현 계약](evaluation-lab-contract.md)에서 구조와 완료 기준을 확인할 수 있습니다.
오프라인 검사는 로컬 흐름을 확인합니다. Windows·Mac의 각 앱에서 로그인한 실제
실행은 별도의 증거입니다. 도구가 있다는 사실만으로 여섯 조합의 실제 동작이나
답변 개선이 검증되지는 않습니다.
