# v1.5.2 language review

The six new instruction languages—French (`fr`), German (`de`), Italian (`it`),
Spanish (`es`), Portuguese (`pt`) and Thai (`th`)—have completed independent AI
source comparison and targeted correction rechecks. This records semantic review;
source, native platform and public publication evidence are separate.

Baseline: released v1.5.1 commit `5a6a7fa2897dd42772c4503a1301770e48bd1f29`.
Content and individual method identities advance from revision 4 to 5. The ten-language
release contains 48 methods, 480 complete procedures, 3,840 cases and 1,440 teacher
questions. Existing four-language procedures, cases and localized values are
preserved. Tracking and final execution evidence:
[issue #117](https://github.com/ParkerHwang/OpenSocrates/issues/117) and
[PR #118](https://github.com/ParkerHwang/OpenSocrates/pull/118).

## Method and complete coverage

Twelve independent AI reviewers each compared 24 methods in one new language
against the complete English source. Each comparison included the entire procedure,
eight cases, three teacher questions, display/action metadata and catalog summaries.
For each language, the first-half reviewer also compared its 127 locale messages,
12 catalog families, common documents, presentation policy, decision/reader/rigor
instructions, Claude account/native guides, installation README and runtime
participation/routing/injection/grounding instructions. Output truncation was
repaired with smaller reads; this was complete coverage, not sampling.

Writers and the parent fully read the baseline `critical-thinking@4` procedure
and decision guide before using them to check translation and evidence claims.
Reviewers used the complete current `critical-thinking@5` canonical procedure;
source decision execution selected it without a model call. Agent application
and source execution do not establish an authenticated native application receipt
or a general answer-quality improvement. Native application remains `unverified`.
Only public findings and corrections are recorded here.

## Authoring and delivery boundaries

The nine English procedure headings and machine identifiers remain protocol fields.
English/Korean procedures retain their 350–900-word bounds. Full, faithful new
European translations reached 1,025 words, so their bound is 350–1,200 words.
Chinese/Japanese/Thai retain 700–6,000 non-whitespace characters. Teacher questions
remain 20–220 characters with ASCII `?`. The complete projection exceeds 4MiB;
its regular-file JSON reader uses a bounded 8MiB limit. Raw prompt, hook, privacy,
context and instruction-delivery budgets remain unchanged.

Latin-script languages require a trusted explicit or saved locale. Kana has
priority for Japanese; otherwise dominant Thai, Hangul or Han selects Thai,
Korean or Chinese. Han-only Japanese is ambiguous; empty input, ties and unknown
scripts fall back to English. Portuguese uses broadly understandable wording with
Brazilian orthography under `pt`, without certifying every regional variant.
Instruction language is separate from host UI and installer output.

The four host profiles and existing platform qualifications are retained. Go and
Windows ARM64 belong to v1.6.0. Account export is separate from upload, activation
and model selection. Complete historical two-/four-language runtime/package
compatibility does not add translations to old releases. Protected merge, native
macOS/Windows checks, immutable exact-tag release assets, trusted npm publication
and fresh public execution must each have their own observed evidence.
