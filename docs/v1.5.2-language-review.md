## OpenSocrates use and review approach

The documentation writer read the complete released `critical-thinking` procedure
before drafting and applied its separation of claims, sources, omissions,
inference and unverified evidence to release/platform/language claims. The parent
reports a source decision request selecting `critical-thinking@4` and a complete
read of the returned instructions. Source execution and model-reported application
are distinct from an authenticated native host application receipt; native
application and answer-quality improvements remain unverified.

Final language reviewers should compare each new translation to the complete
English/Korean source and relevant existing Chinese/Japanese context. Inspect:

- All 48 complete procedures, their metadata and canonical cases per language.
- All 144 teacher questions per new language, addressed to the active agent.
- Catalog, injection, participation, controller, decision/reader/presentation
  instructions, all four host packages and the language's installation README.
- Applicability, contraindications, prerequisites, evidence states, public outputs,
  numerical bounds, required versus optional actions, hold/stop conditions and
  complementary-method handoffs.
- Natural grammar and operational meaning, including Portuguese Brazilian
  orthography under generic `pt` and Thai script-appropriate length rules.
- Closed machine identifiers, placeholders and stable JSON keys; complete reads,
  attribution, source-as-data trust boundaries and hidden-reasoning prohibitions.

The nine English procedure headings are protocol fields. Preserving them is not
an untranslated-prose defect. Do not change the four-language baseline to repair
a new translation without an independently authorized source change.

## Scope and release boundaries

Latin-script French, German, Italian, Spanish and Portuguese require a trusted
explicit or saved locale. Kana has priority for Japanese; otherwise dominant
Thai, Hangul or Han selects Thai, Korean or Chinese. Han-only Japanese remains
ambiguous. Empty input, ties and unknown scripts fall back to English. Instruction
language is distinct from answer language, host UI and installer output.

The four host profiles and v1.5.0/v1.5.1 platform qualifications remain unchanged.
Windows ARM64 and Go migration belong to v1.6.0. Account skill export is separate
from upload, activation and model selection. Historical complete two-/four-language
runtime content compatibility does not add languages to old packages.

The prior release encountered an administration-API HTTP 403 before automated
building and was subsequently published through the verified owner-CLI route.
For v1.5.2, that fallback is a plan only until actual publication evidence is
recorded; do not copy the earlier release's success into this release's results.
Any user-authorized promotional message must follow verified publication.
