## 1. Scope and claim boundary

This report covers 51 unique EN/KO semantic pairs: 48 insufficiency pairs and
three additional boundary pairs. It records a development-policy decision set
for testing the revised selector taxonomy and scorer.

This is not confirmation-grade human gold, not held-out, and not
answer-quality evidence. It does not replace the historical schema 1.0.0
screening results and does not show that OpenSocrates improves answer quality.
The guide's independent-human review requirement remains the bar for any later
confirmation version.

Every standalone decision and disagreement record carries the same evidence
grade. Machine-readable status fields do not end in `_gold`.

## 3. Policy resolution

The two complete reviews were recorded as compatibly agreeing on two boundary
pairs and having 49 substantive disagreements. The committed disagreement
ledger preserves both decisions for those 49 pairs.

For development use, the synthesis applies these rules:

1. A matching **Do-not-use** condition prohibits selecting the method.
2. A matching **Stop condition** with an identifiable owner permits
   `route_owner_then_hold` under the route-identification selector contract.
3. A clarifier leads only when clarification is itself the repair route.
4. Multi-leading and optional-intervention cases are not leading-metric
   eligible unless policy fixes one unique leader.
5. Undetermined, unresolved, rewrite, invalid, and material translation-
   mismatch pairs are excluded from policy metrics.

Three recorded substantive resolutions remain visible in the disagreement
ledger: one mechanical boundary uses the recoverable Claude record, while two
prohibited-intervention cases normalize `bounded_analysis` to
`hold_no_intervention`.

## 9. Generation boundary

The committed decision snapshot is reproducibly **validated**, not
reproducibly regenerated. The original private inputs are not published, so
the repository cannot rebuild the historical packet/reviewer chain.

For a future maintainer run:

- `tools/build_v12_adjudication_packets.py` requires explicit dataset,
  dataset-manifest, queue, guide, raw-result, and output paths. It derives its
  timestamp from source metadata and atomically publishes a complete new
  packet directory.
- `tools/compare_v12_adjudication_reviews.py` requires a packet manifest and
  refuses to overwrite its output without explicit authorization. It builds
  and validates all 51 rows from the two review artifacts; finalization rejects
  stale hashes, swapped reviewers, row tampering, and any count or
  classification mismatch.
- `tools/finalize_v12_ai_adjudication.py` requires an explicit new output
  directory, source lock timestamps, and all reviewer inputs. It stages the
  whole versioned set and publishes the directory atomically. Existing locks
  and dirty source trees are refused unless separately authorized. It validates
  and preserves each primary record's `semantic_review`; secondary residual
  uncertainties are shape-checked, `residual: false` entries leave the record
  unchanged, and only `residual: true` notes may be appended. Equivalence and
  translation-mismatch values are never inferred or overwritten. A translation
  mismatch that conflicts with policy-metric eligibility stops finalization.
  It never creates or overwrites the checker-pinned public-snapshot lock;
  regenerated publication requires a new version or an explicit reviewed lock
  and trust-root rotation.

Packet and finalization directory publication use a two-rename overwrite only
after rejecting symlinks in every existing output-path component. If the
second rename reports an error, the tool restores the previous directory
before returning the error. A process or machine crash between renames can
leave the PID-suffixed `.previous-*` directory beside the requested output;
the old complete directory remains recoverable there, but automatic recovery
after an uncatchable crash is not claimed.

None of these tools fabricate missing review, packet, queue, dataset, or raw
evidence. Their current options are documented by each tool's `--help` output.
