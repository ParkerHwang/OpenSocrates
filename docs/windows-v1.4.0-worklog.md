- Categorical ACL diagnosis on this non-elevated process: `current_sid()` matched the token user; token default owner and a new temporary directory owner were both in the current-user category; the temporary directory was not a reparse point; its inherited DACL contained SYSTEM, Administrators and other inherited-principal categories. The later hosted observation showed a different administrator/runner condition: token user still matched `current_sid()`, but token default owner and a newly created temporary object were both in the Administrators category. The object was not a reparse point; the secure-creation path performed no general owner normalization and finished with current-user ownership plus a private protected DACL. No raw SID, username or absolute diagnostic path was recorded.
- The first remediation attempted narrow owner normalization after creation, but independent replacement-path probes disproved its provenance and object-identity safety. That design was discarded. The reviewed design instead assigns the token-user owner and a protected private DACL atomically through an explicit creation security descriptor; native directory creation returns the exact creation handle. Existing paths are opened without following reparse points and may receive only a DACL update through that stable handle; their owner is never changed. A factory-issued temporary-file capability retains one verified, non-delete-sharing parent handle from handle-relative creation through handle-relative publication, while validation and failed-file disposal remain bound to the exact file handle. Replacement after that first authoritative parent open is blocked; name resolution before the first open selects the object that is then validated and is not claimed as prior identity evidence. Existing Administrators-owned paths, all other foreign owners, reparse points, unprotected DACLs and broad Everyone ACEs remain fail-closed.
