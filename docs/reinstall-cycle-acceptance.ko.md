# 같은 기기의 네이티브 제거·재설치 검증

[English](reinstall-cycle-acceptance.md) · [네이티브 안내](native-v1.6.ko.md)

이 절차는 **같은 기기 재설치**이며 새 기기 증거가 아닙니다. 기존 v1.5를
보존하는 `adopt`와도 구분합니다. 과거 1.3.1→1.4.0 purge·신뢰 초기화 증거는
[버전 고정 문서](https://github.com/ParkerHwang/OpenSocrates/blob/v1.4.0/docs/reinstall-cycle-acceptance.ko.md)에
보존하며 Go 후보의 활성 절차가 아닙니다.

macOS ARM64 또는 Windows x64에서 승인된 정확한 커밋 자산과 검증한 소유
프로필·범위를 사용합니다. 이전 목록·상태·등록·활성/신뢰·예약 소유권을 비공개
복구 상태로 보존합니다. 안전한 제거가 가능하고 필요한 호스트 종료는 사용자가
했는지 확인합니다. 실제 상태를 바꾸는 제거·재설치는 명시적 승인이 필요합니다.

네이티브 관리자의 `remove --host <profile>`에 동일 범위를 지정하고 소유
등록·파일 제거를 확인한 뒤 `install --host <profile> --package
<absolute-bundle>`로 재설치해 목록·상태·등록을 확인합니다. Antigravity는 같은
작업공간·전역을 선택합니다. 일반 제거를 purge·신뢰 초기화·npm 삭제로 해석하지
않습니다. 관련 없는 파일·호스트 설정/기록/인증·미확인 데이터·비활성 상태를
보존합니다.

선택적 예약 제어로 단일 소유자를 유지합니다. 중단 작업은 원래 저널과
`recover --transaction <ID>`로 복구하고 잠금·백업·체크포인트를 지우고 다시
시작하지 않습니다. 수정·다른 소유 교체 파일이나 미검증 복구 바이트는 안전한
충돌·사용 불가 결과이며 완료를 꾸미지 않습니다.

커밋·자산 해시·네이티브 환경·명령/결과·롤백/제거/재설치·예약·범주형 호스트
관찰을 기록합니다. 등록·훅 검토·새 세션 불러오기·실제 전달·읽기/적용·유용성을
구분합니다. 원문·대화·인증·경로는 공개하지 않습니다. 운영 서명·새 기기·
Windows/Mac 네이티브·실제 호스트 누락을 명시합니다. 새 기기 안내의 격리 Go
fixture는 이 실제 재설치 증거를 대신하지 못합니다.
