# Coding-specialist primary routing

Status: implementation and bounded qualification in progress on the unpublished
v1.5.0 candidate. This authorized direction supersedes the earlier discussion's
assumption that coding support must always wrap a general method. General reasoning
and EN/KO collaboration remain foundational. No publication or active-install change
is authorized by this specification.

## Mechanism and source

The separately versioned static library at
`plugin-src/shared/coding-specialists/v0.1.1/` supplies a router and complete
contracts, transitions and ownership procedures in EN/KO/zh-CN. Relevant software
decisions may use one as primary, with no general-method prerequisite. Mechanical,
settled and adequately handled work needs no extra procedure. Complements require
a distinct unresolved question; current general-route empty selection stays valid.

The external v0.1.0 authoring package is preserved. v0.1.1 clarifies Korean
deterministic calculation and abnormal-termination durability, moves the selection
discriminator into each runtime router, and preserves unaffected contracts while
propagating an explicitly approved contract change. A new author counterexample
is a desk review, not an outcome task. Package-agnostic status wording distinguishes
static delivery from native canonical registration. Author reports and worked
answers are not automatic runtime payload.

Keep the existing 48 canonical procedures, content revision, schemas, SQLite
migration/deletion contracts and task-based assistance fallback. All current model
profiles remain unpromoted candidates. Neither specialist IDs nor their hashes
enter native `select`/`acknowledge` or canonical grounding; native general locales
remain EN/KO. Chinese support is limited to these static specialist files. Full
Chinese general methods, native request support and universal language-effect
equivalence are not claimed.

## Integration

The controller, EN/KO general and assistance guides, and default discovery entry
agree on the separate routes. The generator copies the versioned library and
includes every member in the package release inventory. Static library content is
read by the agent; no native semantic compiler or new specialist command is added.
The native binary still needs a rebuild for the changed entry text. Specialist
files need not be embedded in the executable because no native consumer reads them.
Schema/documentation bytes with existing native consumers remain verified inside
and outside the runtime.

`library.json` binds twelve complete prompt files and explicitly describes static
locales, provisional status and lack of native registration. Source mutation tests
reject missing/altered files and false registration metadata. Native tests reject
specialist IDs and zh-CN without broadening the general catalog. These tests prove
mechanical boundaries, not correct semantic routing or useful model behavior.

## Practical evidence boundaries

The [implementation plan](../../evals/v1.5/coding-specialists/revision-v1/PLAN.md)
fixes the bounded scope. The exact Luna/max access probe completed on bundled
`codex-cli 0.158.0-alpha.2`. The [direct-v2 pilot](../../evals/v1.5/coding-specialists/direct-v2/README.md)
has three new matched existing-code pairs and one same-arm follow-up pair. It
compares complete directly delivered current guides against complete specialists;
it does not test installation or discovery. The unexecuted direct-v1 freeze is
preserved after a pre-call import-alias oracle correction.

A separately frozen integrated package pilot will cover needed specialist,
no-intervention, general, mixed/scoped-blocker and static Chinese delivery. It must
inspect actual artifacts and public actions, and keep hooks-off file/command access
separate from normal hook activation. Every attempt/failure/continuation counts;
missing usage is null. There is no model wall-clock cutoff or stronger-model repair
inside Luna treatment. Human review and independent backend echo remain unavailable.

No broad matrix, power calculation, model-profile promotion or claim of internal
logit alignment is required. Correctness, useful reuse, state/output consistency,
follow-up compatibility and full available work are the practical observations.
Report ties and regressions and narrow a harmful/unhelpful intervention rather than
expanding its instructions indefinitely.
