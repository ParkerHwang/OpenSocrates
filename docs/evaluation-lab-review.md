# Evaluation lab design review decisions

2026-10-15, before runtime implementation. Tracking: issue #134. Design advice,
not a measured effect or independent empirical validation. Reviewed the
[design](evaluation-lab-design.md) and [implementation contract](evaluation-lab-contract.md).

## Independent plan review

The reviewer requested four corrections. All were incorporated before delegating
runtime implementation: read-only independent-environment export merge with stable
source identities and conflict refusal; ephemeral exact-byte preview approval;
first assigned attempts as primary comparisons with retries kept diagnostic; and
frozen action fields, enums, payload layout, module interfaces and file ownership.

## Actual Claude consultation

The existing owner-authorized Claude conversation received one consolidated review
request for this implementation, keeping additional Claude usage bounded. We read
the visible final answer, without opening reasoning or retaining screenshots or
the raw conversation. Accepted suggestions:

* A/B absence of OpenSocrates is a start condition, not just a C installation check.
* First use defaults to one host/OS/model cell. Other five remain available.
* Define final deliverable boundaries before generation, including an appropriate
  user-facing note when that is part of the requested work.
* Fixed clarification cards and counts avoid uncontrolled extra information.
* Recommend delayed batch review and record recognition; same operator/reviewer
  remains partial blinding.
* Include conflicting synthetic histories and a judgment/priority case. A fixed
  final artifact cannot establish natural multi-turn collaboration effects.

## Actual Gemini consultation

The existing owner-authorized Gemini web conversation was used only as a design
consultant; it is not the Antigravity test host. One consolidated review request.
Accepted: multi-document context/conflict/noise where appropriate; optional human
edit capture; opaque trial folders; A/B negative preflight; model/effort
confirmation; explicit result boundaries and fixed reply cards.

Two suggestions were deliberately not adopted:

* A marker at a document's end cannot prove a complete read or method application.
  Do not alter pinned skill content, parse a marker into proof, or strip genuine
  answer content to improve blinding. Unknown remains visible; attribution is not
  application evidence.
* Account-scoped Cowork skills cannot be made workspace-local by lab staging.
  The operator follows the real account UI and verifies A/B absence. The kit does
  not promise hidden setup or a clean baseline from a fresh folder.

## Acceptance and evidence limits

The authored eight-case pack remains a candidate synthetic sample until the owner
confirms its practical realism. Two calibration tasks check process; discovery
and fresh confirmation are separate. No actor calls have been made by the lab.
No favorable preference, reduced rework, clean OS qualification, live host
delivery, token savings or general office-user effect is established by review.
Runtime implementation is authorized; GUI qualification and human judgments are
the next experimental stage, not prerequisites for delivering the reusable kit.
