# 다른 과제 묶음으로 실험실 재사용하기

[English](evaluation-lab-casepacks.md) · [사용 안내](evaluation-lab.ko.md)

과제 묶음은 공개해도 되는 가상의 사무업무 자료입니다. 새 실험에서 기존 답변을
이어받거나 비교 도중 조건을 바꾸지 않고, 설정·최종 답변 수집·사람의 평가 흐름을
재사용합니다. 이 버전은 실제 비공개 업무 폴더, 대화, 화면이나 고객 기록을
가져오는 도구가 아닙니다.

## 다음 실험에서 확인할 것

실제로 필요한 판단부터 씁니다. 예를 들어 “변경 사항을 왜곡하지 않고 상대와의
관계도 해치지 않으면서 이 안내를 보낼 수 있는가?”입니다. 상황, 대상 독자,
전달할 메시지, 필요한 참조와 상충하는 조건을 함께 담습니다. 원하는 효과가
이 전체에 걸쳐 있다면 문장을 매끄럽게 쓰는 문제로 축소하지 않습니다.

처음 두 과제로 진행 절차를 확인하고, 다양한 발견용 과제로 사람에게 무엇이
중요한지 살핍니다. 불필요하게 장황해지는 문제를 드러낼 단순 과제도 넣습니다.
사람이 승인한 기준을 고정한 뒤 쓸 확인용 예시는 별도로 남깁니다. 제공된
2 + 4 + 2 구성은 시작용 표본이며 통계적으로 필요한 표본 수를 뜻하지 않습니다.
사용자가 확인용 예시를 읽었거나 설계에 참여했다면 그 한계를 기록합니다.
파일 이름을 바꾼다고 처음 접하는 과제가 되지는 않습니다.

A·B·C에 같은 과제와 자료를 제공합니다. 공통 분량·형식 요구는 일반 프롬프트에
넣습니다. B의 짧은 지시는 모든 과제에서 같고 답변을 보기 전에 승인합니다.
과제에 맞춰 B를 조정하거나 C에 유리하도록 약하게 만들지 않습니다. C에만 방법
이름이나 더 유용한 맥락을 주지 않습니다. 현재 실험은 고정된 입력을 비교합니다.
정해진 후속 대화나 자연스러운 장기 대화는 별도 연구로 설계합니다.

## 파일 작성

소스 저장소의 `evals/office-work-v1/`을 복사해 새 과제 폴더를 만듭니다. 별도의
`id` 또는 새 `version`을 정합니다. `pack.json`과 여기에 열거한 Markdown 자료를
함께 둡니다. UTF-8과 과제 폴더 내부의 상대 경로를 사용합니다. 상위 경로, 외부
파일 참조, 심볼릭 링크, 실시간 웹 자료나 실행 파일을 사용하지 않습니다.

과제 묶음의 필드는 다음과 같습니다.

| 필드 | 의미 |
| --- | --- |
| `schema` | 정확히 `opensocrates.office-pack/1`입니다. |
| `id`, `version` | 작성한 과제 묶음을 구분하는 공개 식별자입니다. |
| `public_synthetic` | 정확히 `true`입니다. 작성자의 선언이며 자동 익명화 기능이 아닙니다. |
| `b_instruction.en`, `.ko` | 의미가 일치하는 공통 B 지시입니다. |
| `cases` | 고유 ID와 단계를 가진 과제 목록입니다. |

각 과제에는 다음 필드가 있습니다.

| 필드 | 작성할 내용 |
| --- | --- |
| `id`, `family`, `title` | 고정 ID, 업무 유형, 사람이 읽을 제목입니다. |
| `phase` | `calibration`, `discovery`, `confirmation` 중 하나입니다. |
| `locale` | 과제 언어입니다. 초기 묶음은 `ko`를 사용합니다. |
| `prompt` | 실행에 필요한 맥락을 담은 공통 일반 요청입니다. |
| `deliverable` | 답변 생성 전에 정하는 최종 결과물의 범위입니다. |
| `materials` | 모든 조건에 같은 근거를 제공하는 상대 `.md` 파일 경로입니다. |
| `clarification_reply` | 앱이 추가 질문을 할 때 사용할 고정 응답 카드입니다. |
| `evaluator_checks` | 첫 판단 이후 평가자에게 공개할 사실·참조 확인 항목입니다. |

이름, 사건, 금액과 참조를 모두 명시적인 가상 내용으로 만듭니다. 일부를 가렸더라도
실제 주소, 계정, 서신이나 독점 자료를 사용하지 않습니다. 필요한 이전 상황의
요약도 포함해 자료만으로 과제를 수행할 수 있게 합니다. 언어를 추가할 때는
의미를 맞춥니다. 실행용 자료 안에 모범 답변, 평가 기준이나 특정 조건에만 해당하는
지시를 넣지 않습니다.

사실 확인 항목은 승인 전인 변경, 서로 다른 날짜, 근거 없는 주장, 다른 독자를
위한 참조처럼 구체적인 제약을 다룹니다. 실용적인 선택 이후 확인할 보조 항목이며,
특정 말투를 강요하거나 사람의 판단을 대신하는 정답표가 아닙니다.

## 실행 전에 고정하기

답변을 모으기 전에 과제 전체가 현실적인지, 공개 가능한 가상 자료인지, 조건별
입력이 같은지, 공통 B 지시가 적절한지 확인합니다. 새 데이터 폴더로 시작합니다.

```text
python tools/evaluation_lab.py --pack PATH_TO_PACK --data PATH_TO_NEW_STUDY
```

압축을 푼 휴대용 도구에서는 대신 `python start-lab.py --pack PATH_TO_PACK
--data PATH_TO_NEW_STUDY`를 사용합니다. 작성한 과제 폴더를 유지하면 실험실이
고정된 입력을 새 실험으로 복사합니다. 기본 ZIP 빌더는 초기 과제 묶음을 포함하므로
다른 묶음은 이 명시적인 실행 옵션으로 지정합니다.

실험실은 해당 실험의 과제와 배정 식별자를 고정합니다. 원본 묶음을 나중에
수정해도 진행 중인 실험의 입력은 바뀌지 않아야 합니다. 결과를 본 뒤 실패한
과제를 교체하거나 지시를 바꾸는 대신, 바뀐 내용에 새 버전과 새 실험을 씁니다.
배정용 시드는 순서에만 영향을 주며 모델의 무작위성을 제어하지 않습니다.

확인 단계에 들어가기 전에 사람이 승인한 기준과 앞선 발견용 실험의 식별자를
고정합니다. 확인용 과제를 실행하기 전에 무엇을 배웠는지 남기는 절차이지,
그 예시를 이전에 보지 않았다는 증명은 아닙니다. 첫 시도의 결과, 실패, 조건
인식과 탐색용 환경 선언을 보고서에 유지합니다. 독립 환경의 결과를 읽기 전용
병합기로 합치려면 내보낸 식별자들이 일치해야 합니다.

## 작은 파일럿 이후 바꿀 것

먼저 평소 체감한 차이가 비교에서도 재현됐는지 사람에게 확인합니다. 그렇지
않다면 빠진 상황, 맥락이나 상호작용을 기록하고 다음 과제에 반영합니다. 짧은
첫 느낌이나 나중에 직접 고친 결과물만으로도, 성급하게 점수표를 강요하지 않고
수정 방향을 찾을 수 있습니다. 첫 파일럿을 보존하고 다음 버전은 수정한 연구로
표시합니다.

유용한 차이가 재현되면 폭넓은 효과를 말하기 전에 업무 범위를 넓힙니다. 새롭고
다양한 과제에서도 B와 C가 비슷하면 그 설정에서 추가 효용은 미확인입니다.
설정 부담이나 반복 가능성을 따로 관찰하지 않고 이를 편리함의 효과로 바꿔
부르지 않습니다. OS·앱·모델 조합과 평가 대상 사람에 맞는 증거가 각각 필요합니다.
