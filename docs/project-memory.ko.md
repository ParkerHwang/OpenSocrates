# v1.5.0 릴리스 후보의 프로젝트 연속성

[English](project-memory.md)

OpenSocrates는 프로젝트의 공개 결정과 체크포인트를 제한된 범위에서 보관해
새 Codex 세션에서도 작업을 이어갈 수 있게 합니다. Git 프로젝트와 일반 로컬
텍스트 폴더를 지원합니다. 메모리는 선택 기능이며 처음에는 꺼져 있습니다.
플러그인을 설치하거나 업데이트해도 프로젝트가 자동으로 등록되지는 않습니다.

평소에는 Codex에 OpenSocrates를 사용해 작업해 달라고 요청하면 됩니다. 단순
편집에 별도의 사고 절차나 메모리 조회를 할 필요는 없습니다. 코드를 바꿀 때는
기존 구현, 영향을 받는 호출부, 필요한 검증을 살펴보도록 안내합니다. 기본
지원은 작업 특성에 맞춰 동작하며, 실험용 모델 프로필을 몰래 켜거나 사용자가
선택한 모델과 사고 수준을 바꾸지 않습니다.

## 원하는 프로젝트만 등록하기

선택한 프로젝트의 OpenSocrates 메모리 등록 내용을 먼저 보여 달라고 요청하세요.
대상 폴더, 보관할 정보, 제외 항목, 조회·비활성화·삭제 방법을 확인한 뒤 필요한
범위를 승인하면 됩니다. 이미 명시적으로 허용한 범위라면 같은 권한을 반복해서
확인할 필요는 없습니다.

등록한 뒤에는 다음과 같이 요청할 수 있습니다.

- “승인된 프로젝트 결정을 바탕으로 이어서 작업하되, 예전 구현 정보를 쓰기
  전에 현재 파일을 확인해 줘.”
- “수용 인원 수치가 잘못됐어. 그 사실만 잊고 접근성 조건과 다른 결정은 유지해 줘.”
- “이 질문에 답한 뒤 원래 작업을 계속해 줘. 다음 행동에 영향을 주는 답이
  빠졌을 때만 질문해 줘.”

세부 메모리 명령은 설치된 안내에 따라 에이전트가 처리합니다. 현재 동작은 현재
소스가 기준이고, 승인된 레코드는 출처가 표시된 의도입니다. 제안은 저장됐다는
이유만으로 승인된 결정이 되지 않습니다. 메모리가 없다고 사실을 만들어내거나
새 권한을 얻는 것도 아닙니다. 작은 프로젝트에는 잘 관리한 프로젝트 노트도
실용적인 대안입니다.

## 확인하고 관리하기

등록된 작업에서는 에이전트가 중요한 단계의 진행 상황을 저장하고 현재 버전을
확인해 갱신한 뒤 새 세션에서 이어갈 수 있습니다. 설치된
[체크포인트 안내](../plugin-src/shared/assistance/checkpoint.ko.md)에 요청 전체와
오류 복구 흐름이 있습니다. 체크포인트는 보고된 진행 상황이며 승인된 의도나
작업 실행의 네이티브 증명이 아닙니다. 현재 소스의 사실은 계속 확인해야 합니다.

저장된 레코드를 조회하거나 내보내 달라고 요청할 수 있습니다. 비활성화하면
일반적인 문맥 사용과 기록은 중단되고 관리 기능은 유지됩니다. 레코드를 삭제하면
해당 레코드와 관리 대상 이력·백업이 제거됩니다. 없앨 사실과 유지할 의도가 섞여
있다면 유지할 의도를 먼저 보존하고 승인해야 합니다. 대체는 이력을 남기므로
잊기와 다릅니다. 프로젝트 전체 삭제도 그 프로젝트의 소유 저장소만 제거하며
소스 파일이나 다른 프로젝트를 삭제하지 않습니다.

보관 가능한 내용은 제한된 공개 결정, 작업 상태, 상대 경로의 자료 참조, 해시와
명시된 색인 메타데이터입니다. 원문 프롬프트·대화·소스 파일 복사본·인증 정보·
스크린샷·비공개 사고 과정은 보관하지 않습니다. 논리적 삭제가 SSD, 운영체제
백업이나 사용자가 별도로 내보낸 사본의 포렌식 삭제까지 보장하지는 않습니다.
일반 업데이트나 제거는 기본적으로 프로젝트 메모리를 보존합니다.

훅을 사용할 수 없거나 아직 신뢰하지 않았다면 설치된 컨트롤러 스킬을 명시적으로
사용해 달라고 요청하세요. 메모리를 사용할 수 없다면 기억한 척하지 않고 한계를
알린 뒤, 독립적으로 할 수 있는 허용된 작업을 이어가야 합니다.

이 브랜치는 공개 배포판이 아닌 릴리스 후보입니다. 정확한 지원 범위와 한계는
[후보 인계 문서](v1.5.0/RELEASE_CANDIDATE.md),
[제한된 비교](../evals/v1.5/practical/README.md),
[기술 프로토콜](project-memory-development.md)을 참고하세요.
