# 결정 지점 조회와 이전 안내

상태: v1.3.0 릴리스 작업이며 콘텐츠 revision 3, 라우터 1.1.0입니다. 방법 절차 본문은 v1.2.1 원문을 유지합니다.
실험용 콘텐츠 revision 2, 방법 변형, 언어 수정안과 Compact 정책을 승격하지
않았습니다. Method ID는 바뀌지 않습니다.

## 같은 요청 안에서 사용하기

목표, 권한, 제약과 완료 조건을 유지합니다. 근거·대안·가정·중대한 위험이 달라져
판단이 필요할 때 컨트롤러를 사용합니다. 사용자의 다음 메시지를 기다리지 않습니다.
컨트롤러는 언어별 안내, 간결한 탐색 메타데이터와 선택한 정본 전체를 연결합니다.
기계적 단계에는 방법을 읽지 않습니다. 앞선 결정에 영향을 주는 제약은 먼저 읽습니다.

패키지의 런타임과 셸을 사용할 수 있는 Claude/Codex에서는 네이티브 `catalog`와
`select`를 먼저 사용합니다. 필요한 입력이 없다는 사실도 닫힌 feature에 넣고,
다른 질문에는 다른 결정 식별자를 사용하며, 사용자가 방법을 명시하지 않으면
`explicit_method`는 null로 둡니다. 적합한 방법이 0개인 것은 정상 결과이므로 파일
읽기로 적용 가능성 검사를 우회하지 않습니다. 런타임·셸이 없거나 실패한 경우에만
같은 금기와 전역 제약을 유지하며 정본 파일 경로를 사용합니다. 다른 호스트는 파일
경로를 유지합니다. 이는 호스트 행동 안내이며, 선택기가 feature 분류나 자유 형식
결과의 의미·실제 방법 적용을 검증한다는 뜻은 아닙니다.

여러 질문의 공개 결과에서는 결론, 부족한 입력과 재검토 근거를 각각 유지하되
사용자가 지정한 형식을 따릅니다. 명시적인 의존관계가 뒷받침할 때만 조건을
공유합니다. 적용 불가를 확인하기 위해 읽은 방법의 출력 요건을 다른 질문으로
옮기거나 그 방법을 적용했다고 인용하지 않습니다.

설치된 Claude/Codex 패키지에서는 다음 명령을 사용할 수 있습니다.

```sh
cat skills/opensocrates/references/decision/request.json | ./bin/launch.sh decision codex
```

예제의 닫힌 feature와 context 값을 현재 판단에 맞게 바꿉니다. 라우팅 필드에
자유로운 지침이나 경로를 넣지 않습니다. Claude 패키지는 `claude`를 사용합니다.
소스 체크아웃에서는 다음과 같이 임시 세션을 유지할 수 있습니다.

```sh
PYTHONPATH=src .venv/bin/python -m opensocrates decision --stream
```

입력은 줄마다 JSON 객체 하나입니다. `select`는 기존 routing feature 스키마와
주방법·선택적 보완 방법 계약을 사용하므로 한 판단에는 0~2개를 반환합니다.
서로 다른 판단이 여러 개면 같은 요청 안에서 이어서 평가할 수 있습니다. 파일 조회
경로는 필요한 방법 수만큼 읽을 수 있습니다. 도구 호출마다 새 판단을 만들지 않습니다.
`catalog`와 `locale`은 메타데이터를 반환하고, `reset`은 임시 가용성 신고를 지웁니다.
프로세스 종료나 중단에도 신고 상태는 사라집니다.

출력된 내용을 실제로 읽은 뒤 `acknowledge`에 `context`, `epoch`, `digests`를
전달할 수 있습니다. digest는 해당 프로세스가 출력한 정확한 방법·언어·revision·본문을
식별합니다. 결과는 `agent_reported`이며 인증된 호스트 증거가 아닙니다. `applied`는
계속 `unverified`입니다. 변하지 않은 선택과 읽기 완료 신고가 있는 정본은 재사용합니다.
신고가 없으면 관측하지 않은 읽기를 주장하지 않고 다시 출력합니다. 별도 모델 선택기를
호출하지 않습니다.

에이전트나 인계마다 새 무작위 소문자 16진수 32자리 context를 사용합니다. 압축 후에는
epoch를 올리고 필요한 내용을 다시 읽습니다. reset은 이미 소비한 문맥 토큰을 제거하지
않습니다. 공개 결정, 근거 참조, 미해결 가정과 남은 일만 기존 작업 기록에 전달합니다.
추론 기록을 저장하지 않습니다. 결정 프로세스는 파일 저장, 네트워크, 인증이나 원격
통계 전송을 시작하지 않습니다.

단발 모드는 보기 좋게 여러 줄로 작성한 JSON을 포함해 정확히 하나의 JSON 문서를
EOF까지 읽습니다. 문서 전체에 16,384자 제한이 그대로 적용됩니다. `--stream`은
계약이 다릅니다. 줄마다 완결된 JSON 객체 하나를 받고 같은 줄별 제한을 유지하며,
하나의 임시 세션에서 여러 응답을 낼 수 있습니다. 단발 모드에 JSON 문서를 여러 개
넣으면 stream으로 암묵 변환하지 않고 잘못된 입력으로 처리합니다.

전환을 모두 알아낼 수 없습니다. v1.3 기본 제출·압축 훅은 상세 방법 없이 짧은 조회 안내만 전달합니다.
초기 후보를 만들지 않으므로 버린 후보 때문에 Stop이 읽기를 요구하지 않습니다.
기존 selector와 영수증 경로는 호환 어댑터로 보존하며 새 기본 경로의 증거와 구분합니다. 메타데이터는 접지 증거가 아닙니다. 요청된 결과물을 완성하고
정본의 근거, 중단, 공개 출력과 접지 계약을 유지합니다. 조회 실패로 전역 제약이
사라지지는 않습니다.

Codex는 기존에 메서드 48개와 컨트롤러·rigor·trace를 광고했습니다. 이 후보에서는
뒤의 3개만 발견 목록에 둡니다. `opensocrates`와 기존 메서드 이름을 함께 호출하거나
decision 명령을 사용하세요. 이전 경로의 대응 참조는
`skills/opensocrates/references/methods/<id>.md`, 전체 정본은
`skills/opensocrates/references/decision/methods/<locale>/<id>.md`입니다. ID는 유지됩니다.
[현재 공식 스킬 문서](https://learn.chatgpt.com/docs/build-skills)는 초기 목록 예산을
문맥의 2%, 문맥 크기를 모르면 8,000자로 설명하며 축약·생략 가능성을 밝힙니다.
파일 수만으로 실제 호스트에서 발견됐다고 주장하지 않습니다.

## 로컬 준비와 복구

`make bootstrap`, `make generate`와 `CONTRIBUTING.md`의 전체 검사를 실행합니다.
`make release-check`는 로컬 네이티브 패키지를 만들며 활성 호스트에 설치하지 않습니다.
새 버전의 Claude Chat 증거가 없으면 출시 검사는 실패로 유지합니다. 별도 Mac의
설치 검증과 독립적인 held-out 품질 평가는 남은 출시 조건입니다.
원래 워크트리는 보존했고 새 브랜치를 분리했습니다. 작업 중 활성 호스트를 교체하지
말고 별도 승인된 프로필이나 이후 정상 설치 트랜잭션을 사용하세요. 기존 rollback
계약은 유지합니다.

## 설치 런처의 세션과 훅 정리 범위

설치된 런처는 `./bin/launch.sh decision codex --stream`도 지원합니다. Claude는
호스트 값을 `claude`로 바꿉니다. 같은 프로세스를 유지해야 가용성 신고를 재사용할
수 있습니다. 단발 호출을 반복하면 매번 상태가 초기화됩니다.

기본 조회 안내 훅은 전체 콘텐츠나 저장 서비스를 구성하지 않고 설치 키·제품 데이터
트리를 새로 만들지 않습니다. 이전 버전의 정리를 위해 안전한 기존 소유자 전용 키만
읽고, 기존 24시간 만료 정리와 세션 정리를 유지합니다. 루트가 없거나 안전하지 않거나
읽기 전용이면 정리를 건너뛰고 정상 작업은 계속하며 루트를 생성·복구하지 않습니다.
제품 데이터 루트는 OS 홈을 기준으로 하므로 CODEX_HOME만으로 시험을 격리할 수
없습니다. 훅 시험 전에 OS 홈, 임시 디렉터리와 워크스페이스의 산출물 경계를 모두
확인해야 합니다. 기존 control·diagnostic 명령의 저장 계약은 유지합니다.
