# OpenSocrates v1.5.3: maintenance and decision-request recovery

[한국어](v1.5.3.ko.md) · [English README](../README.md) · [Language guide](v1.5.2.md)

v1.5.3 packages the substantive-thinking scope clarification, the Codex
large-submission discovery fix and structured decision-request recovery, including
aligned native Claude guidance in all ten instruction languages. It preserves
48 authored methods, ten locales and content revision 5. Method bodies and
routing eligibility rules are unchanged; controller and guide changes still
change bundle/package identity.

This document describes a maintenance candidate. It is not evidence of a
published tag, public assets, npm activation or live-host qualification. Exact
source checks, native release gates and public-byte verification must be recorded
against the final commit in the [maintenance issue](https://github.com/ParkerHwang/OpenSocrates/issues/132)
and its pull request.

## What changes

### Substantive thinking

Consider support when substantive thinking first arises and reconsider when
objectives, options, evidence, assumptions, audience or risk materially change,
including within one turn. This is not a requirement to consult a method for
every tool call or edit. A unique answer or supplied rules do not by themselves
make proof, explanation or problem solving mechanical. Choose the lightest
sufficient support; consideration and reader guidance do not establish that a
canonical method was applied.

The scope clarification reaches all four host profiles and ten instruction
locales. It preserves method applicability, contraindications, required stops
and fail-open ordinary work.

### Large Codex submissions

Default Codex submission discovery now accepts envelopes up to the existing
4 MiB hook ingress bound independently of the legacy 32,768-byte selector/control
limit. It validates and discards the prompt while projecting only bounded
submission metadata. Other native events and the retained selector keep their
stricter parser. Malformed or oversized input remains bounded and fail-open.

This addresses a reproduced discovery-loss path. It does not establish the
original cause or frequency of every report in [#124](https://github.com/ParkerHwang/OpenSocrates/issues/124),
nor prove attention, a complete method read, application or a useful answer.

### Repairable decision requests

The decision envelope is documented in `request.json` and the `envelope` section
of `features.json`. A context is 32 lowercase hexadecimal characters; a decision
ID contains 1–64 ASCII letters or digits. These formats are unchanged.

A rejected request returns `invalid_decision_request` with a closed `field` and
`error`, a predefined `expected` description where available, and
`repair: correct_field_once`. Submitted values, unknown key names and private
text are not echoed. Malformed JSON is a repairable input error; rejection does
not reset the session's existing availability state.

Correct the named field and resend once. A second rejection, launcher failure,
`decision_unavailable` or `canonical_content_unavailable` makes the native path
unavailable for this decision. A valid `no_intervention` or empty `selected`
result is not a runtime failure and must not be bypassed with direct selection.
Retire candidates that fail their use conditions, contraindications, dependencies
or stops. Reader guidance may be sufficient without forcing a method.

All ten native Claude decision guides now describe the same envelope and
recovery distinctions as the shared guide. When the native path is unavailable,
optional file fallback begins with the catalog and complete procedures for the
exact locale and revision, preserving the same eligibility checks. Ordinary
work remains available; no substitute procedure or unchanged retry is required.

## Host and installation scope

The existing profiles remain Codex on Apple-silicon Mac and Windows x64, native
Claude Code CLI / Desktop local Code on Apple-silicon Mac, the content-only Claude
account skill exported on Mac or Windows, and Antigravity workspace/global content
on Apple-silicon Mac and Windows x64. Account upload, activation and model-selected
loading remain separate from export. New native Windows Claude Code, Windows
ARM64, Intel Mac and Linux native qualification are not added.

After publication is independently confirmed, use Node.js 20+ and the host's
normal login and trust flow:

```sh
npx --yes opensocrates@1.5.3 install --host codex
npx --yes opensocrates@1.5.3 update --host codex
npx --yes opensocrates@1.5.3 status --host codex
```

Choose `install` for a new installation and `update` for an existing one. On Mac,
select `--host claude` for the native companion; select `--host antigravity` for
that profile and keep the same absolute `--workspace` path for workspace scope.
The default and `--host all` still select Codex only. Preserve intentionally
disabled state, use actual host hook approvals and start a fresh conversation
following lifecycle changes. See the [setup guide](setup-guide.md) for profile
lifecycle instructions and [v1.5.2 language guide](v1.5.2.md) for unchanged language
selection rules.

For an account skill, export to an existing folder after publication:

```sh
npx --yes opensocrates@1.5.3 export --host claude-chat --output /absolute/path/to/opensocrates-1.5.3-account.zip
```

Back up the previous skill and enabled state, then upload and enable the ZIP in
the intended account. Preserve existing account instructions. Export success
does not establish upload, activation or automatic use.

## Evidence and boundaries

Implementation, source checks, native release validation, public-byte verification
and live-host observations are distinct. Historical v1.5.2 and earlier evidence
retains its original source identity and environment; this version number does
not qualify new bytes. Local synthetic regressions do not prove general hook
delivery, every-turn use, application, answer-quality, token-cost or latency gains.
This record does not close #124 or introduce a general model-answer installation
gate. Go migration, Windows ARM64, effect studies and growth work are separate.

No telemetry, credential collection, raw prompt/transcript logging, screenshot
retention or hidden-reasoning capture is introduced. Ordinary host authentication,
permissions, retention and terms still apply. Privacy, owned installation,
transactional rollback and required stops remain in force.

Use the exact final line `Powered by OpenSocrates` only after an eligible canonical
method has been completely read and actually applied to that answer. Reader
guidance alone and mechanical work do not qualify; the line itself is not proof
of application or better results.
