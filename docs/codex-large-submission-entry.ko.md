# 큰 입력에서 Codex 진입 안내가 누락되는 문제

[English](codex-large-submission-entry.md)

[#124](https://github.com/ParkerHwang/OpenSocrates/issues/124)의 누락에 대한
현재 가장 유력한 설명은 입력 크기로 인한 발견 안내 손실이다. 기록된 크기
패턴과 재현 가능한 파서 결함에 근거한 강한 추론이며, 과거 훅 실행의 원인이
입증된 것은 아니다. [PR #126](https://github.com/ParkerHwang/OpenSocrates/pull/126)은
범위와 문구를 별도로 개선한 변경이다. 병합됐다는 사실이 이번 원인을 입증하지는 않는다.
재현된 입력 한도 결함은 [#127](https://github.com/ParkerHwang/OpenSocrates/issues/127)에서
별도로 추적하므로 이를 수정해도 과거 사건 이슈가 자동으로 닫히지는 않는다.

## 확인한 메커니즘과 과거 증거의 한계

[v1.5.2 네이티브 파서](https://github.com/ParkerHwang/OpenSocrates/blob/v1.5.2/src/opensocrates/hosts/codex/native.py)는
`PostToolUse` 이외의 이벤트에서 32,768바이트를 초과하는 봉투를 JSON 해석 전에
거부한다. 기본 결정 시점 어댑터도 이 파서를 거친다. 제출 시 발견 안내에는
프롬프트 내용이 필요하지 않은데도 그렇다. 훅 입구는 최대 4 MiB를 받으므로,
두 한도 사이의 유효한 제출은 진입 안내 대신 빈 출력을 내고 정상 종료할 수
있다. 일반 작업을 계속하는 fail-open 동작 때문에 이 손실이 드러나지 않는다.
종료 코드 0만으로 안내 전달을 입증할 수는 없다.

조사에서는 주입한 어댑터와 메모리 전용 서비스를 사용해 합성 입력으로
`run_hook`을 호출했다. 설치된 훅을 실행하거나 제품 상태를 쓰지 않았다.
기준 경로의 결과는 다음과 같다.

| 합성 원시 JSON 봉투 | 관찰 결과 |
| --- | --- |
| 32,768바이트 | 정확한 v1.5.2 진입 문구 출력: UTF-8 1,398바이트 |
| 32,769바이트 | 정상 종료; 빈 출력 |
| 합성 프롬프트 96,732바이트를 포함한 96,822바이트 | 정상 종료; 빈 출력 |

이와 별도로 원래 호스트 기록을 제한적으로 확인해 다음을 관찰했다.

| 기록된 턴 | 저장된 프롬프트 크기 | 저장된 개발자 문맥의 진입 안내 |
| --- | --- | --- |
| 최초 전략 종합 | UTF-8 96,732바이트 | 진입 문구 표식을 찾지 못함 |
| 첫 후속 턴 | UTF-8 74바이트 | 정확한 v1.5.2 문구 1,398바이트 |
| 두 번째 후속 턴 | UTF-8 173바이트 | 동일한 문구 |

후속 진입 문구의 해시는
`e21fd108ba3e0c5960abf88da3972c2ed17982ab3ad4571c90f45e001141501e`다.
원래 세션에는 Codex CLI `0.162.0-alpha.17.2`, 모델 `gpt-6.1-sol`이 기록돼
있었다. 이는 해당 세션의 메타데이터이며 다른 호스트나 빌드에 대한 주장이
아니다. 여기에는 내용을 제거한 크기, 진입 문구 식별값, 버전 메타데이터만 보고한다.

원래 훅의 표준 입력과 실행 증거는 이번 조사에서 확보하지 못했다. 저장된
프롬프트가 실제 훅 입력과 같다고 보장할 수 없고, 저장 기록의 부재가 모든
실제 모델 입력에서의 부재를 입증하지도 않는다. 사건 후 확인한 신뢰 설정은
원래 해시가 일치했음을 입증하지 않는다. 신뢰·호스트 호출, 시간 초과, 기록
범위도 대안이나 기여 요인으로 남아 있다. 에이전트가 나중에 제시한
프로젝트와 도구의 혼동 설명은 자기평가 보고이며 독립적인 원인 증거가 아니다.

## 범위를 제한한 수정

수정 후보는 유지 중인 레거시 32 KiB 봉투 검사에 앞서 **기본
`UserPromptSubmit` 발견 경로**에 별도의 메타데이터 투영을 제공한다.
기존 4 MiB 입구 한도를 사용하고 JSON 봉투, 이벤트·실행 경로, 세션
메타데이터와 프롬프트 타입을 확인한다. 프롬프트 내용, 경로, 모델 정보와
알 수 없는 필드는 애플리케이션 코드에 넘기지 않고 버린다.

엄격한 레거시 파싱, 다른 이벤트 경로, 잔여물 정리, 잘못된 입력에 대한 빈
fail-open 응답, 고정된 진입 안내는 보존한다. 방법 선택을 시작하거나 콜백
내용을 보관하지 않으며, 훅 신뢰·사용 중인 설치를 바꾸거나 로그·텔레메트리를
추가하지 않는다. 모든 네이티브 이벤트의 한도를 일괄 확대하는 수정이 아니다.

기준 경로 재현과 수정 후보 검증은 구분해 기록한다. 연결된 변경의 최종
인계에는 정확한 커밋, 명령과 결과를 기록한다. 소스 검사만으로 실제 전달이나
답변 품질을 입증하지는 않는다.

## 기록한 소스 검증

Apple silicon macOS와 Python 3.12에서 커밋
`01d363def89cf456faeee6bec49daf67c645fa7f`에 대해 다음 통합 명령이
종료 코드 0으로 통과했다.

```sh
make bootstrap format-check lint generated-check content-check adjudication-check docs-check governance-check package-check security-scan smoke installer-check
```

여기에는 큰 입력 회귀 사례를 포함한 기본 훅 구성·진입 검사 12개, 결정 시점
검사 35개, 선택기 계약 사례 26개가 포함된다. 코드·보안 검토에서는 수정할
결함을 발견하지 못했다. 활성 설치는 변경하지 않았으며, 소스 검증이 실제
전달이나 자발적 적용을 입증하지는 않는다. 최종 PR 메타데이터와 CI 결과는
연결된 변경의 인계 기록에서 관리한다.

## 다음 최소 확인

1. 생성한 JSON과 주입한 메모리 전용 서비스로 기준 경로의 세 크기를 재현한다.
   후보에는 4 MiB 경계, 잘못된 JSON, 프롬프트·세션 타입 오류, 이벤트·실행
   경로 불일치도 추가한다. 정확한 진입 출력과 상태·내용이 보관되지 않음을 확인한다.
2. 엄격한 레거시 한도, 다른 콜백과 정리가 유지되는지 확인한다. 통합 후 저장소
   검사를 실행하고 검증한 소스 식별값을 기록한다.
3. 필요하면 별도로 적격성을 확인한 후보 패키지를 격리된 프로필에서 사용해
   짧은 합성 입력과 큰 합성 입력을 비교한다. 호스트 빌드, 신뢰, 과제 내용은
   통제한다. 지원되는 호스트 증거로 훅 호출, 진입 출력 반환, 해당 턴으로의
   전달을 구분한다. 관찰할 수 없는 단계는 실패나 성공 대신 미확인으로 남긴다.
4. 자발적 고려는 일반적인 합성 과제로 별도 평가한다. 진입 안내 전달은 방법
   선택, 전체 읽기, 적용이나 유용성을 입증하지 않는다. 명시적 알림 후의 성공은
   훅 전달이나 자발적 사용을 입증하지 않는다. 유효한 재사용에는 새 읽기가 필요하지 않다.

[공식 훅 계약](https://learn.chatgpt.com/docs/hooks)은 `UserPromptSubmit` 입력과
개발자 문맥 전달을 설명한다. 저장된 대화 기록이 완전한 전달 증거라고
보장하지는 않는다. 기존에 허용된 호스트 관찰과 일시적인 비식별 측정으로
제한된 검사를 진행할 수 있다. 비공개 대화, 내부 추론이나 새로운 영구 제품
로그는 필요하지 않다.

과거 턴의 실제 훅 입력이 작았다는 증거는 크기 설명을 약화한다. 실제 입력이
컸고 이 파서가 거부했다는 증거는 설명을 강화한다. 그 증거가 없어도 입력
크기를 통제한 후보 비교로 수정한 결함을 확인할 수 있다. 과거 원인 귀속과
일반적인 누락 빈도에 대한 주장은 계속 증거 범위 안에 한정한다.
