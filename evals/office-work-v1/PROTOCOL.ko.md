# 사례 팩 사용 절차

이 절차는 작성된 사례를 다룹니다. 평가 도구의 플랫폼 설치 안내, 영향 요소
확인, 시도 횟수 제한, 최종 결과 승인 절차도 함께 따릅니다. 사용자가 실제 앱을
실행하고 실용성을 판단합니다. 도구는 입력을 준비하고 전용 결과 폴더의 상태와
승인된 결과물을 기록합니다. AI를 대신 실행하거나 내부 사고를 살피거나 가상
수신자에게 메시지를 보내지 않습니다.

1. 첫 실행 전에 사례와 공통 고정 B 지시가 적절한지 승인합니다. 자기 업무와
   동떨어진 상황이라면 확대를 멈추고 다음 버전을 고칩니다. 답변을 본 뒤 현재
   연구의 입력을 바꾸지 않습니다.
2. 절차 확인 사례 2개로 준비, 요청한 모델·설정, 결과 수집과 전체 답변 평가를
   먼저 확인합니다. 실패한 시도도 세고 남깁니다. 절차 확인은 개선 효과의 증거가
   아닙니다.
3. 탐색 사례 4개는 A·B·C에서 같은 자료와 결과물 범위를 사용합니다. 매 시도마다
   별도의 새 대화와 배정된 분리 환경을 사용합니다. 새 폴더만으로 계정·전역 지시,
   플러그인이나 기억이 사라지지 않습니다. 분리 여부를 모르면 탐색 실행으로
   표시하며, 확인된 조건 혼입은 깨끗한 비교를 막습니다.
4. 표시된 프롬프트를 조건별로 고치지 않고 붙여 넣습니다. 앱이 과제에 관해 추가
   질문하면 그 사례의 고정 `clarification_reply`만 답합니다. 질문 횟수만 세고
   질문 내용은 수집하지 않습니다. 추가 사실이나 대화식 코칭은 제공하지 않습니다.
   다른 후속 대화는 별도로 설계한 연구에서 다룹니다.
5. 최종 본문, 상대에게 보낼 메시지, 명시한 조건과 요청된 작성자 메모를 함께
   `out/final.md`에 둡니다. 생성 전에 사례의 `deliverable`로 범위를 정합니다.
   숨겨진 사고나 도구 기록은 보관하지 않으며, 눈가림을 위해 중요한 유보 사항,
   구성이나 식별 가능한 꼬리말을 지우지 않습니다. 가상 자료로 된 최종 결과만
   미리 보고 승인합니다. 직접 붙여 넣었다면 수동 수집으로 표시합니다.
6. 가능하면 한 묶음의 실행을 마친 뒤 시간을 두고 평가합니다. AI 설명이나 사실
   목록을 보기 전에 답변 전체를 비교합니다. 답변 하나, 동률, 모두 못 씀을 고를
   수 있습니다. 첫 느낌은 선택 사항이며 “왜 좋은지 설명하기 어렵다”도 유효합니다.
   자신감, 조건을 알아봤는지, 평소의 차이가 재현됐는지를 기록합니다. 실행자는
   조건을 기억할 수 있으므로 부분 눈가림이며 이중 눈가림이나 독립 평가가 아닙니다.
7. 조건과 평가자 점검을 보기 전에 첫 판단을 고정합니다. 점검 목록은 사실과
   불확실성을 확인하는 것이며 선호 문체, 모범 답안, 개인적 쓸모를 뒤집는 점수가
   아닙니다. 이후 승인한 편집본이나 분석은 원래 답변과 첫 선호에서 구분합니다.
   마음에 들지 않는 첫 시도를 재시도로 바꾸지 않습니다.
8. 확인 사례 2개의 내용을 열기 전에 사용자가 확인한 기준과 탐색 연구 참조를
   고정합니다. 평가자가 이미 읽거나 사례를 기준에 맞춰 고치는 데 참여했다면
   새로 작성한 팩·버전을 사용하며 새 확인 사례라고 부르지 않습니다. 작성 절차만으로
   평가자의 사전 열람을 차단할 수는 없습니다.
9. 운영체제·호스트·모델·설정별 결과를 따로 보고합니다. 막힘, 실패, 미완료,
   미실행과 진단용 재시도도 포함합니다. 다른 모델의 승률을 합치거나 사용자 한
   사람의 판단을 일반 이용자 효과로 확대하지 않습니다. B와 C가 비슷하게 쓸모
   있다면 추가 프레임워크 효용은 확인되지 않은 것이며, 편의성은 별도 근거가 필요합니다.

원본은 공개 가능한 가상 사례이며, 실제 업무 대화를 수집하라는 허락이 아닙니다.
계정, 고객 문서, 실명, 인증 정보, 스크린샷, 다른 업무의 원문 프롬프트, 대화 기록,
숨겨진 추론을 넣지 않습니다. 최종 결과 승인이 제공자의 보관 정책까지 보장하지는
않습니다. 선택 메모나 편집본에도 실제 민감정보를 붙여 넣지 않습니다. 내보내기는
별도로 선택하는 로컬 작업이며 공개 업로드나 게시가 아닙니다.

과제에서 평소 느끼던 차이가 드러나지 않으면 차원별 점수를 강요하지 않고 무엇이
빠졌는지 기록합니다. 다음 사례 팩을 고치거나 자연스러운 여러 차례 대화를 별도로
설계합니다. 절차를 모두 마쳤거나 여러 AI 조언자가 동의했다는 이유로 효과를
주장하지 않습니다.
