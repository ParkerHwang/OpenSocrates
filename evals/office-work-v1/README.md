# Office work case pack v1

This pack supplies eight newly authored, fictional Korean office tasks for the
local evaluation lab. Every organization, person, event, number and message in the
materials is invented. There are no real recipients, accounts, private documents,
external references or actions to perform. `public_synthetic: true` describes
what was authored; it does **not** mean the owner has approved the cases as a fair
representation of their work. Operator preflight must confirm that approval.

The question is whether a whole answer is useful in its situation: intended
message, reader, relationship, selected content, references, structure and next
work together. This pack does not treat grammatical polish as the whole effect,
prescribe a preferred writing style, or assume OpenSocrates will win.

## Inventory

| ID | Phase | Situation |
| --- | --- | --- |
| `cal-room-change` | Calibration | Tell colleagues that a room changed while the session time stays fixed. |
| `cal-project-status` | Calibration | Give an absent manager a progress update without confusing review with release. |
| `dis-simple-notice` | Discovery | Write a one-line printer status reply; a deliberately simple negative control. |
| `dis-conflicting-updates` | Discovery | Reconcile old plans, completed files and newly confirmed store distribution. |
| `dis-relational-decline` | Discovery | Decline a free collaboration request while preserving an established relationship and the author's limits. |
| `dis-send-priority` | Discovery | Choose a safe immediate partner response and manager request from incomplete launch information. |
| `confirm-archive-intake` | Confirmation | Answer a new donor with a personal deadline and conditional intake availability. |
| `confirm-expo-scope` | Confirmation | Help sales invite customers using confirmed demonstration scope and unresolved product dates. |

Two calibration cases check setup, collection and review. They do not establish an
effect or freeze a quality rubric. Four discovery cases supply different types of
work, including a case where added analysis may impose a cost. The two confirmation
examples introduce independent facts and organizations. They are fresh holdouts
only if the reviewer has not read them or used them to adjust criteria. Reading
this inventory does not reveal the underlying facts, but reading their materials
does. Do not treat source availability as an access-control guarantee.

## Pack contract

`pack.json` is `opensocrates.office-pack/1`, pack `office-work-v1`, version
`1.0.0`. It contains one fixed four-sentence B instruction in English and Korean,
eight cases, and evaluator-only fact checks. Each case points only to its listed
relative Markdown materials. Actor preparation must copy those materials and the
case prompt/deliverable; it must not copy this README, protocol, other cases,
`pack.json`, condition ledgers or evaluator checks. The engine supplies the common
outbox instructions separately. Only the actor's dedicated directory is granted
to the host; directory separation itself is not an operating-system sandbox.

All three conditions use identical task text, listed materials, clarification
reply and deliverable boundary. B adds the same fixed instruction for every case.
C uses the pinned supported content profile; no case tells it which method to use.
The bilingual B texts have the same meaning. Initial task and material language is
Korean; this pack does not claim multilingual outcome evidence.

No model runs, owner preferences, human judgments or effect measurements are
included. These cases were authored after the lab design; they were not selected
because a condition already produced a favorable answer. A change to case content,
B instruction or evaluator facts requires a new version/hash and a new frozen study
identity. Never edit an active study's frozen inputs to improve its results.
