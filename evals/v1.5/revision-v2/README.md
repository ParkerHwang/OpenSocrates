# Structural revision usability boundary

Two explicitly guided fresh sessions, English then Korean, on exactly Luna medium.
This checks the new installed documentation, scoped completion and memory interfaces.
It is not a baseline comparison, independent human review or spontaneous-discovery
test. The initial planned call is the actual account/client access check; an access
or transport failure stops the remaining lane without an unchanged retry. No stronger
model supplies outcome answers or repairs.

Before execution, commit manifest.json with hashes of all executable inputs,
prompts, fixture, source transition, rubric, client and native package members.
The fixed cap is two model invocations / 300 seconds each / no outcome retries.
Use disposable homes, profiles, installed packages and synthetic project memory.
Disable native memories/import, hooks, remote plugins/apps and subagents. Account-side
memory transfer is not proven. No global settings or active installation are changed.

The evaluation native adapter forwards unchanged requests and records operation,
schema, ID, status and digest evidence outside product memory. The separate host
reference tool fetches one declared official Python3.12 page and returns a bounded
JSONDecoder excerpt as untrusted data. It records URL/time/digest/read status, not
page bodies. It is evaluation plumbing, not a new product web-fetch service.

Freeze includes the exact domain example and expected artifact. Artifact and store
checks run after each call; the integrator reads all retained public messages for
the side answer, citations, unnecessary questions and completion claims. Missing
messages/usage stay unassessable/null. Public synthetic prompts/messages/commands,
artifacts and typed state are retained only in this declared evaluation boundary;
no raw event stream or hidden reasoning is saved. Disposable auth copies are removed.

The feedback helper preserves exact own-artifact failing request/response evidence
and marks absent evidence unassessable. It does not modify old runners or scores.
Existing backend failure packets are post-outcome evidence, not new successful repairs.

Run from the repository root:

```sh
python3 evals/v1.5/revision-v2/feedback.py
python3 evals/v1.5/revision-v2/runner.py preflight --manifest-sha256 <frozen-sha256>
python3 evals/v1.5/revision-v2/runner.py execute --manifest-sha256 <frozen-sha256>
```

Execution uses exclusive files/directories and cannot overwrite an old attempt.
Any diagnosed harness repair requires a separately named boundary before further
outcome calls. There is no automatic call expansion or favorable-result retry.
