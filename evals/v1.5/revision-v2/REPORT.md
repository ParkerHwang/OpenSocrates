## Failure diagnosis and bounded repair

English guessed three invalid assistance envelopes/enums before reading the
schemas and submitting a valid request. Korean also mixed invalid Python/JSON
syntax, guessed assistance statuses (`completed`/`complete`) and a `permission`
kind, and finally sent `prepare` using memory schema1.0. That operation requires
schema1.1, so the runtime correctly rejected it. The original guide described the
revision but did not provide a complete dedicated memory1.1 request example.
Assistance failures also lacked actionable field/allowed-value details. This is
caller behavior plus an interface/guidance recovery weakness, not loss of a valid
checkpoint or a reason to relax the closed contract.

English attempted read-only export and the evaluation adapter rejected it. That
adapter admitted only its specified operation list; the product export operation
was not broken. Inspection, recall and independent persisted-state reads still
verified deletion and retained intent. Korean's `--help`/malformed-JSON probes
account for other adapter rejections. No missing native response is counted as OK.

The next separately frozen boundary adds complete v1.1 recall/prepare examples,
assistance guide8 and safe field/version/allowed-value diagnostics. It also allows
the existing read-only export in its evaluation adapter. One targeted fresh Korean
call is authorized for that diagnosed repair; no unchanged-condition retry or
broader matrix is introduced. See [the repair boundary](../revision-v3/README.md).

## Evidence limits

This is explicit guided installed-package usability with synthetic seeded
continuity, one episode per language, hooks and native memory/import disabled.
Account-side transfer is unproven. It is not a v1.4 comparison, natural discovery
study, quality ranking, efficiency estimate or broad prompt-injection guarantee.
The current official page was fetched during each call, not fixed to historical
web bytes; URL/time/digest receipts preserve that boundary. The evaluation reader
is not a product web-fetch implementation. Native commands retain no page body.

and results preserve all attempts, public messages, native status/IDs, artifacts,
