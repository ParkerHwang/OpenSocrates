# Original-receipt usage and timing analysis

`summarize.py` is a deterministic, read-only post-call summarizer. It reads a frozen cohort manifest plus each scheduled episode's structured `response.json`, `summary.json`, start/terminal markers and privacy-safe `observation.jsonl`. It also hashes the dispatch and external-qualification indexes, per-version external receipts and continuity post-role state receipts when present. Its JSON output lists relative input paths and SHA-256 digests so every total can be checked against the same original bytes. It never opens model prompts, transcripts, candidate source contents, private oracles, or reasoning content; it never invokes a model or candidate.

The accounting unit is an actual `response.calls` role receipt. For every episode, the script compares the multiset of role assignment IDs with `kind=role` start/terminal markers and `role_event_summaries`. It separately compares `kind=native_check` markers with native version check receipts. The observer's `start_count` and `terminal_count` include **both** kinds. Thus O-gpt-6-sol-high-D has six model-role calls plus three local native checks, explaining its nine all-marker pairs without a missing-call inference. Duplicate assignment/thread identities, incomplete or mismatched markers and summary/dispatch discrepancies fail integrity instead of silently deduplicating attempts. A blocked dependency is a unit with calls **not made**, not a failed model call.

The five exposed usage fields are independently summed across every call, including invalid outputs and extra producer attempts. Every field reports known sum, complete sum (null if any call is missing), and missing-call count. Cached input is contained within input; reasoning output is contained within output. Cache-write input is kept as a separate reported attribute. The only additive combined token count is input plus output when both are reported. Failed-turn/provider-error event counts and backend-attempt null counts are kept separate from role calls. Extra producer invocations and retained versions beyond v1 are reported separately as repair evidence; neither is used to infer hidden backend retries.

Timing comes from episode start/terminal markers, child summary start/end, and role/native-check observer intervals. The report gives p50/p95, summed process time, cohort wall span and independently recomputed peak overlap. Overlapping episode durations are not added to obtain wall time. Host-load samples and frozen worker limits are not backend isolation proof. External qualification and disposable memory setup model-call reports are displayed separately and never added to subject-role usage. Helper activity outside these scoped receipts remains unobserved. There is no billed-cost or answer-quality claim.

Reproduce the completed reports with the same frozen roots:

```sh
python3 -B summarize.py --root /private/tmp/opensocrates-go-ts-o24-results-20260928 --freeze /private/tmp/opensocrates-go-ts-runner-20260928/evals/v1.5/orchestration/comparison-go-ts-v1/O24_FREEZE.json --cohort O24 --json-out O24_USAGE.json --md-out O24_USAGE.md
python3 -B summarize.py --root /private/tmp/opensocrates-go-ts-continuity8-results-20260928 --freeze /private/tmp/opensocrates-go-ts-runner-20260928/evals/v1.5/orchestration/comparison-go-ts-v1/CONTINUITY8_FREEZE.json --cohort continuity8 --json-out CONTINUITY8_USAGE.json --md-out CONTINUITY8_USAGE.md
python3 -B -m unittest -v test_failures.py
```

Outputs are exclusive-create. Use new output paths for a repeat; compare the input-inventory hash first. `--allow-incomplete --snapshot-at <UTC>` permits an explicitly dated partial cohort such as S24, with missing episodes and token fields retained as unknown. No S snapshot is included here while it remains active. Tests cover only failure and ambiguity cases: missing usage, invalid token subsets, duplicate attempt IDs, mixed role/check markers, missing terminals, mismatched summary totals and invalid intervals.

The generated `O24_USAGE.json`/`.md` and `CONTINUITY8_USAGE.json`/`.md` are independent completed-cohort summaries. Do not pool their denominators, treat zero missing exposed fields as proof of internal backend attempts, or infer quality from completion. `PREP_RECEIPT.json` records exact output/code hashes and validation status without copying raw result material.
