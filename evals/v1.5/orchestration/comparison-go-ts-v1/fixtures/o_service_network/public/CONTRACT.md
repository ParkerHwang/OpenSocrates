# Regional service-network decision (synthetic)

Build a reusable Go analysis program and a Markdown decision memo from this frozen data room. All figures describe a synthetic operation; do not infer market demand. The decision date is `2026-06-30T23:59:59Z`. Source IDs in `data/manifest.json` bind every claim. The unit `O-analysis` owns `analysis.go`, `metrics.json`, and `sources.json`; `O-document` owns `memo.md` and depends on the qualified analysis. Use Go for calculation. `analysis.go` must run as `go run analysis.go -data <data directory> -out <metrics path>` in an isolated copy. The committed `metrics.json` must match this program's output for the frozen data. The source register records relative path, SHA-256 and source ID for every used file.

## Grain and selection

`orders.json` has one immutable order per `order_id`. `events.json` has append-only updates; for each `order_id`, select the event with greatest `recorded_at <= decision_date`, breaking ties by larger integer `revision`, then event ID. Do not pick the greatest status, amount, or occurrence time. An event can correct a previous status, work duration, charge, part quantity or completion time. The selected event fully replaces those fields; `null` means missing, whereas numeric zero is known zero. Cancelled orders are excluded from operating metrics but remain in reconciliation counts. Nonempty warranty work with zero charge remains an eligible job. Duplicate event ID is invalid input. No selected event is an unknown status.

SLA policy is selected by greatest `effective_at <= order.created_at` for its priority; tied policies use larger revision. The policy has an integer target in hours and credit rate in basis points. A completed noncancelled job is SLA eligible when `completed_at` is present. On-time means completion at or before created time plus target hours. Attainment is on-time count divided by eligible count; output ratio as a decimal rounded half-up to 4 places (null when denominator zero). Credit is calculated per late job as charge cents times credit basis points / 10000, rounded half-up to integer cents, then summed. A late job with missing charge contributes no known cents and increments `unknown_credit_jobs`; a late warranty zero-charge job contributes known zero cents. Do not silently impute a missing charge as zero.

Backlog is the count of noncancelled selected events in `open` or `scheduled` state. Capacity is available technician minutes by facility from `capacity.json`, minus completed noncancelled work minutes assigned to that facility; report both available and used minutes. For `part_cost_cents`, select supplier unit rate by part ID and greatest `effective_at <= completed_at` (tie by revision), multiply by each completed event's quantity, then sum. Missing quantity/rate is unknown, not zero; report `unknown_part_cost_jobs`. Units are cents and minutes. No floating-point currency arithmetic.

## Facility decision

Compare three feasible portfolios: `east`, `west`, and `east+west`. Each facility has fixed monthly cost in `capacity.json`; a portfolio with two facilities also incurs one shared dispatch cost from `shared_costs.json`. The only forecast demand in this exercise is the frozen assigned order set, so report observed completed work and available minutes by portfolio; do not claim customer demand can move freely between facilities. Feasible means available minutes at least used minutes for the observed portfolio. Rank feasible portfolios by monthly fixed plus shared costs, but state the lost coverage/assignment caveat for a single-facility option. Sensitivity: increase only part `relay` rates effective from `2026-04-01T00:00:00Z` by 10%, rounded half-up per unit before multiplication. Show baseline and sensitivity part cost; do not change labor minutes, SLA, or fixed facility costs.

Output stable JSON keys for selection counts, `backlog`, `sla`, `capacity`, `part_cost`, `portfolios`, and `sensitivity`; include numerator/denominator and unknown counts, not only percentages. `memo.md` cites metric JSON keys and relevant source IDs, compares all three portfolios, recommends one with stated criteria and uncertainty, sets an operating plan, and keeps a risk/assumption register. Put each material numeric claim in an evidence table with a JSON pointer and its value (for example, `| /backlog | 2 | orders-v1, events-v1 |`); prose may refer to that table. Include the monthly cost, assigned completed-job count, available and used minutes, and feasibility value for **each** portfolio. Add plain-text lines `Recommendation: <east|west|east+west>`, `Criterion: ...`, and `Uncertainty: ...`; these are stable decision-record fields, not a fixed answer. A single-facility recommendation must explicitly address coverage/assignment loss and a validation step before closure. A different recommendation is acceptable when it follows the data and stated criteria. A polished memo with wrong arithmetic is not acceptable.

Native read-only checks may inspect valid JSON, source register hashes and Markdown references.
