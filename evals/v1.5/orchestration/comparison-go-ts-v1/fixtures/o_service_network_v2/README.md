# Version 2 service-network subject fixture

This version is the O task for the proposed 24 office-analysis comparison cells. The committed O version 1 packet is a small oracle/control validation fixture and must not be relabeled or pooled as this subject workload. This package keeps the same six model/effort tuples, four arms, two-unit O-analysis→O-document graph and Go/Markdown deliverable types. No outcome model call has been made by fixture preparation.

The public data room has synthetic work orders across four facilities and four months, an initial event stream plus later corrections, dated SLA policies and supplier rates, monthly capacity and labor rates, pairwise shared dispatch costs, and declared facility portfolios. The interactions are deliberately material: late event revisions and tie breakers alter selected state; one selected completion crosses a month boundary; a completed job has unknown labor minutes; warranty zero charge remains real work; missing part quantity/rate and charge remain unknown; later policy/rate numbers may decrease; and a west-June capacity sensitivity changes option eligibility. The analysis must join at the correct order/event/part/month grain, round per record, and disclose unknown cost/feasibility. A low-cost option may omit assigned work. The source files are bounded and contain no metric answers.

`descriptor.json` is the standalone versioned task descriptor. It declares 12 public sources and four total owned paths (`analysis.go`, `metrics.json`, `sources.json`, `memo.md`). The full contract is within the native request's 8,192-character constraint limit; each source and candidate file is below 64 KiB. Only `public/` is model-visible. The starter validates identities and reconciles event selections but leaves policy/rate joins, per-job costs, monthly capacity, portfolios, sensitivities and the memo to the subject.

`private/oracle.py` recomputes expected values independently in Python. `private/controls/good/analysis.go` is a separate Go reference implementation, and the good memo binds numeric claims to source IDs. `private/verify_external_v2.py` has two scopes: `--scope analysis` checks each exact analysis version without any memo, while default `--scope full` checks a document version only with its **actually qualified** analysis dependency. The runner must retain this lineage and must never pair an old failed analysis with a later memo. Native checks are read-only static/schema checks and do not establish a Go build or numeric answer. The external qualifier runs the candidate Go executable under the locked child Seatbelt policy in a marked disposable copy; trusted Python then computes the private answer key from frozen source bytes.

The good control, an allowed alternative recommendation/format, wrong algorithm controls and misleading memo controls are exercised by `private/control_selftest.py`. It retains every disposable control copy and structured receipt. `private/native_selftest.json` exercises public static checks and a path-traversal source-register mutation without changing staged bytes. A separate exact-policy canary must demonstrate that candidate children cannot read the private oracle directly or through a symlink. Numeric/source/document structure checks do not prove that a recommendation is wise; a separate independent semantic review remains required.

`private/FREEZE_PREP.json` records hashes and evidence once controls are complete. Real O24 outcomes remain gated on the runner's native prepare/schema checks, exact client/package/policy bytes, candidate private-read denial and user-authorized dispatch. No old O v1 outcomes are rewritten.
