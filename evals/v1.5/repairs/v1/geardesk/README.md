# GearDesk repair handoff

These are synthetic exported review artifacts, separate from the original paired
model comparison. `original/` preserves final generated sources, `snapshots/`
preserves the real preceding storage format, and `repaired/` contains explicitly
integrator-authored derivatives. The original and derivative Git identities and
exact exported bytes are in `manifest.json`; `patches/` contains the code changes.
No repaired source is relabelled as an original unassisted model outcome.

From this directory, run each application's own tests with `npm test` in its
folder. The independent checker was frozen before derivative runs:

```sh
python3 checker/v2/controls.py
python3 checker/v2/supplement.py --project repaired/v1.4.0 --arm v1.4.0 --baseline . --output /tmp/new-baseline-result.json
python3 checker/v2/supplement.py --project repaired/v1.5.0-rc --arm v1.5.0-rc --baseline . --output /tmp/new-candidate-result.json
```

Use an unused output path each time. HTTP checks require local loopback access.
The supplement writes counts even when checks fail; inspect `fail` and `error`,
not its process exit alone. `checks.py` supplies the broader three-stage service
suite; historical migration requires a genuine prior-stage store generated by
the exported stage2 CLI. The supplement generates that fixture itself.

The main suite passes 34/34 for both original and repaired implementations after
correcting a whole-object comparison defect. The new supplement exposes five
failures in original v1.4 and ten in original v1.5; repaired results are 25/25 and
24/24 respectively. These are distinct checks/conditions, not comparable quality
percentages. Original strict final scores remain 34 pass versus 32 pass, one
failure and one unassessable in the original local evaluation boundary.

`evidence/` contains compact public exports: scores, individual findings, fixture
controls, failures and scope. Top-level bulky action receipts are omitted and the
local workspace prefix is replaced by `$DEMO`; raw source receipt digests identify
that derivation. Original raw synthetic receipts remain preserved locally.

The baseline safely refuses partial refunds for ambiguous historical mixed-item
deposits; it retains the correct aggregate full refund. A historical allocation
import remains outside this minimum repair. Both implementations now preserve
operation-specific date validation and detached output/replay evidence. Candidate
batch copying is one whole working-store copy for a normalized v2 transaction;
this is not a measured throughput or billing improvement.
