# Practical v1.5 qualification and released-v1.4 comparison

This is the new, bounded completion lane authorized on 2026-09-26. It leaves all
earlier studies, review packets, scores and failures unchanged. Statistical proof,
human recruitment, billing/backend echoes and account-side isolation are not
prerequisites; correctness, privacy, authority and honest support claims remain.

The prospective [fixtures](fixtures.v1.json), [checks](checks.py), [runner](runner.py)
and [manifest](manifest.v1.json) define six matched scenarios: mechanical work,
existing code plus a fresh Git follow-up, non-Git continuity and scoped forgetting,
general planning, and equivalent EN/KO collaboration. Twenty model invocations
are planned under a hard initial ceiling of 24, including every failed call and
session. No automatic outcome retry or model substitution is allowed. Transport
or harness failure stops new dispatch for diagnosis; successful independent work
is retained. Any repair/retest is separately frozen and narrowly scoped.

Use `gpt-6-sol` at medium on the exact recorded bundled client. The released
baseline is the actual v1.4.0 GitHub ZIP, independently matched to its published
SHA-256. The source candidate includes assistance guide 5 and all implemented
v1.5 capabilities, initially retaining the old package version while functional
qualification runs. The final RC version is synchronized only after that gate;
functional source and packaged guide/schema identities must be checked across
the metadata-only transition. No active installation is replaced.

Both versions get competent instructions, identical initial sources, the same
tools and per-scenario permissions/hook mode. The v1.4 baseline receives a usable,
explicitly named maintained note containing the same accepted/proposed facts as
candidate memory. Source corrections and follow-ups are identical. First-stage
artifacts can differ, so this is a naturalistic paired example, not an isolated
causal estimate. Code and non-Git follow-ups have new contexts/profiles; dialogue
follow-ups resume only their disposable episode. Native memory/import is disabled
locally; account-side isolation remains unproven and limits causal claims only.

The normal-hook planning pair is disposable and explicitly trusts only the pinned
package. Other pairs disable hooks and use the installed skill explicitly. Human
quality scores are unavailable. The integrator reads every retained public message
and checks actual artifacts and persisted state. A pack or self-report alone does
not pass. Question detection examines the full public turn and is only an index
for semantic review, never a last-message-only outcome rule.

The synthetic memory [audit adapter](memory_tool.py) forwards unchanged requests
to the installed native launcher. It does not simplify requests, add permissions,
repair answers or modify package bytes. It captures operation/request IDs, status,
version and target IDs outside product memory. Independent inspect/export/recall
checks establish final state and distinguish proposed from accepted records.
This instrumentation is declared evaluation infrastructure, not a product feature.

Retained material is synthetic source/artifacts, public messages, redacted command
templates, operation/state receipts and usage metadata. No hidden reasoning, raw
event stream, credentials or real-project content is retained. Auth copies and
runtime session profiles are removed after each episode. Missing usage stays null.
Read-only snapshots verify that global configuration, the active controller and
the user's agent definition remain unchanged.

Non-model disposable installation/native-memory preflights are in `preflight/`
and `preflight-adapter/`; they do not consume model invocations. The checker
self-test includes a deliberately bad free-item implementation, a fractional/bool
seat case, a proposed-only record, and a question before the final public message.

Run offline checker tests with `python3 evals/v1.5/practical/checks.py`. Live
execution uses `python3 evals/v1.5/practical/runner.py`, verifies committed hashes,
and refuses to overwrite an unfinished attempt. Completed episodes may be skipped
to continue unstarted scenarios after explicit reconciliation. The manifest's
archive paths are local execution inputs; their URLs/hashes and release provenance
identify the baseline without requiring an authentication file to understand it.
