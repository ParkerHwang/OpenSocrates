# Full-stack and consulting observation matrix v1

New user-authorized comparison: three environments, six exact model/effort tuples,
two difficult tasks, one fresh episode in each of 36 cells. This is a practical
observation matrix, not a powered study or a release gate. Historical evaluations
remain immutable. Product baseline: `035fafcd208bf9577ca55ff5e42a93df4ca608ea`.

## Plan and observation contract

- `plan_objective_measure`: compare usable task artifacts, correctness, source
  handling, architecture, actual work and completion. Verified baselines are
  released 1.4.0 package bytes and the qualified 1.5.0 candidate bytes. Vanilla
  has the same task, tools and source access without an OpenSocrates installation.
- `do_scope`: 36 disposable projects/profiles, no production users. Exact tuples:
  GPT-6 Sol/high, GPT-6 Luna/max, GPT-6 Luna/high, GPT-5.6 Luna/max,
  GPT-5.6 Luna/high, GPT-6 Astra/xhigh. No helper agents, substituted models,
  integrator repairs, outcome feedback or cross-cell answers.
- `check_rule`: freeze tasks, packages, environment, observation fields and checks
  before outcome calls. Preserve all attempts and negative evidence. Check actual
  source/data/documents, all public messages and post-call execution. Separate
  process completion, deterministic checks, primary review and performance.
- `act_standardize_decision`: pending observation. A single episode cannot
  validate a model profile or establish universal improvement. Mixed findings
  remain provisional. Do not run until a favorable answer appears.

The user's latest instruction removes experimenter-imposed resource limits:
**no model wall-clock, token, tool-call, output-length or internal-retry budget**.
Polls are observation intervals, never termination deadlines. Provider/client
limits and interruptions are retained as external events. No automatic outer
retry or manual follow-up is sent. An actual unavailable tuple is recorded; it is
never silently replaced. Privacy, authorized workspace boundaries, memory-off,
Fast-off and the task's business requirements still apply.

Each subject receives an empty native-memory profile, ephemeral session, isolated
shell HOME and dependency caches, no user/project history and no external memory
import. A named filesystem permission profile permits its own workspace/profile
and toolchains but not the user's memories, implementation repo or peer cells.
Shell canary checks and prompt-context inspections precede calls. Account-side
memory separation is not independently attestable. No global settings change.

Both product arms use disposable installed ZIPs and an explicit controller cue;
hooks are disabled equally. This tests installed guidance with explicit entry,
not automatic hook activation. Product memory is not enrolled. Vanilla receives
competent normal task instructions and the same tools, source material and notes.
All profiles request `service_tier="default"` and disable `fast_mode`.

Development/task language is English, consistent across arms. Programming language
and stack are the subject's choice. No paid services, credentials, production
deployment or helper models are part of either task. Dependency downloads and
public web research are available equally. The primary observes rather than
coaching or editing subject artifacts.

Office collection includes a reproducible HTTP source room with raw synthetic
client exports and genuine downloaded official source snapshots; subjects must
collect and reconcile them. Original public URLs and vintage are included.
Additional public research is allowed and recorded. This is not described as
uncontrolled live-web discovery. Source snapshots prevent unequal data vintages.

Public synthetic evidence stays in this declared evaluation boundary. Raw model
event streams and hidden reasoning text are not saved. Public messages, tools,
timestamps, artifact manifests and numeric usage are saved; absent usage is null.
Reasoning-token counts, when supplied, are measurements, not reasoning text.
Account identifiers are hashed. Auth copies are private and removed after calls.

The frozen manifest fixes an interleaved order; the scheduler keeps at most three
independent subject processes in flight to avoid overwhelming this host. This is
host scheduling, not a resource limit on an individual episode. Performance
qualification runs separately with no other benchmark running. No throughput
claim follows from generation wall time or concurrently executed self-tests.

Independent human scores and independent backend model/tier echo are unavailable.
Primary qualitative reviews are unblinded and labelled. Native config/receipts
support requested tuple and Fast-off state, not billing proof. Source correctness,
delivery, artifact quality and causal improvement stay separate.

OpenSocrates grounding: pdca-cycle@3 (primary design only; application unverified).
