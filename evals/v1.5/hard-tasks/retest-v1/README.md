## Execution and measurement

The manifest binds the actual Codex executable **and** its launcher before every
call, installed package member hashes, all fixture/checker/helper sources, Go/Python
versions, tuple/order, permissions, budgets and missing-value handling. The client
is the existing desktop-bundled CLI; no API key or new credentials are created.
Each disposable profile uses ephemeral mode, disabled hooks, native memory/import,
apps, remote plugins and multi-agent work. The outcome models may not spawn helpers.
Only synthetic workspaces are enrolled; active installations and global settings
are untouched. Existing auth is copied privately and removed after each attempt.

Six paired rounds use at most two concurrent builders, reversing launch order in
alternating rounds. Invocation time can overlap another task and is descriptive.
The transparent adapter now also forwards `decision` unchanged in both arms, so
new operations/errors can be recorded without adding semantic help. Direct native
command projections remain incomplete when the CLI omits/truncates their output.

missing token categories stay null, never zero. Private reasoning/event streams
are not retained. Public messages, generated source and synthetic artifacts remain
only inside the declared evaluation boundary, never in product memory.

locked with the final outcome. Internal provider retries are not independently
observable; the invocation limit counts actual CLI starts, not an invented backend
request count. Ordinary account usage was available in the read-only host check.
