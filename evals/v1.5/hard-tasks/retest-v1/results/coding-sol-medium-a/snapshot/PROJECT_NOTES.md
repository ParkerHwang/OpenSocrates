AuditLedger implementation is in `cmd/server/main.go` and `internal/platform/driver.go`. The source was rechecked in this session; the starter initially contained only driver and process scaffolding. The database schema, version 1 migration, JSON API, durable idempotency, tenant-local entries, historical reads, and graceful server shutdown are implemented. Tests are in `cmd/server/main_test.go` and `internal/platform/driver_test.go`.

Go build and tests passed after the final code changes. A live check used the supplied legacy fixture producer, started two server processes against one SQLite file, read a migrated summary, reversed a legacy transfer through one process, replayed it through the other, and read the resulting summary. Both processes were stopped by the shell trap. The independent post-episode performance measurement was not run here, as requested.

The design uses `BEGIN IMMEDIATE` for writes and migration, with bounded retry for startup lock contention. This favors correctness under concurrent writers. The historical summary is derived from entries only. A future performance concern would be SQL cost under heavy concurrent writes; no performance claim has been measured here.
