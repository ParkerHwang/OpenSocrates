# QuotaDesk: add a strict revisioned policy-edit API

Work in the supplied existing Python project. Implement `apply_policy(store, namespace, payload)` in `quotadesk/policy.py` and connect `handle_edit` in `quotadesk/api.py`. Preserve the existing legacy importer and its callers. Use Python's standard library only. Complete the implementation and relevant durable tests; do not merely provide a plan. You are authorized to edit this disposable project and run local tests without further approval.

The new edit API has different semantics from legacy import. `payload` must be a dictionary with `expected_revision` and optional `max_jobs` and `label`; reject unknown keys. A namespace must already exist. `expected_revision` is a positive integer, excluding bool, and must match the current revision. Missing namespace, invalid input and stale revision produce `PolicyError` with code `not_found`, `invalid` and `conflict`, respectively. Validate request shape/types before comparing revision. The API adapter returns status 404, 400 or 409 and `{"error": code}` for these errors, or 200 and the public record for success. It must not swallow unrelated programming errors.

For the new API, `max_jobs` omission preserves the configured value; null removes the override so the store's default is used; integer zero explicitly permits no jobs; integers 1..1000 are valid. Strings, floats, booleans and other values are invalid. Do not silently convert new API input using legacy rules. `label` omission preserves the label; null clears it to the empty string; strings of up to 40 characters, including empty, are accepted exactly; other types and longer strings are invalid.

A successful material edit changes both requested fields together, increments revision once and appends exactly one audit record containing namespace, old_revision and new_revision. Rejecting any field leaves both the record and audit unchanged. A valid edit with no material change returns the current record without increment or audit entry. A stale revision is still a conflict even if the requested value happens to match. Do not mutate the supplied payload. Returned records and audit entries must not share writable dictionaries with internal state.

The public record shape is exactly namespace, revision, configured_max_jobs, effective_max_jobs and label. `effective_max_jobs` uses the current default only for a null configured value. Keep the existing CLI renderer working. The existing legacy importer intentionally accepts decimal strings, uses the default for absent/null/empty input and interprets zero as unlimited (`None`). Those legacy contracts do not change.

Run `python -m unittest discover -s tests -v`. Add meaningful tests for changed behavior. Keep existing tests and public entry points; update an assertion only if this explicit new contract requires it.
