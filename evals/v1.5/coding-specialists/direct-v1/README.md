# Coding specialist direct-delivery pilot v1

This new English pilot compares complete current coding support with complete candidate v0.1.1 specialist prompts on the same synthetic existing-code tasks. It tests prompt-delivered support, not plugin discovery, native registration or hook activation. Tasks were authored by the primary integrator before any outcome call, independently of candidate outputs. Hidden expected checks are separately authored from the requested contracts. This is not independent human authorship or a held-out statistical study.

Three pairs: QuotaDesk revisioned policy edits (contracts), ParcelSeal uncertain-outcome publishing (transitions), BatchFlow retained manifests (ownership). A fourth pair adds an approved BatchFlow scaling feature in fresh contexts continuing only each arm's own locked initial source. The candidate's fifteen published worked cases, new author counterexample and prior failing generated programs are not supplied to subjects.

Both arms receive identical task facts, source state, tools, permissions and intervention timing. Current support delivers the complete relevant existing coding guide plus the existing result-verification guide. Specialist support delivers its complete procedure. Prompt lengths and obligations are actual treatment differences; this is not a length-normalized or isolated token-probability experiment. General selection is bypassed only for these explicitly preselected direct-insertion treatments; product routing is evaluated separately later.

`manifest.json` freezes all source, prompt, runner and checker hashes, the exact gpt-6-luna/max tuple, bundled client identity, account fingerprint, program-test guard and no model wall-clock cutoff. The separate access probe must succeed before outcomes. Every call has a started record and terminal receipt; provider/setup failures and uncalled slots remain explicit. Progress polling cannot terminate or relaunch a model.

All calls use ephemeral disposable profiles with native memory/import, hooks, apps, remote plugins and multi-agent features disabled. Account-side isolation is unproven. No product memory is enrolled. Subjects may use only the supplied project and Python standard library; fixed provider/old-producer/protected test files cannot be rewritten. Any outside-scope tool use or protected-byte change is recorded and prevents an unqualified comparison claim.

Raw model streams and hidden reasoning are not persisted. Retained synthetic public messages, tool commands/results, usage categories and source artifacts stay inside this evaluation boundary. Input includes cached input; output includes any reported reasoning subset. Missing usage and billing remain null. Source snapshots are locked before independent qualification, which runs on disposable copies. No hidden-check feedback or stronger-model repair reaches an outcome subject.

Functional group counts are contract coverage, not weighted quality scores. Inspect actual source for suitable reuse and unnecessary machinery separately. Human scores are unavailable; primary semantic review is unblinded/provisional. Report both independent checks and the retained own suite. A failed CLI call may leave a useful artifact but remains a failed call. Additional tests require a diagnosed change and a new versioned boundary, not a search for favorable outcomes.

Freeze and execute, using the approved local Python and owned disposable storage:

```sh
python runner.py execute --storage <OWNED_STORAGE> --python <BUNDLED_PYTHON>
python runner.py qualify --storage <OWNED_STORAGE> --python <BUNDLED_PYTHON>
```

`plan_objective_measure`: compare first-delivery correctness, operation-specific reuse, state/response/snapshot behavior and available total work against current support.

`do_scope`: six initial direct-insertion calls and two same-arm follow-ups; no helper agents or model switching.

`check_rule`: pre-frozen independent expectations, protected source, actual consumers, all attempt/usage accounting and no model wall-clock deadline.

`act_standardize_decision`: pending. A tie or regression does not become a claimed improvement; integrated usability and source correctness are separate gates.
