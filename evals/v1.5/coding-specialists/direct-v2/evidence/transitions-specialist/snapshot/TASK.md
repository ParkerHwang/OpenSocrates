# ParcelSeal: recover a local publisher across uncertain transport outcomes

Extend the supplied Python package with a durable `Publisher` in `parcelseal/publisher.py`. The supplied file transport is a synthetic stand-in with explicit documented semantics; do not infer guarantees of an actual remote provider. Keep `LegacySender` working. Use the standard library and the existing transport interface. You are authorized to implement and test in this disposable project without further approval. Do not introduce a remote service or new dependency.

Public API: `Publisher(state_path, transport)`; `publish(tenant, key, payload)`; `close()`. State persists at the supplied SQLite path across publisher recreation. `tenant` and `key` are nonempty strings up to 80 characters, and `payload` is bytes; reject invalid input with `ValueError` before effects. Scope identity by `(tenant, key)`. Reusing that identity with different bytes raises `PublishConflict` before sending or changing its recorded outcome. Equal payloads under different identities remain independent operations. The supplied `transport.py` is a protected fixture: use its interface without modifying its guarantees or instrumentation.

The transport's `send` can return a receipt, raise `NotAccepted` (definitely no effect, terminal rejection for this logical operation), or raise `TimeoutError` (outcome unknown). `lookup` returns the retained receipt, returns None to confirm the completed attempt had no acceptance, or raises `LookupUnavailable`. A lookup does not itself send. The supplied transport deduplicates accepted logical identities, but this does not make the local SQLite transaction and external file write one transaction. Never interpret a timeout as rollback.

`publish` returns a detached JSON-compatible dictionary with exactly `status` and `receipt`. Status is `delivered`, `pending` or `rejected`; receipt is the transport receipt only for delivered, otherwise null. A completed or rejected operation replays the same outcome without another send. A send timeout returns pending. A later publish for that pending identity must reconcile using lookup: found -> delivered; lookup unavailable -> remain pending without sending; definitively absent -> another send is allowed, whose outcome follows the same rules. Stored payload identity must survive a pending/rejected outcome and restart.

Two Publisher instances sharing the same state file can be used by concurrent threads. They must not lose or overwrite one another's logical identities, publish conflicting content for one identity, or claim success before confirmation. Multiple simultaneous same-identity calls may report pending while another attempt is in flight; a later call must reconcile to delivered. Do not hold a shared mutable result object that an API caller can use to alter stored replay. Keep resource cleanup usable: close releases owned database resources; constructing another publisher on the same file must still work. Never close the supplied transport because its lifetime belongs to the caller.

Add durable tests and run `python -m unittest discover -s tests -v`. Use controlled ordering or failure injection rather than elapsed sleeps as the only evidence. Check actual persistent state and effect counts, not only the final status. Retain the existing public entry points and tests. Report what was implemented, actual checks and unverified physical-crash/remote-provider guarantees. No performance benchmark is requested.
