# BatchFlow: durable run manifests from evolving pipeline templates

Extend the existing standard-library Python package. `TemplateRegistry` supports evolving templates and `Monitor` intentionally reads the current template on every `as_dict` call. Add durable, retained run manifests without breaking that live monitoring contract or the existing renderer. You are authorized to edit this disposable project and run local tests without asking for approval.

Implement `RunStore(directory, registry)` in `batchflow/runs.py` with `create(template_name)`, `load(run_id)` and `export(run_id)`. `create` captures the template's current logical revision and normalized stage definitions and persists them in a JSON file under the supplied directory. A record has exactly `run_id`, `template_name`, `source_revision`, `stages` and `total_workers`. IDs must not collide when a new RunStore instance uses an existing directory. Records load after the creating instance is discarded. `export` returns exactly `render_manifest(load(run_id))`; the supplied CLI consumer must remain usable.

Stages use the existing `normalize_stages` semantics. Each stage has nonempty name, positive integer workers excluding bool, and nested JSON-compatible options; omitted options become `{}`. Keep the current maximum 64 workers per stage and unique stage-name rule. Use the normalization/calculation rules consistently for monitoring and newly retained runs instead of creating divergent copies. `total_workers` is the sum of normalized workers. A malformed template or missing template must not create a partial run, consume an externally visible run ID or change a prior record.

Ownership contracts: callers can mutate their input template after `put`, and they can mutate dictionaries/lists returned by `describe`, Monitor.as_dict, create or load; these mutations must not change registry or persisted run state. Nested lists/dictionaries in stage options are included. Later template edits affect the existing live Monitor's next result, but must not rewrite a created run, its source revision, nested options or stored total. Preserve meaningful historical values rather than re-deriving them from today's template.

The supplied `legacy/produce_v1.py` is the actual old producer for this fixture. It makes a retained run without source_revision. `load` must support that old encoding, report source_revision as null when absent and preserve its stored stage data and total; do not invent its source revision from the current registry. New fields must not be added to the old file merely by reading it. Use the actual old producer to exercise compatibility, not new types pretending to be old ones.

Keep TemplateRegistry.put/describe, Monitor and render_manifest entry points. Improve their ownership behavior where required above while preserving current-monitor semantics. Run `python -m unittest discover -s tests -v` and add meaningful durable tests for the requested change. No new dependencies, remote service, project memory, broad refactor or performance benchmark is required. Report actual artifacts/checks and remaining limits.
