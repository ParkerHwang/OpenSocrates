# 명시적 전문 제작과 독립 검증

이 선택 경로는 주 에이전트에게 위임 제작 권한이 이미 있을 때만 실제 Codex 모델
프로세스를 실행합니다. 일반 훅과 판단 조회는 자동으로 시작하지 않습니다.
[예시](request.example.json)에 따라 현재 제약, 독립적인 분야·작업 종류·역할 축,
단독 경로 소유자, 의존성, 필수 산출물과 운영자 승인 검사를 포함한 완전한 닫힌 계획을
준비하세요. `operation: prepare`는 모델 호출 없는 검사, `operation: run`은 실행입니다.
locale은 en 또는 ko이며 모든 역할·수정에서 현재 승인된 주 모델·추론 강도를 그대로
유지합니다. 알 수 없는 전문 분야는 분류 공백입니다. 이를 쓰기 위해 기억을 등록하거나
전역 설정을 바꾸지 마세요.

설치 경로는 `${PLUGIN_ROOT}/bin/launch.sh orchestrate codex`이며 Windows 실행기는
`node ${PLUGIN_ROOT}/bin/launch.mjs orchestrate codex`입니다. V1 어댑터는 별도로
선택한 검증 대상 macOS Codex 실행 파일을 요구합니다. 실행기가 있다고 다른 플랫폼도
지원되는 것은 아닙니다. 범위가 정해진 소스·맥락을 호출자가 인증한 Codex 클라이언트에
보내며 해당 계정의 사용량을 소비합니다. 원시 프롬프트·JSONL·비공개 사고 과정·검사
출력 덤프를 보존하지 않습니다. 후보 산출물과 제한된 공개 지적 사항이 결과입니다.

각 텍스트·설계·코드·계산 버전은 서로 다른 새 검토자와 실행 검증자를 거칩니다.
적용되는 전체 역할·분야 지침과 선택한 소프트웨어 전문 절차를 전달합니다. 기계적
작업은 선택적 추론을 건너뛸 수 있지만 독립 검증은 생략하지 않습니다. 검토자는
수정하지 않습니다. 지정 제작자가 정해진 횟수 안에서 수정하면 변경 버전을 다시
검토·검사합니다. 선언된 argv만 시험된 읽기 전용·네트워크 차단 샌드박스에서 실행합니다.
필수 누락·실패는 열린 상태로 남기며 V1 검사는 어떤 파일도 쓸 수 없습니다.

소스는 각 임시 맥락의 `inputs/<source-id>/<원래 파일명>`에 있고 의존·후보 산출물은
선언된 상대 경로를 씁니다. 결과 폴더는 소스 프로젝트 밖의 새 경로여야 합니다.
`versions/<unit>/vN/<path>`에 모든 시도, `artifacts/<path>`에 최종 통과 후보가 있습니다.
`integration_pending`는 주 에이전트가 영향받는 최종 프로젝트 바이트를 대조·재검사해야
한다는 뜻이며 배포·통합 완료가 아닙니다. 외부·합성 seed는 명시한 제작자를 유지하고
최초 제작만 건너뜁니다.

이미 등록된 범위의 기억이나 명시적인 인계 내용을 쓰세요. 레코드를 선택해도 전체
채택 제약을 유지하고 소스를 재검증하며 삭제·버전 변경은 재사용을 무효화합니다.
첫 검토에서 제작자 자기 평가와 미검증 교훈을 제외합니다. 채택·근거·현재성·독립 검토는
별개이며 정확한 버전의 독립 영수증이 없으면 검토 상태는 미확인입니다. 기억이 없거나
비활성이면 상태를 만들지 않습니다. 새 대화는 계정·백엔드 격리나 무관한 모든 파일의
읽기 차단을 보장하지 않습니다. 가짜 검사, 준비 결과와 지침 배송은 실제 모델 실행이나
품질 향상의 증거가 아닙니다.
