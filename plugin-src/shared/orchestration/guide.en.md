# Explicit specialized orchestration

This optional route launches real Codex model processes only when the primary has
existing authorization for delegated production. Ordinary hooks and decision
retrieval never start it automatically. Prepare a complete closed plan using
[the example](request.example.json), including current constraints, independent
domain/work-kind/role axes, sole path owners, dependencies, required artifacts and
operator-approved checks. Use `operation: prepare` for zero-call validation and
`operation: run` to execute. Set locale to `en` or `ko`; keep the exact configured
primary model and effort for every role and repair. Unknown specialties remain a
classification gap. Do not enroll memory or change global settings to use it.

The literal installed route is `${PLUGIN_ROOT}/bin/launch.sh orchestrate codex`
(or `node ${PLUGIN_ROOT}/bin/launch.mjs orchestrate codex` on Windows). The v1
adapter requires the separately selected qualified macOS Codex executable; an
available launcher alone does not make another platform supported. It sends
bounded selected source/context to the caller's authenticated Codex client and
consumes that account's usage. It retains no raw prompts, JSONL, private reasoning
or test-output dumps. Candidate artifacts and bounded public findings are outputs.

Each text/design/code/calculation version receives a different fresh reviewer and
execution verifier. All applicable role/domain instructions and selected software
specialists are delivered completely. Mechanical work can skip optional reasoning;
it cannot skip independent acceptance. A reviewer never patches. A designated maker
repairs within the plan's bound and the changed version is reviewed and checked again.
Only declared argv arrays run under the tested read-only, network-disabled sandbox.
Missing/failed required obligations remain open. V1 tests may not write any files.

Sources appear at `inputs/<source-id>/<basename>` in each temporary context.
Dependencies/current candidates occupy declared relative paths. Result folders must
be new and outside the source project. `versions/<unit>/vN/<path>` preserves all
artifact attempts and `artifacts/<path>` contains qualified final candidates.
`integration_pending` requires the primary to reconcile/recheck affected final
project bytes; it is not deployment or integration completion. Seeded external or
synthetic artifacts keep their stated author and skip only the initial maker.

Use already enrolled scoped memory or an explicit handoff. Full accepted constraints
survive optional record selection; sources are revalidated and deleted/version-changed
records invalidate reuse. First reviews exclude maker self-assessment and unverified
lessons. Accepted, supported, current and independently reviewed are separate; review
state remains unknown without an exact-version independent receipt. No memory state
is created when absent/disabled. Fresh conversation is not account/backend isolation
or a guarantee against every unrelated file read. Fake checks, emitted preparation
and shipped guides are not live model or quality evidence.
