# 전달할 결과 검증

Guide revision: 1

공유 코드를 바꾸거나 서로 연결된 산출물을 만들거나 성능 측정을 요청받았을 때
관련 부분을 읽습니다. 검사는 요청한 결과에 맞는 범위로 정합니다. 이 안내가
별도의 정책 호출이나 공개 체크리스트를 요구하지는 않으며, 정본 추론 방법을
추가하지도 않습니다.

## 코드와 호출부

바뀐 계약과 실제 호출부, 등록 및 테스트 대상을 찾습니다. 이름을 바꾸거나 함수를
나눈 뒤에는 영향받는 사용처를 빌드하고 저장소의 관련 테스트 명령을 실행합니다.
실행 파일 빌드나 외부 API 검사를 통과해도 테스트 호출부는 깨질 수 있습니다.
유효한 기존 테스트 의도는 보존하고, 현재 요구사항이 뒷받침할 때만 낡은 검증을
고칩니다. 통과시키려고 테스트를 지우지 않습니다. 중요한 불변 조건을 바꾸면
유지할 수 있는 동작 테스트를 추가하되, 사소한 편집을 그대로 반복한 테스트는
피합니다. 프로젝트에 도움이 될 때 응집된 순수 도메인 규칙과 명시적인 부작용
경계를 사용합니다. 모듈 수, 추상화 수나 특정 프로그래밍 스타일은 품질의 증명이 아닙니다.

## 데이터, 설명과 표시

중요한 주장마다 기준이 되는 출처나 계산 결과를 정합니다. 표, 메모 설명, 대안,
대기자와 최종 답변의 수치를 그것에 대조하며 제외한 선택지도 확인합니다.
단위와 실제 표시도 확인합니다. 사람 수, 좌석 수와 개수에 통화 형식이 적용되면
안 됩니다. 값의 부재, null, 0과 유효한 무료 항목을 구분합니다. 정정한 뒤에는
그에 의존하는 주장도 다시 계산합니다. JSON이나 통합 문서의 계산이 맞는 것만으로
옮겨 쓴 설명이 검증되지는 않습니다. 질문이나 약속을 평가할 때는 볼 수 있는
모든 공개 메시지를 확인하고, 앞선 메시지가 없으면 해당 결론은 평가 불가로 둡니다.

## 요청받은 성능 측정

측정 전에 작업 부하, 소스, 호스트, 동시성, 시간 제한과 합격 조건을 정합니다.
빌드와 테스트가 끝난 뒤 부하를 실행해 다른 작업의 간섭을 피합니다. 정확성과
지연 시간, 처리량, 자원 사용을 구분하고 준비 구간 실패, 시간 초과와 종료 대기
작업도 남깁니다. 동시성이나 풀 크기를 조정하기 전에 실제 드라이버의 읽기·쓰기
트랜잭션 경계, 잠금과 자원 수명을 진단합니다. 필수 정확성 검사가 실패했거나
끝나지 않았다면 성능은 진단용입니다. 한 부하의 우위를 일반화하거나 글 길이로
내부 추론량을 추정하지 않습니다.

완료 조건 추적이 도움이 되는 복합 작업에는 기존 v1.1의
[코딩](verification-coding.json) 또는 [산출물](verification-artifacts.json) 예시를
사용하고 locale은 `en`이나 `ko`로 둡니다. 작업에 맞게 조건을 바꾸고 실제 관찰과
근거 ID를 기록합니다. 다른 검사가 통과해도 필수 실패나 미확인 검사는 남겨 둡니다.
성능 작업은 요청받지 않았다면 선택 사항으로 유지합니다. 런타임의 `finish`는
호출자 신고에 따른 조건부 안내이며 독립적인 빌드·산출물 검토나 권한이 아닙니다.
관련 필수 검사가 통과했고 입력이 그대로라면 결과를 전달하고 끝냅니다.
