# 유지보수성 검토

Guide revision: 3

API·산출물 검사 통과와 관련 저장소 테스트 결과를 구분합니다. 작업에 둘 다
필요하다면 각각 필수 완료 근거로 유지합니다. 엔드포인트가 정상이어도 깨진 호출부나
실행하지 않은 테스트 대상은 해결되지 않습니다. 기존 완료 조건 예시는
[결과 검증](../assistance/verification.ko.md)을 참고합니다.

기계적 수정이 아닌 코드 변경을 마치기 전에 사용합니다. 변경된 동작과 영향받는
계약에 맞춰 검토 깊이를 정하며, 일상적인 수정을 아키텍처 검토로 키우지 않습니다.

1. 최종 차이와 소유 책임 및 호출부를 이해할 만큼의 주변 코드를 읽습니다. 역할의
   일관성, 도메인 규칙 중복, 불필요한 추상화나 옵션, 취약한 결합, 실패 동작,
   테스트 가능성, 문서화된 프로젝트 관례와의 적합성을 확인합니다.
2. 각 발견에는 위치, 구체적인 결과나 뒤따를 변경 상황, 이를 뒷받침하는 소스
   근거, 적절한 수정안을 제시합니다. 프로젝트 규칙이나 결과와 연결되지 않는
   취향은 결함으로 취급하지 않습니다.
3. 범위 안의 중요한 문제를 고칩니다. 동작 테스트, 린터, 타입 검사, 복잡도나
   중복 신호는 각각의 목적에 맞게 사용합니다. 점수, 줄 수, 모델의 의견이나
   테스트 통과 하나로 유지보수성이 보증되지는 않습니다.
4. 고친 동작과 관련 사용처를 검증합니다. 요청 범위 밖의 정상 코드는 보존하고
   더 큰 리팩터링은 별도로 제안합니다.

실패를 고치기 전에 정확한 입력, 기대·관찰 결과, 소스 버전과 해당 완료 조건을
연결합니다. 변경 후 그 경계를 확인하며, 직접 작성한 테스트가 통과했다는 이유로
독립 검사의 실패를 해결된 것으로 보지 않습니다. 제공·보호된 테스트는 소스 출처와
작업 지시로 식별하며 이번 대화 전에 있었다는 이유만으로 보호 대상으로 삼지
않습니다. 모르는 근거는 미확인으로 남깁니다. 원본 테스트 자료는 승인된 테스트
작업공간에 두고 제품 메모리에는 넣지 않습니다.

범위 안의 중요한 문제를 처리하고 필수 검사를 실행했거나 구체적인 장애를
보고했다면 멈춥니다. 바뀐 것이 없는 검사를 반복하거나 사소한 수정을 그대로
복제한 테스트를 만들거나 이 안내문이 적용되었다는 얻을 수 없는 증거를 찾지
않습니다. 근거가 있는 발견과 수정, 실행한 정확한 검사와 결과, 남은 한계, 변경
동작의 완료 상태를 제시하면 완료합니다.
