# 재사용 적합성

Guide revision: 1

동작, 공유 함수나 컴포넌트, 의존성, 추상화를 추가하거나 기존 구현이 겹쳐 보일 때
사용합니다. 동작과 계약이 달라지지 않는 기계적 수정에는 적용하지 않습니다. 이
안내문은 일반적인 코딩 작업을 돕고, 정본 추론 방법에 추가되지 않습니다.

1. 필요한 동작, 입력과 출력, 실패 처리, 소유 책임, 앞으로 변경될 이유를 밝힙니다.
2. 관련 프로젝트 결정을 후보 단서로 삼되 현재 체크아웃에서 다시 확인합니다.
   관련 소스, 표준 기능, 설치된 의존성을 찾고 검색 범위를 기록합니다. 검색 결과가
   없다고 해서 어디에도 구현이 없다고 단정하지 않습니다.
3. 유력한 구현의 본문, 실제 호출부, 테스트, 공개 계약을 읽습니다. 의미, 버전과
   설정 호환성, 오류 처리, 소유 책임을 확인합니다. 이름이나 형태가 같다는 것만으로는
   충분한 근거가 아닙니다.
4. 그대로 재사용할지, 좁게 확장·변형할지, 별도로 구현할지 선택합니다. 중요한
   후보를 채택하거나 제외한 이유를 설명합니다. 동작이나 변경 이유가 다르면
   분리하고, 공유 이익보다 비용이 큰 추상화나 새 라이브러리는 피합니다.
5. 선택한 방식을 구현하고 새 동작과 영향을 받는 기존 사용처를 검증합니다.

현재 근거로 선택을 뒷받침할 수 있고 추가 검색이 결론을 바꾸기 어려우면 탐색을
멈춥니다. 도구나 소스 접근이 제한되면 구조적 근거를 지어내지 말고 확인한 범위와
미해결 후보를 밝힙니다. 선택한 위치와 방식, 결정에 사용한 소스 근거, 관련 검증과
결과, 남은 불확실성을 제시하면 완료합니다. 테스트 통과만으로 장기적인 재사용
적합성이 입증되지는 않습니다.
