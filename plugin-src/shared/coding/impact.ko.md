# 변경 영향

Guide revision: 1

다른 모듈이 사용하는 공유 동작, 공개 타입이나 인터페이스, 상태 소유권, 설정 또는
등록 규칙을 바꾸기 전에 사용합니다. 계약이 그대로인 국소적 기계 수정은 바로
완료합니다.

1. 합의된 의도와 변경할 계약을 정확히 찾습니다. 기억한 결정은 현재 소스와 설정에
   대조해 다시 확인합니다.
2. 정의에서 호출부, 등록, 생성된 인터페이스, 영향받는 테스트까지 구체적인 입출력
   관계를 추적합니다. 관련 데이터 형태, 오류 전파, 재시도, 취소, 부작용, 자원 수명과
   순서를 살피고 파일이나 심벌 위치를 기록합니다.
3. 텍스트 검색 결과, 구조적으로 확인된 관계, 추론한 계약, 해결하지 못한 동적
   동작을 구분합니다. 참조가 있어도 실행 경로라는 증거는 아니고, 검색 결과가
   없어도 소비자가 없다는 증거는 아닙니다. 동적 호출은 관련 설정이나 실행 근거를
   확인합니다.
4. 함께 고쳐야 할 곳과 변경 계약 및 영향받는 사용처를 확인할 최소한의 검증을
   정합니다. 실패나 중대한 불확실성이 생길 때만 검증 범위를 넓힙니다.

소스 목록, 설정, 생성된 인터페이스 또는 추적되지 않은 파일이 달라지면 소비자가
없다는 판단을 다시 확인합니다. 변경에 중요한 관계를 충분히 확인했거나 나머지를
명시적으로 미확인 상태로 남겼다면 추적을 멈춥니다. 변경 계약, 근거가 있는 영향
범위와 동반 수정, 검증 결과, 확인 범위의 한계와 미해결 위험을 제시하면 완료합니다.
텍스트 검색 목록이나 테스트 통과를 의존성 전체의 증거로 표현하지 않습니다.
