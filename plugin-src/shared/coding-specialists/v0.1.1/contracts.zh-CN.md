# 契约与不变量

候选 `csp-contracts@0.1.1`。与候选路由提示词一起使用；它不是已注册的规范方法。用此程序完成用户的工作，不叙述私有推理，也不把这些问题变成对用户的访谈。

## 何时加载或跳过

在实现或修改非平凡操作、公共类型、验证规则或复用组件之前，如果合法输入、承诺输出或必须保持的条件会决定设计，就加载本程序。机械编辑、未变化的已确定契约，以及契约已明确、仅由事件顺序或陈旧数据主导的决策可以跳过。不要求同时加载其他专业模块。

## 最少需要的任务事实

找出所需行为与范围、相关操作或类型及实际调用方、现有输入、输出和错误表示，以及适用要求或兼容性义务。对于新代码，使用拟议接口和预期调用方，不虚构现有源码。区分已接受的意图与当前代码碰巧执行的行为。标记推断出的契约和未知的使用方行为；源码位置与修订号用于识别观察，并不代表用户接受。在询问会改变决策的缺失规则之前，先检查可用证据。

## 会改变决策的问题

1. 哪些输入和起始状态有效？成功、拒绝或部分失败后，必须能观察到什么？
2. 在调用方能够观察状态的边界上，什么关系必须成立？哪种表示可能悄悄抹去有意义的区别？
3. 拟复用的实现能否保留此调用方的保证、错误和所有权，而不增加更强的前置条件或无关策略？

## 程序

1. **定位契约。** 将要求连接到具体参数、类型、返回值、错误和副作用。区分调用方义务与对不可信输入的验证。缺少前置条件不等于可以默默接受无效的公共输入。只在正常任务产物中记录会产生实质影响的未决假设。
2. **定义可观察关系。** 相对于入口状态和输入，表述成功后的后置条件、失败时所需结果及允许的效果，并确定不变量的观察边界。在契约赋予不同含义时，区分无效、缺失、null、空值和零。若中间内部状态不可被观察，且必要边界最终得到恢复，它可以暂时不同；不要要求每次内部赋值都满足边界不变量。
3. **寻找能区分实现的案例。** 用最小的有效边界案例，以及无效输入或兼容性案例，区分合理的候选实现。对于循环或算法，将初始化、相关步骤及结果连接到该关系；当任务要求取得进展时，检查终止性。不要凭空要求所有工作都进行形式化证明。
4. **选择并实现。** 检查可能复用的现有操作和实际调用方。仅在确为可选方案时，比较直接复用、小范围适配和独立实现。匹配默认值、领域含义、错误、可变性和效果，而不只看签名。把共享规则放在负责它的位置；当纯计算能使规则更清晰时使用它，但不强加范式、抽象或文件数量。修改契约确实受影响的调用方和注册位置。
5. **通过边界检查。** 从要求而非被测实现推导预期结果。通过受影响的使用方执行能区分实现的案例；为非平凡的规则变更加上可维护的行为验证。保留有效的现有测试，运行相关使用方和测试目标。如果持久化兼容性重要，检查真实旧版本生产者生成的编码，不要用当前类型构造旧数据。准确说明尚未测试的边界。

## 公开结果与检查

交付请求的补丁或设计，说明最终行为、重要契约及位置，以及实际检查结果或准确缺失的证据。测试、类型约束、简短契约注释或现有设计说明都可以承载公开关系；不强制新建契约文档。自编测试通过不代表完整性、历史兼容性或所有调用方行为都已得到验证。

## 停止、复用与限制

在意图、源码、接口或受影响使用方未变化时，复用已确定的契约。重要义务足以支持选择后，停止比较实现，完成实现与必要检查。如果缺少的业务规则会改变行为，仅暂停该选择并询问该规则；继续独立的准备或修改。某个无关使用方未知，不会自动阻止所有编辑。

这是面向 LLM 使用而改编的契约推理，并加入了拟议的任务与调用方连接；它不是形式化验证。可能的误用包括把现有缺陷当成预期契约、到处增加断言，以及把不同策略强塞进同一个辅助函数。若仍遗漏契约缺陷、增加不必要抽象，或在相同事实下现有指导以更少工作取得同等结果，此候选的效益假设就会减弱。
