# 状态转换与失败

候选 `csp-transitions@0.1.1`。与候选路由提示词一起使用；它不是已注册的规范方法。用问题实施任务，不叙述私有推理，也不要求用户主导设计练习。

## 何时加载或跳过

当操作顺序、部分失败、取消、重试或并发执行者会改变正确性时加载，例如任务生命周期、异步 UI 更新、事务或资源获取。契约清晰的纯计算、机械编辑，以及已覆盖且未变化的转换可以跳过。不要为不存在相应边界的本地操作引入分布式系统机制。

## 最少需要的任务事实

识别相关状态与事件、可以改变状态的执行者、所需成功或失败行为，以及外部可见的效果。阅读与该决策相关的实际入口、异步回调、存储或 API 语义和资源生命周期。仅在涉及重试标识、取消或可见性时确认这些要求。区分已接受的保证、观察到的行为及推断出的调度假设。未知的原子性或提供方保证仍是未知；模拟对象无法证明它们。

## 会改变决策的问题

1. 哪些状态与事件组合被允许？尝试的修改何时对各观察者可见，或得到持久化？
2. 如果失败、取消或其他执行者介入两个效果之间，可能留下什么状态和响应？谁能够恢复？
3. 重复请求是否代表同一意图？调用方能否在不造成第二次效果的前提下区分拒绝、已完成和结果未知？

## 程序

1. **限定转换。** 使用能够区分允许动作的最小状态表示。把每个相关事件映射到守卫条件、下一状态、响应或错误及效果；若省略未变字段会掩盖缺陷，就明确其保持不变。区分禁止出现的结果与必须最终发生的结果。说明取得进展所需的环境假设，不承诺重试循环必然成功。
2. **定位效果与观察点。** 跟踪实际写入、返回值、通知、回调和获取的资源。确定哪些修改必须不可分割，哪些可以分阶段。找出实际事务、锁、版本检查或所有权边界，不从函数名推断。本地事务不会让外部请求也变得原子化。只有任务确有需要且操作支持时，才选择分阶段处理、状态核对或补偿；某些效果无法撤销。
3. **检验关键间隙。** 检查成功路径，以及可能违反所需关系的最小失败或交错执行。在相关时，包含提交前后的取消，或新意图之后才到达的旧回调。区分确定未执行与结果未知。绝不仅凭超时就判断已回滚。确定各相关退出路径由谁关闭、释放或保留资源。
4. **选择恢复方式并实现。** 保留操作特定的守卫条件。对可重试效果，确认逻辑操作标识、调用方或租户范围、同标识不同内容的处理、记录保留期及承诺的重放响应。检查去重记录与状态修改是否共同提交；若不是，处理暴露的间隙，不承诺恰好一次投递。不要仅凭相同内容推断是同一请求。对于相互竞争的执行者，选择实际存储或运行时语义支持的机制，并按要求使拒绝或过期转换可被观察。保留足够解决问题的最小设计。
5. **执行边界检查。** 通过实际使用方检查正常路径和已识别的负面序列。在相关时使用受控执行顺序、故障注入或代表性并发测试；避免仅用休眠证明顺序。同时断言状态、所需响应和效果次数，包括清理。单元模拟仅验证其模型；若未测试真实提供方或崩溃持久性，就保留未验证状态。即使正常路径通过，独立的必要失败仍未解决。

## 公开结果与检查

交付请求的变更，简要说明重要转换或恢复选择、对应源码边界和实际检查。必要时可用小型转换表、测试执行记录或代码注释揭示契约；不要求新建图表或状态机框架。对受影响的调用方说明尚未确定的结果，不声称成功或回滚。

## 停止、复用与限制

在相关事件、效果、源码或保证变化前，复用已确定的转换模型。当范围内的实现与检查足以应对已识别风险时，停止探索执行顺序；不声称穷尽证明了并发正确性。缺失的外部保证只阻塞依赖该保证的选择。继续独立的本地工作，指出最少需要的证据或用户决定，不重新询问已确定的授权。

这是对状态机规格与幂等 API 设计的拟议组合，不是形式化模型检查，也不是通用重试处方。误用包括不必要的锁或状态枚举、把所有错误都视为可重试，以及在没有明确间隙时引入 outbox。若在相同事实下失败未减少、新增活性缺陷，或只增加机制而无有用结果改善，其效益假设就会减弱。
