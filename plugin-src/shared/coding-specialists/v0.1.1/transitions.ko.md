# 상태 전이와 실패

후보 `csp-transitions@0.1.1`입니다. 후보 라우터와 함께 사용하며 등록된 정본 방법은 아닙니다. 비공개 추론을 설명하거나 사용자에게 설계 과정을 맡기지 말고, 질문을 활용해 작업을 구현합니다.

## 불러올 때와 건너뛸 때

작업 순서, 부분 실패, 취소, 재시도나 동시 실행 주체가 정확성에 영향을 줄 때 불러옵니다. 작업 수명주기, 비동기 UI 갱신, 트랜잭션이나 자원 획득이 해당할 수 있습니다. 계약이 명확한 순수 계산, 기계적 수정, 이미 확인했고 바뀌지 않은 전이는 건너뜁니다. 관련 경계가 없는 로컬 작업에 분산 시스템 장치를 도입하지 않습니다.

## 필요한 최소 사실

관련 상태와 사건, 상태를 바꿀 수 있는 실행 주체, 필요한 성공·실패 동작과 외부에서 보이는 효과를 찾습니다. 현재 판단과 관련된 실제 진입점, 비동기 콜백, 저장소·API 의미와 자원 수명을 읽습니다. 재시도 식별, 취소와 가시성 요건은 해당할 때만 확인합니다. 승인된 보장, 관찰한 동작, 추론한 실행 순서의 가정을 구분합니다. 원자성이나 제공자 보장이 확인되지 않았다면 미확인으로 남깁니다. 모의 객체로 실제 제공자의 보장을 입증할 수는 없습니다.

## 판단을 바꾸는 질문

1. 어떤 상태와 사건의 조합이 허용되며, 시도한 변경은 언제 각 관찰자에게 보이거나 영속적으로 반영되는가?
2. 두 효과 사이에 실패·취소·다른 실행 주체가 끼어들면 어떤 상태와 응답이 남을 수 있으며, 누가 복구할 수 있는가?
3. 반복된 요청은 같은 의도를 뜻하는가? 호출자가 두 번째 효과를 만들지 않으면서 거절·완료·결과 미확인을 구분할 수 있는가?

## 절차

1. **전이 범위를 정합니다.** 허용되는 행동을 구분할 수 있는 가장 작은 상태 표현을 사용합니다. 관련 사건을 각각 진입 조건, 다음 상태, 응답·오류와 효과에 연결합니다. 생략하면 버그를 숨길 수 있는 필드는 변경되지 않는다는 점도 명확히 합니다. 금지된 결과와 반드시 언젠가 일어나야 할 결과를 구분합니다. 재시도 반복이 반드시 성공한다고 약속하지 말고 진행에 필요한 환경 가정을 밝힙니다.
2. **효과와 관찰 지점을 찾습니다.** 실제 쓰기, 반환값, 알림, 콜백과 획득한 자원을 따라갑니다. 어떤 변경을 나눌 수 없고 어떤 변경을 단계적으로 처리할 수 있는지 정합니다. 함수 이름으로 추정하지 말고 실제 트랜잭션·잠금·버전 검사·소유권 경계를 찾습니다. 로컬 트랜잭션이 외부 요청까지 원자적으로 만들지는 않습니다. 작업에 필요하고 해당 연산이 지원할 때만 단계화·상태 대조·보상 동작을 선택합니다. 되돌릴 수 없는 효과도 있습니다.
3. **결정적인 틈을 점검합니다.** 성공 경로와 필요한 관계를 깨뜨릴 수 있는 가장 작은 실패·끼어들기 순서를 살핍니다. 해당한다면 반영 확정 전후의 취소나 새로운 의도 뒤에 도착하는 오래된 콜백을 포함합니다. 확실히 실행되지 않은 경우와 결과를 모르는 경우를 구분합니다. 시간 초과만으로 롤백됐다고 판단하지 않습니다. 관련 종료 경로마다 누가 자원을 닫고 해제하거나 보유하는지 정합니다.
4. **복구 방식을 고르고 구현합니다.** 작업별 진입 조건을 보존합니다. 재시도할 수 있는 효과에는 논리적 작업 식별자, 호출자·테넌트 범위, 같은 식별자에 다른 내용이 온 경우의 처리, 기록 유지 기간과 약속한 재응답을 확인합니다. 중복 제거 기록과 변경이 함께 반영되는지 살핍니다. 그렇지 않다면 정확히 한 번 전달된다고 약속하지 말고 드러난 틈을 처리합니다. 내용이 같다는 이유만으로 같은 요청이라 판단하지 않습니다. 실행 주체가 경쟁하면 실제 저장소·런타임 의미가 뒷받침하는 장치를 고르고 거절되거나 오래된 전이를 요구사항에 맞게 드러냅니다. 필요한 일을 하는 가장 작은 설계를 유지합니다.
5. **경계를 실행해 봅니다.** 실제 사용처를 통해 정상 경로와 찾아낸 부정 사례의 순서를 검사합니다. 해당하면 실행 순서 제어, 실패 주입이나 대표 동시성 검사를 사용합니다. 대기 시간만으로 실행 순서를 입증하지 않습니다. 상태와 필요한 응답·효과 횟수, 정리 동작을 함께 확인합니다. 단위 시뮬레이션이 검증하는 것은 그 모형뿐입니다. 실제 제공자의 동작이나 프로세스·시스템 비정상 종료 후의 영속성을 검사하지 않았다면 미확인으로 남깁니다. 정상 경로를 통과했어도 별개의 필수 실패는 미해결로 유지합니다.

## 공개 결과와 확인

요청한 변경과 함께 중요한 전이·복구 선택, 그 선택이 근거한 소스 경계와 실제 검사 결과를 간결하게 설명합니다. 필요하면 작은 전이표·테스트 실행 기록·코드 주석으로 계약을 드러낼 수 있습니다. 새 다이어그램이나 상태 머신 프레임워크는 필수가 아닙니다. 결과가 미확인이라면 성공이나 롤백을 주장하지 말고 영향을 받는 호출자에게 그 상태를 설명합니다.

## 중단·재사용·한계

관련 사건·효과·소스·보장이 바뀌기 전까지 정한 전이 모형을 재사용합니다. 식별한 위험에 대해 범위 내에서 적절한 구현과 검사가 갖춰지면 실행 순서 탐색을 멈춥니다. 동시성 전체를 증명했다고 주장하지 않습니다. 외부 보장이 빠졌다면 그 보장에 의존하는 선택만 보류합니다. 독립적인 로컬 작업을 계속하고, 이미 정한 권한을 다시 묻지 않으면서 필요한 최소 근거나 사용자 결정을 밝힙니다.

상태 머신 명세와 멱등 API 설계를 응용해 제안한 조합이며, 형식 모델 검사나 모든 상황에 통하는 재시도 처방은 아닙니다. 불필요한 잠금·상태 열거형을 만들거나, 모든 오류를 재시도 대상으로 보거나, 확인된 문제 없이 outbox를 추가하는 오용이 가능합니다. 같은 사실을 제공했을 때 실패가 줄지 않거나, 새로운 진행 불능 문제가 생기거나, 유용한 결과 개선 없이 장치만 늘어난다면 효용 가설은 약해집니다.
