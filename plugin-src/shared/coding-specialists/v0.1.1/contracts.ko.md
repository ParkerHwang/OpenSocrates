# 계약과 불변 조건

후보 `csp-contracts@0.1.1`입니다. 후보 라우터와 함께 사용하며 등록된 정본 방법은 아닙니다. 비공개 추론을 설명하거나 질문을 사용자 인터뷰로 바꾸지 말고, 이 절차로 사용자의 작업을 수행합니다.

## 불러올 때와 건너뛸 때

중요한 작업·공개 타입·입력 검증 규칙·재사용 컴포넌트를 구현하거나 바꾸기 전에, 유효한 입력·보장할 결과·유지할 조건이 설계를 결정한다면 불러옵니다. 기계적 수정, 바뀌지 않은 확정 계약, 계약이 이미 명확하고 사건 순서나 오래된 데이터만 문제인 판단에는 건너뜁니다. 다른 전문 모듈을 반드시 불러올 필요는 없습니다.

## 필요한 최소 사실

요청한 동작과 범위, 관련 작업·타입과 실제 호출부, 기존 입력·출력·오류 표현, 적용되는 요구사항이나 호환성 의무를 찾습니다. 새 코드라면 존재하지 않는 소스를 지어내지 말고 제안한 인터페이스와 예정된 호출부를 사용합니다. 승인된 의도와 현재 코드가 실제로 하는 일을 구분합니다. 추론한 계약과 확인하지 못한 사용처의 동작을 표시합니다. 소스 위치와 리비전은 관찰을 식별할 뿐 사용자 승인을 뜻하지 않습니다. 선택을 바꾸는 규칙이 빠졌다고 묻기 전에 이용 가능한 근거를 확인합니다.

## 판단을 바꾸는 질문

1. 어떤 입력과 시작 상태가 유효하며, 성공·거절·부분 실패 뒤에 무엇이 관찰되어야 하는가?
2. 호출부가 상태를 관찰할 수 있는 경계에서 어떤 관계가 성립해야 하며, 어떤 표현이 의미 있는 차이를 조용히 없앨 수 있는가?
3. 재사용하려는 구현이 더 강한 전제조건이나 무관한 정책을 요구하지 않으면서 이 호출부의 보장·오류·소유권을 유지할 수 있는가?

## 절차

1. **계약을 찾습니다.** 요구사항을 구체적인 매개변수, 타입, 반환값, 오류와 부작용에 연결합니다. 호출자의 의무와 신뢰할 수 없는 입력의 검증을 구분합니다. 전제조건이 빠져 있다고 잘못된 공개 입력을 조용히 허용해도 되는 것은 아닙니다. 중요한 미해결 가정만 기존 작업 산출물에 남깁니다.
2. **관찰할 관계를 정합니다.** 진입 시점의 상태와 입력에 대한 성공 후조건, 실패 시 필요한 결과와 허용되는 효과, 불변 조건이 성립해야 할 관찰 경계를 표현합니다. 계약상 다르다면 잘못된 값, 필드 부재, null, 빈 값과 0을 구분합니다. 중간의 내부 상태는 외부에서 관찰할 수 없고 필요한 경계를 복원한다면 달라도 됩니다. 모든 내부 대입에서 경계의 불변 조건이 성립해야 한다고 요구하지 않습니다.
3. **구현을 구별하는 사례를 찾습니다.** 가능한 구현들을 가르는 가장 작은 유효 경계 사례와 무효 입력 또는 호환성 사례를 사용합니다. 반복문이나 알고리즘이라면 초기화, 관련 단계와 결과를 해당 관계에 연결하고, 진행이 요구사항에 포함되면 종료도 살핍니다. 모든 작업에 형식 증명을 요구하지 않습니다.
4. **선택하고 구현합니다.** 재사용할 만한 기존 작업과 실제 호출부를 읽습니다. 실제 대안인 경우에만 직접 재사용, 좁은 변형, 별도 동작을 비교합니다. 시그니처뿐 아니라 기본값, 도메인 의미, 오류, 변경 가능성과 효과를 맞춥니다. 공유 규칙은 그 규칙을 책임지는 곳에 두고, 규칙이 명확해진다면 순수 계산을 활용합니다. 특정 패러다임·추상화·파일 수를 강요하지 않습니다. 계약이 실제 바뀌는 호출부와 등록부를 함께 고칩니다.
5. **경계를 통해 확인합니다.** 기대 결과는 검사할 구현이 아니라 요구사항에서 도출합니다. 영향받는 사용처를 통해 구현을 구별하는 사례를 실행하고, 중요한 규칙 변경에는 유지할 수 있는 동작 검증을 추가합니다. 유효한 기존 테스트를 보존하고 관련 사용처와 테스트 대상을 실행합니다. 저장 데이터의 호환성이 중요하면 현재 타입으로 옛 데이터를 만드는 대신 실제 이전 생산자가 만든 형식을 확인합니다. 검사하지 않은 경계는 정확히 밝힙니다.

## 공개 결과와 확인

요청한 패치나 설계를 전달하며 결과 동작, 중요한 계약과 위치, 실제 검사 결과 또는 정확히 빠진 근거를 설명합니다. 테스트, 타입 제약, 짧은 계약 주석이나 기존 설계 문서에 필요한 관계를 담을 수 있습니다. 별도 계약 문서는 필수가 아닙니다. 직접 만든 테스트의 통과만으로 완전성·과거 호환성·모든 호출부의 동작이 입증되지는 않습니다.

## 중단·재사용·한계

의도, 소스, 인터페이스나 영향받는 사용처가 바뀌기 전까지 확정한 계약을 재사용합니다. 중요한 의무에 비추어 선택할 근거가 충분하면 구현 비교를 멈추고 구현과 필수 검사를 마칩니다. 빠진 업무 규칙이 동작을 바꾼다면 그 선택을 보류하고 해당 규칙만 질문합니다. 그와 무관한 준비나 수정은 계속합니다. 무관한 사용처가 미확인이라는 이유만으로 모든 편집을 막지 않습니다.

계약 추론을 LLM 작업에 맞게 적용하고 작업·호출부 연결을 제안한 절차이며 형식 검증은 아닙니다. 현재 버그를 의도된 계약으로 만들거나, 곳곳에 단언문을 추가하거나, 서로 다른 정책을 한 도우미 함수에 억지로 합치는 오용이 가능합니다. 계약 결함을 놓치거나 불필요한 추상화가 늘거나, 같은 사실을 제공한 기존 안내가 더 적은 작업으로 같은 결과를 낸다면 이 후보의 효용 가설은 약해집니다.
