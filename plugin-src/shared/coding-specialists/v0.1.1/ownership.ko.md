# 소유권과 파생 상태

후보 `csp-ownership@0.1.1`입니다. 후보 라우터와 함께 사용하며 등록된 정본 방법은 아닙니다. 질문을 활용해 실제 변경을 수행합니다. 비공개 추론을 요구하거나 방법을 나열해 발표하지 않습니다.

## 불러올 때와 건너뛸 때

기준 상태, 캐시·파생 결과, 변경 가능한 공유 데이터, 스냅샷이나 자원 소유권의 선택·변경으로 사용처의 결과가 어긋나거나 유효 수명을 넘겨 데이터를 사용할 수 있을 때 불러옵니다. 기계적 수정, 확인했고 바뀌지 않은 소유권 경계, 입력이 이미 명확하고 경쟁하는 표현이 없는 순수 계산은 건너뜁니다. 같은 변수가 두 번 나타난다는 사실만으로 재설계를 정당화하지 않습니다.

## 필요한 최소 사실

의미 있는 값, 그 출처와 수명, 생산자·쓰기 주체, 관련 사용처, 기대하는 일관성·신선도를 찾습니다. 실제 타입, 갱신 경로, 반환값과 같은 객체를 가리키는 참조를 읽습니다. 자원이라면 획득·해제 책임을 찾습니다. 승인된 의도, 소스 관찰과 추론한 관계를 구분합니다. 새 소스라면 제안하는 소유권을 명시합니다. 버전·격리·수명이 미확인이라면 모든 읽기가 최신 값을 본다고 가정하지 말고 그 불확실성을 유지합니다.

## 판단을 바꾸는 질문

1. 이 판단에서 어떤 표현이 기준이며, 어떤 표현이 파생 뷰·캐시·사용자 초안 또는 별도 의미를 가진 과거 스냅샷인가?
2. 각 값을 누가 변경하거나 보유할 수 있으며, 공유 참조·이른 해제·늦은 갱신이 다른 사용처에 의도하지 않은 상태를 보이게 할 수 있는가?
3. 사용처가 필요한 결과와 일치하려면 어떤 입력과 버전을 공유해야 하며, 계산·무효화·복사는 어디에서 이루어져야 하는가?

## 절차

1. **관련 데이터 흐름을 따라갑니다.** 입력이나 저장된 출처에서 변경·계산·공개를 거쳐 영향받는 사용처까지 값을 추적합니다. 즉시 반환, 후속 읽기, 콜백이나 렌더링 경로는 변경한 값을 소비할 때만 포함합니다. 원본 상태, 파생 값과 독립적인 스냅샷을 구분합니다. 비슷해 보이는 필드를 같은 의미로 취급하지 않습니다. 과거의 사실이 오늘 다시 계산한 값과 같아야 하는 것은 아닙니다.
2. **기준과 소유 책임을 정합니다.** 누가 쓰고, 빌려 쓰거나 보유할 수 있으며, 언제 데이터나 자원이 무효가 되는지 찾습니다. 해당한다면 공유 참조, 얕은 복사, 클로저, 지연 순회와 소유권 이전의 의미를 확인합니다. 필요한 계약이 실시간 뷰·고정 스냅샷·소유한 값 중 무엇을 요구하는지 정합니다. 프로젝트에 맞는 언어·런타임 기능을 사용합니다. Rust의 대여 규칙을 다른 언어의 필수 설계로 적용하지 않습니다.
3. **갱신과 계산 경계를 고릅니다.** 의미와 비용에 맞는다면 중복 값은 적절한 기준 입력에서 계산하는 방식을 우선합니다. 계산 결과의 저장, 초안이나 캐시가 필요하다면 버전·신선도와 무효화·갱신 책임을 정합니다. 영향받는 사용처가 같은 규칙을 공유할 수 있는 곳에 동일한 입력에 동일한 결과를 내는 계산을 두고, 결과에 영향을 주는 I/O·변경·시계·난수 입력·수명 관리는 명확히 합니다. 로컬 함수나 기존 메서드로 충분할 수 있으며 새 계층은 필수가 아닙니다.
4. **일관성 관계를 구현합니다.** 생산자와 사용처를 선택한 규칙이나 스냅샷에 연결합니다. 변경 대상이 아닌 공개 타입·오류·소유권 계약은 유지합니다. 사용자가 계약을 명시적으로 바꾸었다면 이전 계약을 고정하지 말고 승인된 변경을 영향받는 사용처에 함께 반영합니다. 사용처가 같은 논리적 버전에서 일치해야 한다면 이를 보장하는 스냅샷이나 원자적 갱신을 찾습니다. 최종 일관성이 의도되었다면 명시된 지연·상태 대조 의미를 보존하고 조용히 더 강한 보장으로 바꾸지 않습니다. 동시 읽기에는 실제 저장소·프레임워크 보장을 확인합니다. 수식이 같다는 사실만으로 원자성이 확보되지는 않습니다. 모든 곳에 복사를 넣거나 획일적인 캐시 정책을 강요하지 않습니다.
5. **관찰 가능한 차이를 확인합니다.** 변경이나 수명 변화를 실행하고 계약상 관련된 버전에서 사용처를 확인합니다. 보유한 결과의 고정성을 약속했다면 유지되는지, 실시간 뷰를 약속했다면 바뀌는지 확인합니다. 공유 참조를 통한 변경, 무효화나 정리 동작은 관련될 때만 검사합니다. 같은 잘못된 함수를 재사용할 수 있는 두 경로끼리만 비교하지 말고, 독립적으로 도출한 기대값에 관찰값을 대조합니다. 영향받는 호출부와 테스트 대상을 실행하고 남은 확인 범위의 한계를 보존합니다.

## 공개 결과와 확인

요청한 산출물과 함께 중요한 기준 데이터·소유권 선택, 영향받는 위치와 실제 검사 결과를 전달합니다. 짧은 설명, 의미를 담은 타입, 집중된 테스트나 기존 설계 기록이면 충분합니다. 아직 검증하지 않은 신선도·수명 보장을 밝힙니다. 파생 결과 검사를 통과해도 검사하지 않은 과거·동시 실행·원격 동작까지 입증되지는 않습니다.

## 중단·재사용·한계

출처, 쓰기 주체, 사용처와 일관성 요건이 바뀌지 않는 동안 소유권·데이터 흐름 결론을 재사용합니다. 중요한 경로가 선택을 뒷받침하면 추적을 멈추고 변경과 검사를 마칩니다. 과거 사실이나 외부 수명 보장이 빠져 한 가지 약속을 할 수 없다면 그 약속만 보류하고 독립적인 작업을 계속합니다. 질문 전에 접근 가능한 코드를 확인합니다. 새로운 승인이나 메모리 요건을 만들지 않습니다.

소유권·대여와 상태 구조 안내를 참고해 새로 제안한 조합이며, 하나의 확립된 보편 방법론은 아닙니다. 의미 있는 스냅샷을 없애거나, 독립적인 기준들을 하나로 합치거나, 복사·정규화를 지나치게 적용하는 오용이 가능합니다. 같은 사실을 제공했을 때 오래된 값·공유 참조 문제가 계속되거나, 정당한 스냅샷 의미가 사라지거나, 산출물 개선 없이 작업만 늘어난다면 효용 가설은 약해집니다.
