## Purpose

Use this procedure when a recurring result gap may be produced by the goal, rule, value, assumption, or authority structure guiding action, not only by execution. It separates a single-loop correction inside the current rule from a double-loop move that questions the rule itself. The result is a revised governing statement and safe learning test, not a verdict about a person’s attitude or intent.

## Use when

Use it when the same problem returns after a reasonable procedural fix, when a policy or target repeatedly creates the behavior it later criticizes, or when defensive routines prevent an organization from examining its own premises. It fits a bounded operational, product, or team learning problem with an observable expected-versus-actual gap and enough context to identify the rule that shaped the action.

## Do not use when

Do not use it when one isolated execution defect fully explains the failure, when the task is mechanical, or when a binding safety, legal, or policy response must be followed rather than questioned. Do not infer intent from recurrence or use “mindset” as a substitute for evidence. If harm is active, first use a qualified incident or safety response; learning analysis must not delay containment.

## Inputs to establish

Establish the expected result, observed result, gap scope and time window, rule or target in force, prior single-loop fixes, and evidence of recurrence. Gather the goal, value, assumption, incentive, and authority conditions that may have made the rule reasonable. Name affected roles without assigning blame. Define a limited learning test and safe boundary for changing practice. Ask no more than two questions, only when the answer could distinguish an execution defect from a governing-variable problem; otherwise label it unverified or assumed.

## Procedure

1. **Publish the result gap.** State the expected and observed outcomes, time window, scope, impact, and recurrence evidence in one record. Mark direct observations, user reports, checked records, and interpretations separately. **Visible output/state change:** result-gap state.
2. **Publish the single-loop split.** Record the correction that would improve execution while leaving the current rule intact, then state why recurrence or side effects require deeper review. **Visible output/state change:** gap register with a single-loop action and double-loop trigger.
3. **Publish the governing-variable map.** Trace the action to its goal, value, rule, assumption, incentive, and decision authority. Label each link `verified`, `computed`, `inferred`, `assumed`, `unverified`, or `conflicted`. **Visible output/state change:** governing-variable map.
4. **Publish revised-rule candidates.** Compare candidate changes to the governing rule or goal, including benefit, cost, affected role, and unresolved objection. Do not rank candidates with invented probabilities; preserve a conflict when purpose does not select one. **Visible output/state change:** revised-rule register.
5. **Publish a learning test.** Choose a limited, reversible practice change with an observable result, window, owner, stop boundary, and decision rule. Do not remove a safety control or expose people to avoidable harm; missing authorization holds the test. **Visible output/state change:** learning test or hold.
6. **Publish the learning record.** After evidence is available, state whether the rule is supported, revised, rejected, or held, and record the next safe check and organizational memory location. If the decisive observation is absent, publish a provisional rule candidate. **Visible output/state change:** learning status and next check.

## Public output contract

Return `result_gap`, `governing_assumption_rule`, `evidence`, `revised_rule`, and `learning_test` as card-ready fields. Show the single-loop action separately so a routine fix is not misrepresented as double-loop learning. The revised rule must name the changed governing variable, scope, owner, and unresolved uncertainty. The learning test must state its observable signal, safe limit, and decision rule. A held result is valid when the evidence or authority to change the rule is missing.

## Evidence and uncertainty rules

Recurrence supports a pattern claim only when the events, scope, and comparison are identified; it does not prove that one rule caused every event. Treat time-stamped records, reproducible observations, and explicit policy text differently from recollection or a plausible story. Do not attribute the gap to a person when the rule, incentive, authority, workload, or control path has not been examined. Use ordinal materiality only with a stated decision consequence. Do not invent probabilities or claim that a short learning test proves an organizational theory. If credible branches conflict, expose the conflict and hold the revised-rule conclusion.

## Stop conditions

Hold when there is no concrete expected-versus-actual gap, no credible recurrence pattern, or no record that could distinguish execution from rule effects. Hold when the governing rule or decision authority is unknown and cannot be safely inferred. Stop the analysis if active harm requires containment, or if the proposed learning test would weaken a required control, create avoidable exposure, or make an irreversible change. If one execution defect explains the event and no governing-variable question remains, stop and hand off to a more focused failure or cause method.

## Complement handoff

Hand off to `root-cause-analysis` when the result gap needs a fuller causal chain, control review, and prevention owner before a governing rule can be changed. Pass the published gap, relevant timeline, rule and control links, known evidence states, and the unresolved branch only. Do not pass blame, hidden deliberation, or a fabricated causal certainty, and do not activate the full complement when the learning test already answers the bounded rule question.
